## 1 TypeScript

### 1.1 理解泛型、接口等面向对象的相关概念，TypeScript对面向对象理念的实现

::: details 参考

#### 接口（Interface）

接口用于定义对象的类型结构，描述对象应该具有哪些属性和方法，是 TypeScript 类型系统的核心。

```typescript
interface User {
  name: string
  age: number
  sayHello(): void
}

// 接口可继承
interface Admin extends User {
  role: 'admin' | 'super_admin'
  permissions: string[]
}

// 接口可合并声明（同名接口自动合并）
interface Window {
  myLib: string
}
```

接口 vs type 的区别：

- `interface` 可被类实现（`implements`），`type` 不行
- `interface` 同名自动合并，`type` 不能重复声明
- `type` 可以声明联合类型、元组等，`interface` 不行
- 对象结构优先用 `interface`，联合/交叉/映射类型用 `type`

#### 泛型（Generics）

泛型让函数、类、接口能够适用于多种类型，同时保持类型信息。

```typescript
// 泛型函数
function identity<T>(arg: T): T {
  return arg
}

// 泛型约束
interface Lengthwise {
  length: number
}
function logLength<T extends Lengthwise>(arg: T): T {
  console.log(arg.length)
  return arg
}

// 泛型工具函数
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key]
}

// 泛型类
class Stack<T> {
  private items: T[] = []
  push(item: T) {
    this.items.push(item)
  }
  pop(): T | undefined {
    return this.items.pop()
  }
}
```

#### TypeScript 对 OOP 的实现

| 概念 | 实现方式                                                                    |
| ---- | --------------------------------------------------------------------------- |
| 封装 | `public` / `private` / `protected` 访问修饰符（编译时检查，运行时仍可访问） |
| 继承 | `extends` 关键字，支持单继承                                                |
| 多态 | 通过抽象类 `abstract` 和方法重写 `override` 实现                            |
| 抽象 | `abstract class` 和 `interface` 两种方式                                    |

```typescript
abstract class Animal {
  abstract makeSound(): void
  move(): void {
    console.log('moving...')
  }
}

class Dog extends Animal {
  makeSound(): void {
    console.log('woof!')
  }
}
```

> TypeScript 的 `private` 只是编译时约束，运行时 JavaScript 仍然可以访问。ES2022 新增的 `#privateField` 才是真正的运行时私有。

### 1.2 理解使用TypeScript的好处，掌握TypeScript基础语法

::: details 参考

#### 好处

1. **静态类型检查**：编译阶段发现类型错误，减少运行时 Bug。常见场景：拼写错误的属性名、参数类型不匹配、可能为 `null/undefined` 的值。
2. **智能提示和自动补全**：IDE 能提供精确的代码补全、跳转定义、重构支持，大幅提升开发效率。
3. **代码即文档**：类型定义本身就是最好的文档，降低维护成本。
4. **更好的协作**：类型约束让大型项目中多人协作更加安全，接口定义就是团队契约。
5. **渐进式采用**：可以逐步迁移 JS 项目，`.js` 改名 `.ts` 就能开始使用。

#### 基础语法要点

```typescript
// 1. 基本类型注解
let num: number = 42
let str: string = 'hello'
let bool: boolean = true
let arr: number[] = [1, 2, 3]
let tuple: [string, number] = ['age', 25]

// 2. 联合类型与交叉类型
type Status = 'pending' | 'success' | 'error' // 字面量联合
type A = { a: string }
type B = { b: number }
type C = A & B // { a: string; b: number }

// 3. 类型断言
const el = document.getElementById('app') as HTMLDivElement

// 4. 类型守卫
function isString(val: unknown): val is string {
  return typeof val === 'string'
}

// 5. 枚举
enum Direction {
  Up,
  Down,
  Left,
  Right
}

// 6. 泛型（见 1.1）

// 7. 工具类型
interface Todo {
  title: string
  description: string
  completed: boolean
}
type TodoPreview = Pick<Todo, 'title' | 'completed'>
type TodoOptional = Partial<Todo>
type TodoReadonly = Readonly<Todo>
```

> 核心原则：类型注解不是越多越好——能推导出来的就不要手动标注，让类型在代码中自然流动。

:::

### 1.3 TypeScript的规则检测原理

::: details 参考

TypeScript 的类型检查流程分为以下几个阶段：

#### 1. 词法分析 → 语法分析 → AST

`tsc` 首先将源代码解析为 AST（抽象语法树），这个 AST 不仅包含 JavaScript 语法节点，还包含类型注解信息。

#### 2. 类型绑定（Binder）

遍历 AST，建立 Symbol 表。每个变量、函数、类、接口都会被分配一个 Symbol，记录其声明的类型信息和所在作用域。

#### 3. 类型检查（Checker）

TypeScript 的"灵魂"——类型检查器(Type Checker)，对 AST 进行深度遍历：

- **结构化类型系统（Structural Typing）**："鸭子类型"——只要形状匹配就认为兼容，不像 Java/C# 必须显式声明 `implements`。
- **控制流分析（CFA）**：基于 `if`、`switch`、`return` 等控制流逐步收窄联合类型。例如 `if (typeof x === 'string')` 之后，`x` 被收窄为 `string`。
- **类型推断**：未标注类型时，从初始化表达式或上下文推断类型。`const x = 1` → 字面量类型 `1`，`let x = 1` → 基础类型 `number`。
- **类型兼容性检查**：函数参数双向协变（strict 模式下开启 `strictFunctionTypes` 变为参数逆变），对象属性多余检查等。

#### 4. 代码生成（Emitter）

类型检查通过后，删除所有类型注解，输出纯 JavaScript。

#### tsconfig 核心规则配置

```json
{
  "compilerOptions": {
    "strict": true, // 开启所有严格检查
    "noImplicitAny": true, // 禁止隐式 any
    "strictNullChecks": true, // null/undefined 独立类型检查
    "strictFunctionTypes": true, // 函数参数严格逆变
    "noUnusedLocals": true, // 未使用的局部变量报错
    "noUnusedParameters": true // 未使用的参数报错
  }
}
```

> TypeScript 的类型检查完全是编译时行为，**不会产生任何运行时开销**。类型信息在编译后全部擦除。

:::

### 1.4 可以在React、Vue等框架中使用TypeScript进行开发

::: details 参考

#### Vue 3 + TypeScript

Vue 3 从设计之初就考虑 TS 支持，`<script setup>` 写法体验最佳：

```vue
<script setup lang="ts">
import { ref, computed, type PropType } from 'vue'

interface Item {
  id: number
  name: string
}

const props = defineProps({
  items: { type: Array as PropType<Item[]>, required: true }
})

const emit = defineEmits<{
  select: [id: number]
}>()

const count = ref<number>(0)
const doubled = computed<number>(() => count.value * 2)

function handleClick(id: number): void {
  emit('select', id)
}
</script>
```

Vue 2 使用 `vue-class-component` + `vue-property-decorator` 或 `@vue/composition-api` + TS，体验不如 Vue 3。

#### React + TypeScript

```tsx
interface User {
  id: number
  name: string
  email: string
}

interface Props {
  users: User[]
  onSelect: (user: User) => void
}

const UserList: React.FC<Props> = ({ users, onSelect }) => {
  const [selectedId, setSelectedId] = useState<number | null>(null)

  return (
    <ul>
      {users.map((user) => (
        <li
          key={user.id}
          onClick={() => {
            setSelectedId(user.id)
            onSelect(user)
          }}
        >
          {user.name}
        </li>
      ))}
    </ul>
  )
}

// 泛型 Hook
function useArray<T>(initial: T[]) {
  const [arr, setArr] = useState<T[]>(initial)
  const push = (item: T) => setArr([...arr, item])
  const remove = (index: number) => setArr(arr.filter((_, i) => i !== index))
  return { arr, push, remove }
}
```

#### 实践建议

- 将共享类型抽取到 `types/` 目录
- API 请求/响应类型单独定义，使用泛型工具类型
- 优先使用类型推断，不滥用标注
- 使用 `satisfies` 关键字（TS 4.9+）做类型断言而不改变推导结果

### 面试高频：Vue 2 vs Vue 3 全面对比

::: details 参考

#### 核心差异一览

| 维度                         | Vue 2                                                 | Vue 3                                                                         |
| ---------------------------- | ----------------------------------------------------- | ----------------------------------------------------------------------------- |
| **响应式系统**               | `Object.defineProperty`                               | `Proxy`                                                                       |
| **API 风格**                 | Options API（`data`/`methods`/`computed`/`watch`）    | Options API 兼容 + **Composition API**（`ref`/`reactive`/`computed`/`watch`） |
| **组件根节点**               | 必须单根节点包裹                                      | 支持多根节点（**Fragment**）                                                  |
| **生命周期**                 | `beforeCreate` / `created` 等 11 个                   | 移除 `beforeCreate`/`created`（`setup` 替代），其余 9 个加 `on` 前缀          |
| **类型支持**                 | 基于 Flow，TS 支持弱                                  | 完全用 TypeScript 重写                                                        |
| **编译优化**                 | 全量 diff                                             | PatchFlag + Block Tree + 静态提升 + 预字符串化                                |
| **虚拟 DOM**                 | 双端 diff                                             | 预处理 + 最长递增子序列 LIS                                                   |
| **Tree Shaking**             | 不支持                                                | 全局 API 支持按需引入                                                         |
| **打包体积**                 | ~23KB（gzip）                                         | ~13KB（gzip），更小                                                           |
| **性能**                     | 中等                                                  | 快 2 倍+（渲染、更新均有优化）                                                |
| **组件实例**                 | `new Vue()` 创建根实例                                | `createApp()` 工厂函数（避免全局配置污染）                                    |
| **全局 API**                 | `Vue.component()` / `Vue.directive()` / `Vue.mixin()` | `app.component()` / `app.directive()` / `app.mixin()`，作用域隔离             |
| **事件总线**                 | 内置 `$on` / `$off` / `$once`                         | **已移除**，推荐 mitt 或 props/emits                                          |
| **`v-model`**                | 单一 `v-model`，`.sync` 修饰符                        | 可多个 `v-model`（`v-model:title`），废弃 `.sync`                             |
| **`v-if` vs `v-for` 优先级** | `v-for` > `v-if`（不推荐同时使用）                    | **`v-if` > `v-for`**（同时使用时 `v-if` 先执行，可能访问不到 `v-for` 变量）   |
| **`$listeners` / `$attrs`**  | `$attrs` 不含 class/style，有 `$listeners`            | `$attrs` 包含 class/style/事件监听器，**移除 `$listeners`**                   |
| **过滤器（Filters）**        | 支持                                                  | **已移除**，推荐用 computed 或全局方法                                        |
| **`key` 属性**               | `v-if` 分支不需要 `key`                               | `v-if`/`v-else` 分支**自动生成唯一 key**                                      |
| **异步组件**                 | `() => import('./Comp.vue')`                          | `defineAsyncComponent(() => import('./Comp.vue'))`                            |
| **`<Transition>` class**     | `v-enter` / `v-leave`                                 | **`v-enter-from` / `v-leave-from`**（更语义化）                               |
| **自定义指令钩子**           | `bind` / `inserted` / `update` 等                     | **重命名对齐组件生命周期**：`created` / `mounted` / `updated` 等              |
| **渲染函数**                 | `h` 从参数传入                                        | `h` 从 `vue` **全局导入**                                                     |
| **Teleport**                 | 无，需第三方库（`portal-vue`）                        | **内置** `<Teleport to="body">`                                               |
| **Suspense**                 | 无                                                    | **内置** `<Suspense>`（实验性）                                               |
| **响应式 API**               | `Vue.set()` / `Vue.delete()` 补丁                     | 不再需要，Proxy 天然支持                                                      |

#### 面试回答模板

> "Vue 3 相比 Vue 2 主要有四大提升：
>
> 1. **性能更好**——响应式从 `defineProperty` 升级到 `Proxy`，diff 算法加入静态标记和预处理，编译期做了大量优化。
> 2. **包体积更小**——全局 API 支持 Tree Shaking，按需引入。
> 3. **TypeScript 支持更好**——源码用 TS 重写，Composition API 天然友好的类型推断。
> 4. **开发体验更好**——Composition API 解决了 mixins 的命名冲突和来源不清晰，`<script setup>` 大大减少了样板代码。
>
> 同时也有一些破坏性变更需要注意：移除了 `$on/$off` 事件总线、过滤器、`.sync` 修饰符被多 `v-model` 替代、`v-if/v-for` 优先级互换等。"

### 2.1 熟练使用Vue的API、生命周期、钩子函数

::: details 参考

#### Vue 3 组合式 API 核心

| API                                | 说明                                                                  |
| ---------------------------------- | --------------------------------------------------------------------- |
| `ref()`                            | 创建响应式引用，`.value` 访问/修改，模板中自动解包                    |
| `reactive()`                       | 创建响应式对象，直接访问属性，不能替换整个对象                        |
| `computed()`                       | 计算属性，缓存结果，依赖变化时重新计算                                |
| `watch()`                          | 监听响应式数据变化，执行副作用。默认懒执行，可配置 `immediate`/`deep` |
| `watchEffect()`                    | 自动追踪依赖的 watch，立即执行一次                                    |
| `onMounted()` / `onUnmounted()` 等 | 生命周期钩子                                                          |

#### 生命周期 V2 vs V3 对照表

| Vue 2 (Options API) | Vue 3 (Composition API) | 说明                                                                 |
| ------------------- | ----------------------- | -------------------------------------------------------------------- |
| `beforeCreate`      | **`setup()`** 本身      | 组件实例初始化前，无法访问 `data`/`methods`。Vue 3 由 `setup()` 替代 |
| `created`           | **`setup()`** 本身      | 实例已创建，可访问响应式数据，但 DOM 未挂载。Vue 3 由 `setup()` 替代 |
| `beforeMount`       | `onBeforeMount`         | DOM 挂载前。此时 `render` 函数即将首次执行，VDOM 已生成但未挂载      |
| `mounted`           | `onMounted`             | DOM 挂载完成。可以访问真实 DOM，适合发起网络请求、初始化第三方库     |
| `beforeUpdate`      | `onBeforeUpdate`        | 数据变化后、DOM 更新前。可以在此获取更新前的 DOM 状态                |
| `updated`           | `onUpdated`             | DOM 重新渲染完成。注意：不要在此更改数据，会导致无限循环             |
| `beforeDestroy`     | **`onBeforeUnmount`**   | 组件销毁前。清除定时器、取消订阅、解绑事件                           |
| `destroyed`         | **`onUnmounted`**       | 组件销毁完成。所有子组件也已被销毁                                   |
| `errorCaptured`     | `onErrorCaptured`       | 捕获后代组件的错误                                                   |
| `activated`         | `onActivated`           | `<KeepAlive>` 缓存的组件被激活时                                     |
| `deactivated`       | `onDeactivated`         | `<KeepAlive>` 缓存的组件被停用时                                     |

> Vue 3 两个关键命名变化：`beforeDestroy` → `onBeforeUnmount`，`destroyed` → `onUnmounted`，更准确反映组件"卸载"而非"销毁"。

#### Hook 执行顺序（父子组件）

```
父 beforeMount
  → 子 beforeMount
    → 子 mounted
  → 父 mounted

父 beforeUpdate
  → 子 beforeUpdate
    → 子 updated
  → 父 updated

父 beforeUnmount
  → 子 beforeUnmount
    → 子 unmounted
  → 父 unmounted
```

#### setup() 详解

`setup()` 是 Composition API 的入口，在 `beforeCreate` 之前执行：

```javascript
// setup(props, context) —— Vue 3
export default {
  setup(props, context) {
    // props 是响应式的（不可解构，解构会丢失响应性）
    // context: { attrs, slots, emit, expose }

    const count = ref(0)
    const doubled = computed(() => count.value * 2)

    // 暴露给模板和外部
    context.expose({ count, doubled })

    // 返回的对象会合并到组件上下文中（模板可直接使用）
    return { count, doubled }
  }
}

// <script setup> —— Vue 3.2+（推荐）
// 编译时语法糖，无需 return，顶级变量自动暴露给模板
const count = ref(0)
const doubled = computed(() => count.value * 2)
// 编译器自动处理：等同于 setup() return
```

**为什么 `beforeCreate` 和 `created` 被移除？**

- `setup()` 在实例创建之前执行，包含了 `beforeCreate` 和 `created` 的全部时机窗口
- 在 `setup()` 中可以直接访问响应式数据和组合函数，不再需要等待 `data` 初始化
- 减少生命周期数量，降低理解成本

#### 关键差异（Vue 2 Options API vs Vue 3 Composition API）

| 对比项     | Options API                                   | Composition API                     |
| ---------- | --------------------------------------------- | ----------------------------------- |
| 代码组织   | 按选项类型（data/computed/methods/watch）分散 | 按功能/逻辑聚合在一起               |
| 逻辑复用   | Mixins（命名冲突、来源不清晰）                | 组合函数（composables），函数级复用 |
| TypeScript | 类型推断困难                                  | 天然友好                            |
| `this`     | 大量使用 `this`                               | 无 `this`                           |

#### ref vs reactive 选用原则

- 单值（string、number、boolean）→ `ref`
- 需要整个替换 → `ref` 包裹对象
- 不需要整个替换的对象 → `reactive`
- 数组 → `ref`（`reactive` 包裹数组赋值会丢失响应性）

:::

### 2.2 MVVM框架设计理念

::: details 参考

MVVM（Model-View-ViewModel）是一种通过**数据绑定**解耦视图和业务的架构模式。

```
View (模板/DOM)
    ↕    数据绑定（声明式）
ViewModel (Vue 实例/组件) —— Model（数据/状态）
```

三层职责：

- **Model（数据层）**：纯数据和业务逻辑，不关心 UI。通常是 `ref()`/`reactive()` 定义的状态和 API 请求。
- **View（视图层）**：模板/DOM，用户看到的界面。Vue 中就是 `<template>` 部分。
- **ViewModel（视图模型层）**：View 和 Model 之间的桥梁。Vue 组件实例就是 ViewModel，通过响应式系统自动同步 View 和 Model。

#### 核心机制：响应式数据绑定

View ←→ ViewModel：通过模板语法（`{{ }}`、`v-bind`、`v-model`）声明式绑定，开发者无需手动操作 DOM。
ViewModel ←→ Model：通过响应式系统，数据变化自动通知视图更新。

#### 相比传统开发模式的优势

| 传统（jQuery）                     | MVVM（Vue）                     |
| :--------------------------------- | :------------------------------ |
| `$('#el').val('xxx')` 手动操作 DOM | `data.value = 'xxx'` 声明式更新 |
| 数据和 DOM 容易不同步              | 响应式系统保证一致性            |
| 业务逻辑和 DOM 操作混杂            | 关注点分离                      |

> 理解要点：MVVM 的核心不是"双向绑定"，而是**响应式**——框架帮你追踪数据依赖，在数据变化时自动更新该更新的地方。

:::

### 2.3 Vue双向绑定实现原理

::: details 参考

#### Vue 2（Object.defineProperty）

```javascript
function observe(obj) {
  if (typeof obj !== 'object' || obj === null) return
  Object.keys(obj).forEach((key) => {
    let value = obj[key]
    const dep = new Dep() // 依赖收集器
    Object.defineProperty(obj, key, {
      get() {
        Dep.target && dep.addSub(Dep.target) // 收集依赖
        return value
      },
      set(newVal) {
        if (newVal === value) return
        value = newVal
        observe(newVal) // 新值也需要劫持
        dep.notify() // 通知更新
      }
    })
    observe(value) // 递归劫持
  })
}
```

**Vue 2 的局限**：

- 无法检测对象属性新增/删除 → 需要 `Vue.set()` / `Vue.delete()`
- 无法直接通过索引修改数组 → 需要重写数组方法
- 初始化时深度递归，性能开销大

#### Vue 3（Proxy）

```javascript
function reactive(obj) {
  return new Proxy(obj, {
    get(target, key, receiver) {
      track(target, key) // 依赖收集
      const result = Reflect.get(target, key, receiver)
      if (typeof result === 'object' && result !== null) {
        return reactive(result) // 懒代理（用到才代理）
      }
      return result
    },
    set(target, key, value, receiver) {
      const oldValue = target[key]
      const result = Reflect.set(target, key, value, receiver)
      if (oldValue !== value) {
        trigger(target, key) // 派发更新
      }
      return result
    },
    deleteProperty(target, key) {
      const hadKey = Object.prototype.hasOwnProperty.call(target, key)
      const result = Reflect.deleteProperty(target, key)
      if (hadKey) trigger(target, key)
      return result
    }
  })
}
```

| 对比              | Vue 2 (defineProperty) | Vue 3 (Proxy)        |
| ----------------- | ---------------------- | -------------------- |
| 对象新增/删除属性 | 检测不到               | 可以检测             |
| 数组索引修改      | 检测不到               | 可以检测             |
| 数组 `.length`    | 检测不到               | 可以检测             |
| 性能              | 初始化时递归所有属性   | 懒代理，用到时才代理 |
| 兼容性            | 支持 IE                | Proxy 不支持 IE      |

#### 「双向绑定」到底是怎么「双向」的？

1. **Model → View**：数据变化 → 响应式系统通知 watcher → diff → patch DOM
2. **View → Model**：`v-model` 本质是语法糖，监听 input 事件 → 更新数据

```vue
<!-- 这两行等价 -->
<input v-model="name" />
```

#### 深入：Vue 2 响应式完整链路（Dep + Watcher + Scheduler）

面试高频题——"描述 Vue 数据变化后到 DOM 更新的完整过程"：

```
1. 数据变化 → setter 触发
2. Dep.notify() → 通知所有收集到的 Watcher
3. Watcher.update() → 不立即执行，而是把自己交给 Scheduler
4. Scheduler 将 watcher 推入队列（同一个 watcher 去重）
5. nextTick(flushSchedulerQueue) → 异步清空队列
6. Watcher.run() → 执行更新（对比新旧值 → 通知组件重新渲染）
7. 组件 render → 产生新 VNode → patch(oldVNode, newVNode)
```

```javascript
// Vue 2 完整响应式系统核心类
class Dep {
  constructor() {
    this.subs = [] // 订阅者 = Watcher 实例列表
  }
  addSub(sub) {
    this.subs.push(sub)
  }
  notify() {
    // 通知所有 watcher 更新
    this.subs.forEach((sub) => sub.update())
  }
}

// 全局唯一的"当前正在求值的 watcher"
Dep.target = null
const targetStack = [] // 处理嵌套 watcher（如 computed 依赖 computed）

function pushTarget(watcher) {
  targetStack.push(watcher)
  Dep.target = watcher
}
function popTarget() {
  targetStack.pop()
  Dep.target = targetStack[targetStack.length - 1]
}

class Watcher {
  constructor(vm, expOrFn, cb) {
    this.vm = vm
    this.getter = typeof expOrFn === 'function' ? expOrFn : parsePath(expOrFn)
    this.cb = cb
    this.deps = [] // 当前 watcher 依赖了哪些 dep
    this.depIds = new Set() // 去重用
    this.value = this.get() // 首次求值，触发依赖收集
  }

  get() {
    pushTarget(this) // Dep.target = 当前 watcher
    const value = this.getter.call(this.vm, this.vm) // 执行 → 触发 getter → 收集依赖
    popTarget() // Dep.target = 上一个 watcher
    return value
  }

  addDep(dep) {
    // 双向记录：watcher 记住 dep，dep 记住 watcher
    const id = dep.id
    if (!this.depIds.has(id)) {
      this.depIds.add(id)
      this.deps.push(dep)
      dep.addSub(this)
    }
  }

  update() {
    // 数据变化时 dep.notify() 调用此方法
    queueWatcher(this) // 不直接执行，交给调度器
  }

  run() {
    const oldValue = this.value
    this.value = this.get() // 重新求值
    this.cb.call(this.vm, this.value, oldValue) // 触发回调（组件更新/用户 watch 回调）
  }
}
```

**关键面试追问**：

- **为什么 Dep 和 Watcher 是"多对多"关系？** — 一个数据可以被多个 watcher（组件、computed、用户 watch）依赖；一个 watcher 也可以依赖多个数据（如模板里用了多个响应式变量）。
- **嵌套 watcher 如何处理？** — 用 `targetStack` 栈来保存和恢复 `Dep.target`，保证 watcher 嵌套时不会错乱。

#### 深入：Vue 3 响应式完整链路（effect + track + trigger + scheduler）

Vue 3 用更通用的 **effect（副作用）** 概念替代了 Vue 2 的 Watcher：

```
数据变化 → Proxy set → trigger(target, key)
  → 找到 target[key] 对应的所有 effect
  → 将 effect 加入调度队列（去重 + 排序）
  → nextTick(flushQueue) → 逐个执行 effect.run()
  → effect 重新执行 → 组件重新渲染
```

```javascript
// Vue 3 @vue/reactivity 核心简化实现

// ━━━ 全局状态 ━━━
let activeEffect // 当前正在执行的 effect
const targetMap = new WeakMap() // target → key → Set<effect>
// WeakMap 的 key 是弱引用，target 没其他引用时可以 GC

// ━━━ track：依赖收集 ━━━
function track(target, key) {
  if (!activeEffect) return // 没有在 effect 中读取数据 → 不需要追踪

  let depsMap = targetMap.get(target)
  if (!depsMap) {
    targetMap.set(target, (depsMap = new Map()))
  }
  let dep = depsMap.get(key)
  if (!dep) {
    depsMap.set(key, (dep = new Set()))
  }
  dep.add(activeEffect) // 记录：这个 key 被当前 effect 依赖了

  // 同时让 effect 也记住 dep（用于清理旧依赖）
  activeEffect.deps.push(dep)
}

// ━━━ trigger：派发更新 ━━━
function trigger(target, key) {
  const depsMap = targetMap.get(target)
  if (!depsMap) return
  const dep = depsMap.get(key)
  if (!dep) return

  const effectsToRun = new Set(dep)
  effectsToRun.forEach((effect) => {
    if (effect.scheduler) {
      effect.scheduler() // 组件渲染 effect 有 scheduler → 走调度
    } else {
      effect.run() // watchEffect 无 scheduler → 直接执行
    }
  })
}

// ━━━ effect：副作用函数 ━━━
class ReactiveEffect {
  constructor(fn, scheduler = null) {
    this.fn = fn
    this.scheduler = scheduler
    this.deps = []
    this.active = true
  }

  run() {
    if (!this.active) return this.fn()
    cleanupEffect(this) // 清除旧的依赖关系
    activeEffect = this // 设为当前 effect
    const result = this.fn() // 执行 → 触发 getter → track 收集依赖
    activeEffect = null
    return result
  }

  stop() {
    // 停止 effect（如 watchEffect 返回的停止函数）
    if (this.active) {
      cleanupEffect(this)
      this.active = false
    }
  }
}

function cleanupEffect(effect) {
  // 每个 effect 也记录了自己的 deps，所以可以反向清理
  effect.deps.forEach((dep) => dep.delete(effect))
  effect.deps.length = 0
}
```

**Vue 3 相比 Vue 2 的核心改进**：

|            | Vue 2 (Watcher)                    | Vue 3 (effect)                                                            |
| ---------- | ---------------------------------- | ------------------------------------------------------------------------- |
| 依赖存储   | Dep 实例挂在 `__ob__` 上（闭包内） | WeakMap → Map → Set 三层结构                                              |
| 对象 key   | `Object.keys()` 遍历注册           | Proxy 拦截，用到才追踪                                                    |
| 数组       | 重写数组方法                       | Proxy 天然支持                                                            |
| 嵌套对象   | 初始化时深度递归                   | 懒代理：访问子对象时才 `reactive()`                                       |
| 依赖清理   | watcher 直接持有 dep 列表          | `cleanupEffect()` 重新执行前清理旧依赖                                    |
| 副作用范围 | 仅 watcher                         | effect 是通用概念（watch / watchEffect / computed / 组件渲染都是 effect） |

#### ref() 的内部实现

`ref()` 不是简单的 `reactive({ value: x })`。对于基础类型（string/number/boolean），无法用 Proxy 代理（Proxy 只能代理对象），所以 `ref` 用 class + getter/setter：

```javascript
class RefImpl {
  constructor(value) {
    this._rawValue = value
    this._value = isObject(value) ? reactive(value) : value
    this.__v_isRef = true
  }

  get value() {
    track(this, 'value') // 收集依赖
    return this._value
  }

  set value(newVal) {
    if (hasChanged(newVal, this._rawValue)) {
      // Object.is 比较
      this._rawValue = newVal
      this._value = isObject(newVal) ? reactive(newVal) : newVal
      trigger(this, 'value') // 派发更新
    }
  }
}
```

**`ref` vs `reactive` 选择**：

- `ref` 可以持有任意值（包括基础类型），通过 `.value` 访问。模板中自动解包。
- `reactive` 只能代理对象，直接访问属性。但不能被整体替换，也不能解构（丢失响应性）。
- 面试技巧：说清楚 `ref` 对对象类型内部还是调了 `reactive` 就行。

#### 调度器（Scheduler）—— 批量更新 + nextTick

```javascript
// Vue 3 调度队列简化
const queue = [] // 待执行的 effect
let isFlushing = false
const resolvedPromise = Promise.resolve()
let currentFlushPromise = null

function queueJob(job) {
  if (!queue.includes(job)) {
    // 去重
    queue.push(job)
    queueFlush()
  }
}

function queueFlush() {
  if (!isFlushing) {
    isFlushing = true
    currentFlushPromise = resolvedPromise.then(flushJobs)
  }
}

function flushJobs() {
  isFlushing = false
  queue.sort((a, b) => a.id - b.id) // 父组件优先于子组件
  queue.forEach((job) => job.run())
  queue.length = 0
  currentFlushPromise = null
}
```

> 面试金句："Vue 的响应式是**异步批量更新**——同一 tick 内多次数据变化只触发一次组件重新渲染，通过微任务在事件循环末尾统一执行。"

#### Proxy 为什么不能被 IE 兼容？为什么不用 Object.defineProperty 做 Polyfill？

Proxy 是语言层面的能力，无法用旧 API 模拟。它拦截的是对对象的**任何操作**（包括 `in`、`delete`、`for...in`、`Object.keys`、数组索引、`.length`），而 `Object.defineProperty` 只能劫持已知属性的 get/set。因此 Vue 3 直接放弃了 IE 兼容。

### 2.4 Diff算法的内部实现,vue3相比vue2，它在diff算法上做了哪些优化？

::: details 参考

#### 为什么需要 Diff？

当数据变化时，直接销毁整个 DOM 树再重建代价巨大。虚拟 DOM Diff 的目标是：**对比新旧两颗 VNode 树，找出最小的 DOM 更新操作。**

Diff 的三大前提假设（使 O(n³) 降为 O(n)）：

1. 只做同层比较，不跨层级
2. 不同类型的元素会生成不同的树
3. 通过 `key` 标识哪些子元素是"同一个"

#### Vue 2 双端 Diff

维护 4 个指针：`oldStart`、`oldEnd`、`newStart`、`newEnd`，每轮比较 4 种情况：

1. oldStart ↔ newStart
2. oldEnd ↔ newEnd
3. oldStart ↔ newEnd
4. oldEnd ↔ newStart

若都不匹配，则去旧节点中用 `key` 查找。这种方式需要频繁移动指针。

#### Vue 3 优化

**1. 预处理（前置/后置）**
先从头到尾找出相同的前缀节点（不用 diff），再从尾到头找出相同的后缀节点，只对中间真正变化的节点做 diff。

```
旧: [A, B, C, D, E, F, G]
新: [A, B, E, D, C, F, G]

预处理后 → 前缀 A,B 不变，后缀 F,G 不变
真正需 diff: [C, D, E] vs [E, D, C]
```

**2. 最长递增子序列（LIS）**
对于中间乱序部分，通过最长递增子序列找出不需要移动的节点，只移动其余节点。

```javascript
// 场景: 旧 [a,b,c,d,e] → 新 [a,c,b,e,d]
// 新节点在旧数组中的索引: [0, 2, 1, 4, 3]
// LIS = [0, 1, 3] 或 [0, 2, 3]（长度 3）
// 只移动不在 LIS 中的节点
```

**3. 静态标记（PatchFlag）**
编译模板时给动态节点打标记，运行时跳过静态节点比较。

```html
<!-- 编译产物带 PatchFlag -->
<div>
  <span>静态文本</span>
  <span>{{ msg }}</span>
  <!-- 带 1 /* TEXT */ 标记 -->
</div>
```

**4. Block Tree**
将模板按动态绑定拆分为 Block，Diff 时只遍历 Block 树，跳过纯静态的子树。

**5. 相同类型节点判断优化**
Vue 3 在 patch 时增加更多前置判断，如 `key` 相同且 `type` 相同时直接复用。

| 优化比较  | Vue 2     | Vue 3                   |
| --------- | --------- | ----------------------- |
| diff 策略 | 双端比较  | 预处理 + 最长递增子序列 |
| 静态节点  | 全量 diff | PatchFlag 跳过          |
| 模板编译  | 无优化    | Block Tree + 静态提升   |
| 节点复用  | key + tag | 增加 ShapeFlag 快速判断 |

### 2.5 Vue2为什么要对数组的常用方法进行重写？

::: details 参考

#### 原因

`Object.defineProperty` 可以劫持数组索引的 getter/setter，但：

1. **性能问题**：大数组劫持每个索引代价极高
2. **设计取舍**：实践中通过索引直接修改数组的场景极少

所以 Vue 2 选择**不劫持每个索引**，而是**重写会改变原数组的 7 个方法**，在这些方法被调用时手动触发更新。

#### 重写的 7 个方法

`push`、`pop`、`shift`、`unshift`、`splice`、`sort`、`reverse`

```javascript
// Vue 2 内部实现简化版
const arrayProto = Array.prototype
const arrayMethods = Object.create(arrayProto)

;['push', 'pop', 'shift', 'unshift', 'splice', 'sort', 'reverse'].forEach((method) => {
  const original = arrayProto[method]
  Object.defineProperty(arrayMethods, method, {
    value: function (...args) {
      const result = original.apply(this, args)
      const ob = this.__ob__ // Observer 实例
      let inserted
      switch (method) {
        case 'push':
        case 'unshift':
          inserted = args
          break
        case 'splice':
          inserted = args.slice(2)
          break
      }
      if (inserted) ob.observeArray(inserted) // 新元素也需要响应式
      ob.dep.notify() // 通知更新
      return result
    }
  })
})
```

#### 仍检测不到的变更

- 通过索引赋值：`arr[0] = val` → 使用 `Vue.set(arr, 0, val)` 或 `arr.splice(0, 1, val)`
- 修改 `.length`：`arr.length = 0` → 使用 `arr.splice(0)`

#### Vue 3 的改进

Proxy 天然能拦截 `arr[0] = val` 和 `.length` 赋值，**不再需要重写数组方法**。

### 2.6 Vue的nextTick是怎么实现的？

::: details 参考

#### 作用

将回调延迟到 DOM 更新完成后执行。因为 Vue 是**异步更新 DOM**的——数据变化时不会立即更新 DOM，而是批量推入队列，在下一次"tick"统一执行。

```javascript
import { nextTick } from 'vue'

state.value = 'hello'
console.log(dom.textContent) // 旧值！
await nextTick()
console.log(dom.textContent) // 'hello'
```

#### 实现原理

Vue 的 `nextTick` 本质是对浏览器异步任务的封装，按优先级降级：

```javascript
// 简化实现
const callbacks = []
let pending = false

function flushCallbacks() {
  pending = false
  const copies = callbacks.slice(0)
  callbacks.length = 0
  copies.forEach((cb) => cb())
}

let timerFunc

// 优先使用微任务
if (typeof Promise !== 'undefined') {
  timerFunc = () => Promise.resolve().then(flushCallbacks)
}
// 降级到 MutationObserver（微任务）
else if (typeof MutationObserver !== 'undefined') {
  let counter = 1
  const observer = new MutationObserver(flushCallbacks)
  const textNode = document.createTextNode(String(counter))
  observer.observe(textNode, { characterData: true })
  timerFunc = () => {
    textNode.data = String(++counter)
  }
}
// 再降级到 setImmediate（宏任务，仅 IE/Node）
else if (typeof setImmediate !== 'undefined') {
  timerFunc = () => setImmediate(flushCallbacks)
}
// 最后兜底 setTimeout
else {
  timerFunc = () => setTimeout(flushCallbacks, 0)
}

function nextTick(cb) {
  callbacks.push(cb)
  if (!pending) {
    pending = true
    timerFunc()
  }
}
```

#### 执行流程

```
数据变化 → 触发 watcher
  → watcher 被推入更新队列（去重，同一个 watcher 只会被推进一次）
  → nextTick(flushSchedulerQueue)
  → 微任务/Promise.resolve()
  → DOM 更新完成
  → 用户 nextTick 回调执行
```

#### Vue 2 vs Vue 3

Vue 2 用宏任务/微任务兼容方案。Vue 3 直接统一用 `Promise.resolve()`，不再兼容 IE。

> `nextTick` 返回 Promise，可以 `await nextTick()` 而不用传回调。

:::

### 2.7 Vue的事件机制

::: details 参考

#### 模板事件绑定

```vue
<!-- 内联处理器 -->
<button @click="count++">+1</button>

<!-- 方法处理器 -->
<button @click="handleClick">Click</button>

<!-- 传参 + $event -->
<button @click="handleClick($event, 'extra')">Click</button>

<!-- 事件修饰符 -->
<button @click.stop="handle">阻止冒泡</button>
<input @keyup.enter="submit" />
```

#### 常用修饰符

| 修饰符                         | 作用                                 |
| ------------------------------ | ------------------------------------ |
| `.stop`                        | 阻止事件冒泡 (`e.stopPropagation()`) |
| `.prevent`                     | 阻止默认行为 (`e.preventDefault()`)  |
| `.self`                        | 只在事件源是自身时触发               |
| `.once`                        | 只触发一次                           |
| `.capture`                     | 使用捕获模式                         |
| `.passive`                     | 不阻止默认行为（滚动性能优化）       |
| `.left` / `.right` / `.middle` | 鼠标按键过滤                         |

#### 自定义事件（组件通信）

```vue
<!-- 子组件 -->
<script setup>
const emit = defineEmits(['update', 'delete'])
emit('update', { id: 1 })
</script>

<!-- 父组件 -->
<Child @update="handleUpdate" />
```

#### 事件底层机制

Vue 模板编译时，事件绑定被编译为 `onXXX` 的 props。组件事件通过发布-订阅模式实现：

1. 组件实例维护 `_events` 对象，存储事件名 → 回调函数列表
2. `$emit('eventName', ...args)` → 查找 `_events['eventName']` → 依次执行回调
3. `$on` / `$off` / `$once` 直接操作 `_events` 对象

Vue 3 移除了 `$on/$off/$once`（实例级别事件总线），推荐使用 mitt 等轻量库或 props/emits。

#### 对比 React 事件

|          | Vue                        | React                          |
| -------- | -------------------------- | ------------------------------ |
| 绑定方式 | `@click="handler"`         | `onClick={handler}`            |
| 事件对象 | 原生事件                   | 合成事件（SyntheticEvent）     |
| 事件委托 | 不强制                     | 默认委托到 root 上（React 17） |
| 修饰符   | 内置 `.stop` `.prevent` 等 | 需手动处理                     |

#### Vue 3 事件机制的变化

**1. `$on` / `$off` / `$once` 被移除**

Vue 2 中很常见的事件总线（Event Bus）模式：

```javascript
// Vue 2 事件总线（Vue 3 不可用）
const bus = new Vue()
bus.$on('event', handler)
bus.$emit('event', data)
bus.$off('event', handler)
```

Vue 3 **移除了实例级别的 `$on/$off/$once`**，原因：

- 事件总线导致代码流向难以追踪（"哪里发了这个事件？"）
- 大型项目中事件总线变成"全局变量"，难以维护
- 推荐使用 props/emits 显式传参，或轻量库 mitt

```javascript
// Vue 3 替代方案 1：mitt（~200 bytes）
import mitt from 'mitt';
const emitter = mitt();
emitter.on('event', handler);
emitter.emit('event', data);

// Vue 3 替代方案 2：provide/inject + 回调
// 祖先组件
provide('onUpdate', (data) => { ... });
// 后代组件
const onUpdate = inject('onUpdate');
onUpdate(data);
```

**2. `emits` 选项**

Vue 3 新增 `emits` 选项，声明组件会触发的所有事件。与 `props` 一样形成"组件契约"：

```vue
<!-- Vue 2 -->
<script>
export default {
  emits: ['update', 'delete'] // Vue 3 新增，Vue 2 无此选项
}
</script>

<script setup>
// <script setup> 语法
const emit = defineEmits<{
  update: [id: number];
  delete: [id: number];
}>();
// 或简写
const emit = defineEmits(['update', 'delete']);
</script>
```

`emits` 的作用：

- 文档化：一眼看出组件向外暴露哪些事件
- 类型推断：TS 中 `emit('xxx', payload)` 可得到类型检查
- **事件验证**：`emits` 可返回 `true/false` 验证 payload
- 优先于原生事件：`emits` 中声明的事件不会再绑定到组件根元素上作为原生事件

**3. 原生事件 vs 组件事件**

Vue 2 中 `.native` 修饰符用于在组件根元素上监听原生事件（`<Comp @click.native="handle" />`）。Vue 3 移除了 `.native` ——不在 `emits` 声明中的事件自动 fallback 到组件根元素的原生事件。

:::

### 2.8 从template转换成真实DOM的实现机制

::: details 参考

整个流程分为**编译**和**运行时**两大阶段：

#### 编译阶段（Compile）

```
Template → AST 解析 → 优化 → 生成渲染函数
```

**1. 词法+语法解析 → AST**

```html
<div id="app">
  <p>{{ message }}</p>
</div>
```

被解析为嵌套的 AST 节点，每个节点包含 `type`（元素/文本/插值）、`tag`、`attrs`、`children` 等信息。

**2. 优化（Optimize）**

- **静态节点标记**：遍历 AST，给纯静态节点打 `static: true` 标记，后续 diff 直接跳过。
- **静态提升（Hoisting）**：将静态节点提升到 `render` 函数外部，多次渲染复用同一个 VNode。
- **PatchFlag**：给动态节点标记变化的类型（文本/class/style/props），diff 时只看这些 flag。

**3. 生成（Generate）**

将 AST 转换为 `render` 函数的代码字符串：

```javascript
// 编译产出（简化）
function render(_ctx, _cache) {
  return _createVNode('div', { id: 'app' }, [
    _createVNode('p', null, _toDisplayString(_ctx.message), 1 /* TEXT */)
  ])
}
```

#### 运行时阶段（Runtime）

```
render() → VNode Tree → patch(oldVNode, newVNode) → 真实 DOM
```

**1. 首次渲染（Mount）**

- 执行 `render()` → 产生 VNode 树
- `patch(null, vnode, container)` → 遍历 VNode 递归创建真实 DOM → 插入 `container`
- `mounted` 钩子触发

**2. 更新（Update）**

- 响应式数据变化 → 重新执行 `render()` → 产生新 VNode 树
- `patch(oldVNode, newVNode)` → Diff 算法对比 → 最小化 DOM 操作
- `updated` 钩子触发

#### Vue 3 编译器优化详解

Vue 3 的编译优化是整个框架性能提升的关键。编译器不仅要生成 `render` 函数，还要给运行时提供"提示信息"。

**1. PatchFlag（补丁标记）**

编译器分析模板中的动态绑定，给每个动态节点打上标记，告诉运行时"这个节点的什么会变"：

```javascript
// PatchFlag 类型（部分）
const PatchFlags = {
  TEXT: 1, // 动态文本 {{ }}
  CLASS: 2, // 动态 class
  STYLE: 4, // 动态 style
  PROPS: 8, // 动态属性（不含 class/style）
  FULL_PROPS: 16, // 有动态 key（需完整 diff）
  HYDRATE_EVENTS: 32, // 有事件监听
  STABLE_FRAGMENT: 64, // 子元素顺序不会变的 Fragment
  KEYED_FRAGMENT: 128, // 带 key 的 Fragment
  UNKEYED_FRAGMENT: 256, // 无 key 的 Fragment
  NEED_PATCH: 512, // 需要 patch
  DYNAMIC_SLOTS: 1024 // 动态插槽
}
```

```html
<!-- 模板 -->
<div>
  <h1>静态标题</h1>
  <!-- 无 PatchFlag，diff 时直接跳过 -->
  <p>{{ msg }}</p>
  <!-- PatchFlag: 1 (TEXT)，只比较文本 -->
  <p :class="cls">{{ msg }}</p>
  <!-- PatchFlag: 3 (TEXT | CLASS) -->
</div>
```

运行时 diff 时，如果节点没有 PatchFlag，直接跳过比较。这是一个巨大的优化。

**2. 静态提升（Static Hoisting）**

静态节点（永远不变的节点）被提升到 `render` 函数外部，多组件实例共享同一个 VNode，避免重复创建：

```javascript
// 编译前模板
;<div>
  <p>这是一段永远不会变的静态文字</p>
  <span>{{ dynamic }}</span>
</div>

// 编译后（简化）
const _hoisted_1 = /*#__PURE__*/ createVNode('p', null, '这是一段永远不会变的静态文字')

function render(_ctx) {
  return createVNode('div', null, [
    _hoisted_1, // 复用同一个 VNode，不重新创建
    createVNode('span', null, _ctx.dynamic, 1 /* TEXT */)
  ])
}
```

**3. 预字符串化（Pre-stringify）**

如果连续多个静态节点且没有动态内容夹杂，编译时直接拼接成 HTML 字符串：

```html
<!-- 编译前 -->
<div>
  <p>段落1</p>
  <p>段落2</p>
  <p>段落3</p>
</div>

<!-- 编译后：整个静态块变成一个 Static VNode -->
const _hoisted_1 = createStaticVNode('
<p>段落1</p>
<p>段落2</p>
<p>段落3</p>
');
```

`createStaticVNode` 在挂载时直接用 `innerHTML` 一次性插入，比逐个 `createElement` + `appendChild` 快得多。

**4. Block Tree**

Vue 3 的 VNode 引入了一个新概念 —— **Block**：

- Block 节点记录了所有带 PatchFlag 的后代动态节点（跳过静态节点）
- Diff 时只遍历 Block 记录的动态节点列表，不递归遍历整棵树
- 每个 Block 通过 `dynamicChildren` 数组持有子孙动态节点的引用

```html
<template>
  <div>
    <!-- Block 根节点 -->
    <span>标题</span>
    <span>{{ msg1 }}</span>
    <!-- dynamicChildren[0] -->
    <div>
      <p>深层静态</p>
      <p>{{ msg2 }}</p>
      <!-- dynamicChildren[1] -->
    </div>
  </div>
</template>
```

**5. 事件缓存（Cache Handlers）**

编译器识别出模板中的事件处理函数（非动态绑定的），会缓存函数引用：

```html
<!-- 模板 -->
<button @click="count++">+1</button>

<!-- 编译后 -->
function render(_ctx, _cache) { return createVNode('button', { onClick: _cache[0] || (_cache[0] =
($event) => (_ctx.count++)) }, '+1'); }
```

这样每次 render 时，`onClick` 拿到的都是同一个函数引用，patch 阶段比对 props 时发现没变化，就不会移除旧事件再绑定新事件。

**6. `v-memo`（Vue 3.2+）**

手动指定依赖，只有当依赖变化时才重新渲染子树：

```html
<div v-memo="[valueA, valueB]">
  <!-- 只有 valueA 或 valueB 变化时，这个子树才重新渲染 -->
  <span>{{ computeExpensive(valueA) }}</span>
</div>
```

**7. `v-once` + `v-memo` 结合（Vue 3.2+）**

```html
<div v-once v-memo="[]">
  <!-- 永远不会重新渲染 -->
</div>
```

#### Vue 3 编译策略对比 Vue 2

| 编译优化   | Vue 2                                   | Vue 3                                    |
| ---------- | --------------------------------------- | ---------------------------------------- |
| 静态节点   | 仅标记 `static: true`，运行时仍需要判断 | PatchFlag 精确定位 + Block Tree 直接跳过 |
| 静态提升   | 无                                      | 提升到 render 外，多实例共享             |
| 预字符串化 | 无                                      | 连续静态节点 → `innerHTML` 一次插入      |
| 事件缓存   | 无                                      | `_cache` 缓存函数引用                    |
| 动态锁定   | 无（全量 diff）                         | Block + dynamicChildren 只 diff 动态节点 |

> Vue 3 的编译策略是"动静分离"的极致应用——编译器在构建时尽可能多地分析出哪些是不变的，运行时就可以跳过这部分工作。

:::

### 2.9 vue中都使用了那些设计模式

::: details 参考

- **观察者模式**：响应式系统核心。数据是被观察者（Dep/effect），Watcher 是观察者。数据变化时通知所有依赖更新。

- **发布-订阅模式**：组件事件系统（`$emit` / `$on`），以及 Vuex 的 store 订阅。

- **策略模式**：编译器对不同指令（`v-if`、`v-for`、`v-model`）使用不同的代码生成策略。`mergeOptions` 对不同选项（data、computed、methods）有不同的合并策略。

- **代理模式**：Vue 3 的 `Proxy` 响应式系统，代理对原始对象的访问。计算属性 `computed` 也是代理模式——访问 `.value` 时代理到实际的计算函数。

- **工厂模式**：`createApp()`、`createRouter()`、`createStore()` 等创建实例的工厂函数。VNode 的创建 `h()` 函数也是工厂方法。

- **单例模式**：全局路由实例 `router`、Vuex store 实例。

- **组合模式**：Vue 3 的 Composables（组合函数）将分散的逻辑组合到组件中。

- **装饰器模式**：高阶组件（HOC）、`mixins`——在不修改原组件的情况下增强功能。

- **适配器模式**：`computed` 将普通函数适配为带缓存的响应式引用。

- **模版方法模式**：生命周期钩子——框架定义好流程骨架（创建→挂载→更新→销毁），开发者只需"填空"钩子函数。

:::

### 2.9 vue中 computed 与 watch 的实现原理

::: details 参考

#### computed 实现原理

computed 本质上是一个**惰性求值的、带缓存的 watcher**。

```javascript
// 简化实现
class ComputedRefImpl {
  private _value: any;
  private _dirty = true;  // 脏标志，控制缓存
  private effect: ReactiveEffect;

  constructor(getter) {
    this.effect = new ReactiveEffect(getter, () => {
      // scheduler: 依赖变化时不立即重新计算，只标记为脏
      if (!this._dirty) {
        this._dirty = true;
        trigger(this, 'value'); // 通知 computed 的依赖更新
      }
    });
  }

  get value() {
    if (this._dirty) {
      this._value = this.effect.run(); // 重新计算
      this._dirty = false;
    }
    track(this, 'value'); // 收集使用 computed 的副作用
    return this._value;
  }
}
```

核心特性：

1. **惰性求值**：创建时不执行，第一次访问 `.value` 才计算
2. **缓存**：依赖不变时，`.value` 直接返回缓存值（`_dirty = false`）
3. **依赖追踪**：内部依赖变化时，只标记 `_dirty = true`，不立即计算

#### watch 实现原理

```javascript
// 简化实现
function watch(source, cb, { immediate = false, deep = false } = {}) {
  let getter
  if (typeof source === 'function') {
    getter = source
  } else if (typeof source === 'object') {
    getter = () => (deep ? traverse(source) : source) // traverse 深度遍历
  }

  let oldValue
  const job = () => {
    const newValue = effect.run()
    cb(newValue, oldValue)
    oldValue = newValue
  }

  const effect = new ReactiveEffect(getter, job)

  if (immediate) {
    job() // 立即执行，oldValue 为 undefined
  } else {
    oldValue = effect.run() // 只收集依赖，不执行回调
  }
}
```

`deep: true` 时的 `traverse()` 是递归遍历对象所有属性，触发 getter 来收集深层依赖。

#### watchEffect（Vue 3）

自动追踪依赖，不用手动指定 source：

```javascript
const count = ref(0)
watchEffect(() => {
  console.log(count.value) // 自动追踪 count
})
```

内部通过 `effect` 直接运行回调，隐式收集所有读取到的响应式数据。

#### 对比总结

|          | computed         | watch                            | watchEffect              |
| -------- | ---------------- | -------------------------------- | ------------------------ |
| 返回值   | 计算后的值       | 无（执行副作用）                 | 无                       |
| 缓存     | 依赖不变不重算   | 无缓存                           | 无缓存                   |
| 惰性     | 第一次访问才计算 | 默认懒执行                       | 立即执行                 |
| 使用场景 | 派生值           | 异步操作、DOM 操作、开销大的操作 | 需要自动追踪依赖的副作用 |

### 2.10 谈谈你对 `vuex` 的理解

::: details 参考

Vuex 是 Vue 官方的**集中式状态管理方案**，借鉴了 Flux、Redux 的设计思想。

#### 核心理念

```
                    ┌──────────┐
          dispatch  │  Actions │   commit
  Vue Comp ──────→  │ (异步)    │ ──────→
                    └──────────┘
                              ┌──────────┐    ┌──────────┐
                              │ Mutations │ →  │  State   │ → 重新渲染
                              │ (同步)     │    │ (单一状态)│
                              └──────────┘    └──────────┘
                                                  ↑
                              ┌──────────┐         │
                              │  Getters  │ ───────┘
                              │ (计算属性) │
                              └──────────┘
```

- **State**：单一状态树，全局唯一的数据源
- **Getters**：类 computed，基于 state 计算派生值（带缓存）
- **Mutations**：**唯​​一**改变 state 的方式，必须是同步函数（保证 DevTools 可追踪）
- **Actions**：处理异步逻辑，通过 `commit` 触发 mutation，可组合多个 action
- **Modules**：将 store 拆分为模块，每个模块独立管理自己的 state/mutations/actions

#### 数据流

```
组件 dispatch('actionName')
  → Action 执行异步操作（API 请求等）
  → commit('mutationName', payload)
  → Mutation 同步修改 state
  → state 响应式更新 → 所有依赖该 state 的组件重新渲染
```

#### 为什么需要 Vuex

- **多组件共享状态**：父子通信需要逐层 props/emits，兄弟组件通信困难
- **状态可预测**：通过 mutation 严格控制修改入口，配合 DevTools 时间旅行调试
- **代码组织**：将状态逻辑从组件中抽离，组件只负责渲染

#### Vue 3 生态替代方案 —— Pinia

Vue 3 官方推荐 Pinia（Vuex 5 的前身），核心改进：

- 不再有 mutations，直接 `store.xxx = val` 修改（底层仍是响应式追踪）
- 完整的 TypeScript 支持，无需额外类型声明
- 无需嵌套模块，通过组合多个 store 实现模块化
- 更轻量，API 更简洁

```javascript
// Pinia 示例
import { defineStore } from 'pinia'

export const useCounterStore = defineStore('counter', {
  state: () => ({ count: 0 }),
  getters: { doubleCount: (state) => state.count * 2 },
  actions: {
    async increment() {
      this.count++
    }
  }
})
```

### 2.11 首页白屏时间过长如何处理

::: details 参考

白屏时间 = 从用户输入 URL 到页面首次渲染出内容的时间。白屏过长通常由以下因素导致：

#### 1. 构建层面

- **代码拆分（Code Splitting）**：路由懒加载，首屏只加载必要的 JS
  ```javascript
  const Home = () => import('@/views/Home.vue')
  ```
- **Tree Shaking**：确保未使用的代码/库被打包剔除
- **压缩**：JS/CSS 压缩（terser/mini-css-extract-plugin）、Gzip/Brotli 压缩
- **静态资源**：图片压缩、使用 WebP、雪碧图/iconfont/SVG sprite

#### 2. 网络和资源

- **CDN**：静态资源使用 CDN，减少传输延迟
- **资源预加载**：`<link rel="preload">` 关键资源，`<link rel="prefetch">` 非首屏资源
- **HTTP/2 多路复用**：减少连接开销
- **缓存策略**：强缓存（`Cache-Control: max-age`）+ 协商缓存（`ETag`）

#### 3. 渲染层面

- **SSR（服务端渲染）**：Nuxt.js / Next.js，服务端直出 HTML，减少客户端渲染等待
- **SSG（静态站点生成）**：VitePress / Gridsome，构建时生成 HTML
- **骨架屏（Skeleton Screen）**：在 JS 执行完前展示骨架，提升用户感知性能
- **关键 CSS 内联**：将首屏必需 CSS 内联到 HTML，避免额外请求

#### 4. 代码层面

- **第三方依赖按需加载**：如 Element Plus 只引入使用的组件
- **避免同步阻塞**：不在 `main.js` 中做大量同步计算
- **大组件异步加载**：使用 `defineAsyncComponent`
- **减少首屏 API 请求数**：合并请求，或服务端注入初始数据

#### 5. 监控与拆解

用 Chrome Lighthouse / WebPageTest 分析具体瓶颈，定位到具体的资源、请求或脚本。

### 2.12 Vue 3 新增内置组件：Teleport、Suspense、Fragment

::: details 参考

#### Fragment（片段）

Vue 2 中组件模板必须有**单根节点**包裹，多余的 `<div>` 影响布局和语义化。Vue 3 原生支持多根节点：

```vue
<!-- Vue 3：合法，自动用 Fragment 包裹 -->
<template>
  <header>标题</header>
  <main>内容</main>
  <footer>尾部</footer>
</template>

<!-- Vue 2：必须多包一层 div -->
<template>
  <div>
    <header>标题</header>
    <main>内容</main>
    <footer>尾部</footer>
  </div>
</template>
```

原理：编译时将多根节点包裹在 `Fragment` 类型的 VNode 中。Fragment 本身不生成任何 DOM 元素，渲染时只渲染其 children。

#### Teleport（传送门）

将组件的一部分 DOM **传送到 DOM 树的其他位置**（如 `<body>` 底部），常用于 Modal/Dialog/Toast/Notification。

```vue
<template>
  <button @click="showModal = true">打开弹窗</button>

  <!-- 这个 Modal 的 DOM 会被渲染到 body 末尾 -->
  <!-- 但逻辑上仍在当前组件中，props/事件/状态照常工作 -->
  <Teleport to="body">
    <Modal v-if="showModal" @close="showModal = false">
      <p>这是弹窗内容</p>
    </Modal>
  </Teleport>
</template>
```

核心特性：

- **逻辑位置和 DOM 位置解耦**：组件逻辑仍然属于当前组件树（props、事件、provide/inject 正常工作），但 DOM 被"传送"到目标位置
- **to 属性**：可以是 CSS 选择器（`#app`、`body`）或 DOM 元素引用
- **disabled 属性**：动态禁用传送（`disabled="true"` 时组件渲染在原始位置）
- **多个 Teleport**：同一目标可以有多个 `<Teleport>`，按顺序追加

> 与 Vue 2 的 `portal-vue` 库功能相同，但现在是**内置的一等公民组件**。

#### Suspense（悬念，实验性）

在异步组件加载完成前展示 fallback 内容，类似 React 的 `<Suspense>`：

```vue
<template>
  <Suspense>
    <!-- 默认插槽：异步组件 -->
    <template #default>
      <AsyncDashboard />
    </template>

    <!-- fallback 插槽：加载中展示的内容 -->
    <template #fallback>
      <LoadingSpinner />
    </template>
  </Suspense>
</template>

<script setup>
import { defineAsyncComponent } from 'vue'
const AsyncDashboard = defineAsyncComponent(() => import('./Dashboard.vue'))
</script>
```

Suspense 可以处理两种异步依赖：

1. 异步组件（`defineAsyncComponent`）
2. `setup()` 中使用了 `await`（`<script setup>` 顶层 await）

状态：Vue 3.3+ 中仍标记为实验性，一般建议在生产环境的 Nuxt 等框架中间接使用。

:::

### 2.13 Vue 3 破坏性变更详解（面试高频追问）

::: details 参考

#### 变更清单速查

| 序号 | 变更项                         | Vue 2 写法                     | Vue 3 写法 / 替代方案                           |
| ---- | ------------------------------ | ------------------------------ | ----------------------------------------------- |
| 1    | 全局 API                       | `Vue.component()`              | `app.component()`                               |
| 2    | 创建实例                       | `new Vue({})`                  | `createApp({}).mount('#app')`                   |
| 3    | **移除 `$on/$off/$once`**      | `this.$on('evt', fn)`          | mitt / props + emits                            |
| 4    | **移除过滤器**                 | `{{ date \| format }}`         | `computed` / 全局方法                           |
| 5    | **`v-if`/`v-for` 优先级互换**  | `v-for` > `v-if`               | **`v-if` > `v-for`**                            |
| 6    | 移除 `.sync` 修饰符            | `:title.sync="val"`            | `v-model:title="val"`                           |
| 7    | 多 `v-model`                   | 不支持                         | `v-model:title="val"` + `v-model:content="val"` |
| 8    | 移除 `.native`                 | `@click.native="fn"`           | 不在 `emits` 声明的事件自动 fallback            |
| 9    | **移除 `$listeners`**          | `$listeners` 对象              | 合并到 `$attrs` 中（以 `onXxx` 形式）           |
| 10   | `$attrs` 包含 class/style      | 不包含                         | **包含** class/style                            |
| 11   | 渲染函数 `h`                   | 从 `render(h)` 参数传入        | 从 `vue` 全局导入：`import { h } from 'vue'`    |
| 12   | 异步组件                       | `() => import('./C.vue')`      | `defineAsyncComponent(() => import('./C.vue'))` |
| 13   | Transition class               | `v-enter` / `v-leave`          | `v-enter-from` / `v-leave-from`                 |
| 14   | 自定义指令钩子                 | `bind` / `inserted` / `update` | `created` / `mounted` / `updated` 等            |
| 15   | **`key` 在 `v-if` 分支**       | 需手动加                       | 自动生成唯一 key                                |
| 16   | `v-bind` 合并行为              | 独立属性优先                   | `v-bind` 对象中的属性优先（后声明优先）         |
| 17   | 组件 `v-model` 默认 prop/event | `value` / `input`              | `modelValue` / `update:modelValue`              |
| 18   | `data` 必须是函数              | 不需要                         | **必须**是函数（之前根实例可以是对象）          |
| 19   | 被 `v-for` 中的 `key`          | `key` 放在子元素上             | `key` 放在 `<template v-for>` 上                |
| 20   | 函数式组件                     | `functional: true`             | 普通函数即可                                    |

#### 逐项详解（面试最常问的几项）

**1. `v-if` / `v-for` 优先级互换**

```vue
<!-- Vue 2: v-for > v-if，不推荐同时使用 -->
<!-- 列表中条件过滤：v-for 先执行，每次循环判断 v-if -->

<!-- Vue 3: v-if > v-for，v-if 先执行 -->
<!-- v-if 中无法访问 v-for 的变量，会报错！ -->
<div v-for="item in items" v-if="item.active">{{ item.name }}</div>
<!-- Vue 3: v-if not have access to item -->

<!-- 推荐写法 -->
<template v-for="item in items">
  <div v-if="item.active">{{ item.name }}</div>
</template>
<!-- 或直接用 computed 过滤 -->
```

**2. `v-model` 变化**

```vue
<!-- Vue 2 -->
<Child v-model="name" />
<!-- 只能一个 v-model -->
<Child :title.sync="title" />
<!-- .sync 实现"双向绑定"第二个 prop -->

<!-- Vue 3 -->
<Child v-model="name" />
<!-- 等价于 :modelValue + @update:modelValue -->
<Child v-model:title="title" />
<!-- 多 v-model，替换 .sync -->
<Child v-model:title="title" v-model:content="content" />
<!-- = 等价于 -->
<Child
  :title="title"
  :content="content"
  @update:title="title = $event"
  @update:content="content = $event"
/>

<!-- 自定义修饰符 -->
<Child v-model:title.capitalize="title" />
<!-- 子组件中通过 props.modelModifiers 访问 -->
```

子组件接收：

```vue
<script setup>
// Vue 2: prop 叫 value，事件叫 input
defineProps({ value: String })
defineEmits(['input'])

// Vue 3: prop 叫 modelValue，事件叫 update:modelValue
defineProps({ modelValue: String })
defineEmits(['update:modelValue'])
</script>
```

**3. `$attrs` 变化**

Vue 3 中 `$attrs` 包含：

- 所有非 props/non-emits 的属性
- **class 和 style**（Vue 2 不包含！）
- 事件监听器（以 `onXxx` 形式，取代了 Vue 2 的 `$listeners`）

```vue
<!-- 透传组件：一行搞定 -->
<template>
  <el-input v-bind="$attrs" />
</template>
```

**4. 自定义指令钩子重命名**

| Vue 2              | Vue 3       | 说明                               |
| ------------------ | ----------- | ---------------------------------- |
| `bind`             | `created`   | 只调用一次，元素初始化时           |
| `inserted`         | `mounted`   | 元素插入父节点后                   |
| `update`           | —           | **移除**，用 `updated` 替代        |
| `componentUpdated` | `updated`   | 组件 VNode 及其子 VNode 全部更新后 |
| `unbind`           | `unmounted` | 只调用一次，指令与元素解绑时       |

```javascript
// Vue 3 自定义指令
app.directive('focus', {
  mounted(el) {
    el.focus()
  },
  updated(el) {
    /* VNode 更新后 */
  },
  unmounted(el) {
    /* 清理 */
  }
})
```

**5. 渲染函数 `h` 变化**

```javascript
// Vue 2
render(h) {
  return h('div', { attrs: { id: 'app' } }, 'hello');
}

// Vue 3 — h 全局导入
import { h } from 'vue';
export default {
  render() {
    return h('div', { id: 'app' }, 'hello');
  }
}
```

### 2.14 Vue 组件通信方案全景图

::: details 参考

面试常见的 "Vue 组件之间有哪些通信方式？" 系统回答：

| 场景        | 方案                                                     | 适用关系                        |
| ----------- | -------------------------------------------------------- | ------------------------------- |
| 父 → 子     | **props**（最基础）                                      | 父子                            |
| 子 → 父     | **emits**（自定义事件）                                  | 父子                            |
| 父 ↔ 子    | **v-model**（双向绑定语法糖）                            | 父子                            |
| 子访问父    | **$parent** / **$root**（Vue 2 可用，不推荐）            | 父子（边界）                    |
| 父访问子    | **$refs** + **defineExpose**                             | 父子（直接调用子组件方法/数据） |
| 祖先 → 后代 | **provide / inject**（依赖注入，长距离）                 | 祖先-任意后代                   |
| 任意组件    | **mitt**（事件总线，Vue 3 推荐）/ $on/$off（Vue 2 可用） | 任意                            |
| 任意组件    | **Vuex / Pinia**（状态管理）                             | 任意                            |
| 任意组件    | **$attrs**（属性透传，简化中间层）                       | 跨层级                          |
| 任意组件    | **路由传参**（query/params/meta）                        | 跨页面                          |
| 任意组件    | **LocalStorage / SessionStorage**（持久化）              | 任意（简单场景）                |

#### 核心方案详解

**1. provide / inject（Vue 3）**

```javascript
// 祖先组件
import { provide, ref, readonly } from 'vue'
const theme = ref('dark')
const updateTheme = (val) => {
  theme.value = val
}
provide('theme', readonly(theme)) // readonly 防止后代直接修改
provide('updateTheme', updateTheme) // 通过函数修改

// 后代组件（任意深度）
import { inject } from 'vue'
const theme = inject('theme', 'light') // 第二个参数是默认值
const updateTheme = inject('updateTheme')
// 调用 updateTheme('light') 就能影响祖先
```

> Vue 2 的 provide/inject **不是响应式**的（除非传 Vue 实例），Vue 3 中默认响应式。

**2. $attrs 透传（Vue 3）**

```vue
<!-- 中间组件：不需要声明任何 props，直接透传 -->
<template>
  <BaseInput v-bind="$attrs" />
  <!-- $attrs 包含：未被声明为 props 的属性 + class + style + 事件监听器 -->
</template>

<script setup>
// 无需定义任何 props ——默认透传给子组件
// 可以结合 useAttrs()
import { useAttrs } from 'vue'
const attrs = useAttrs() // 响应式，包含外部传来的所有非 props 属性
console.log(attrs.class, attrs.style, attrs.onClick)
</script>
```

**3. mitt 事件总线（替代 Vue 2 $on/$off）**

```javascript
// bus.js
import mitt from 'mitt'
export const bus = mitt()

// 组件 A：监听
import { bus } from './bus'
import { onMounted, onUnmounted } from 'vue'
onMounted(() => bus.on('logout', handleLogout))
onUnmounted(() => bus.off('logout', handleLogout)) // 一定要清理！

// 组件 B：触发
bus.emit('logout')
```

#### 通信方案选择原则

```
是否父子关系？
  ├─ 是 → props + emits / v-model
  ├─ 是（深层嵌套 → 跨多级传参）
  │    └─ provide/inject 或 $attrs 透传
  └─ 否（兄弟 / 任意组件）
       ├─ 全局 UI 状态（主题/语言/登录状态）→ Pinia / Vuex
       ├─ 跨页面传参 → 路由 params / query
       ├─ 临时通知（如"刷新列表"）→ mitt 事件总线，用完要 off
       └─ 多组件共享的服务端数据 → Pinia / composable（带缓存和去重）
```

### 2.15 Vue Router 详解：路由模式、导航守卫、动态路由

::: details 参考

#### 两种路由模式

|            | Hash 模式                                | History 模式                          |
| ---------- | ---------------------------------------- | ------------------------------------- |
| URL 形态   | `xxx.com/#/home`                         | `xxx.com/home`                        |
| 原理       | `hashchange` 事件，`#`之后变化不触发请求 | `history.pushState` + `popstate` 事件 |
| 服务端配置 | 不需要                                   | **必须配置**：所有路径返回 index.html |
| SEO        | 差                                       | 好（URL 干净）                        |
| 兼容性     | 全兼容（含 IE）                          | IE10+                                 |
| 锚点       | 冲突                                     | 正常工作                              |

```javascript
// 创建路由
const router = createRouter({
  history: createWebHashHistory(), // Hash 模式
  // history: createWebHistory(),    // History 模式（需服务端配置）
  routes: [
    /* ... */
  ]
})
```

#### 导航守卫（Navigation Guards）

Guard 执行顺序是面试高频题。完整链路：

```
1. 导航触发（用户点击 / 代码 push）
2. 在失活的组件里调用 beforeRouteLeave
3. 调用全局 beforeEach
4. 在重用的组件里调用 beforeRouteUpdate
5. 在路由配置里调用 beforeEnter
6. 解析异步路由组件
7. 在被激活的组件里调用 beforeRouteEnter
8. 调用全局 beforeResolve
9. 导航被确认
10. 调用全局 afterEach
11. 触发 DOM 更新
12. 调用 beforeRouteEnter 中传给 next 的回调
```

**全局守卫（router 实例上）**：

```javascript
const router = createRouter({
  /* ... */
})

// 全局前置守卫 —— 最常用：鉴权、权限检查
router.beforeEach((to, from, next) => {
  // Vue Router 4: next 是可选的，推荐 return
  if (to.meta.requiresAuth && !isLoggedIn()) {
    return { name: 'login', query: { redirect: to.fullPath } } // 重定向
    // 或 return false; 取消导航
  }
  // return true 或 undefined 确认导航
})

// 全局解析守卫 —— 在组件内守卫和异步路由组件解析之后调用
router.beforeResolve((to, from) => {
  // 适合：确保数据已获取完成后再确认导航
})

// 全局后置钩子 —— 不能改变导航，常用于页面标题、埋点
router.afterEach((to, from) => {
  document.title = to.meta.title || '默认标题'
  analytics.track('page_view', { page: to.fullPath })
})
```

**路由独享守卫（routes 配置里）**：

```javascript
const routes = [
  {
    path: '/admin',
    component: AdminLayout,
    beforeEnter: (to, from) => {
      // 仅此路由生效，用来做路由级别的权限
      if (!hasRole('admin')) return { name: '403' }
    },
    children: [
      /* ... */
    ]
  }
]
```

**组件内守卫（Options API）**：

```javascript
export default {
  // 进入该组件前（不能访问 this，组件还未创建）
  beforeRouteEnter(to, from, next) {
    next((vm) => {
      /* vm = 组件实例，next 回调中能访问 this */
    })
  },
  // 路由变化、组件被复用时的更新守卫（如 /user/1 → /user/2）
  beforeRouteUpdate(to, from) {
    // this 可用
    this.fetchUser(to.params.id)
  },
  // 离开该组件前 —— 最常用：表单未保存提示
  beforeRouteLeave(to, from) {
    if (this.formDirty) {
      const answer = window.confirm('有未保存的修改，确定离开？')
      if (!answer) return false
    }
  }
}
```

**Composition API 中的组件内守卫（Vue Router 4.x）**：

```javascript
import { onBeforeRouteLeave, onBeforeRouteUpdate } from 'vue-router'

onBeforeRouteLeave((to, from) => {
  if (formDirty.value) {
    const answer = window.confirm('有未保存的修改，确定离开？')
    if (!answer) return false
  }
})

// 注意：没有 onBeforeRouteEnter 的 Composition API 版本
// 因为 setup() 执行时机等同于 beforeRouteEnter
```

#### 动态路由（addRoute / removeRoute）

面试高频场景：根据用户权限动态注册路由。

```javascript
// 基础动态路由
router.addRoute({ path: '/about', component: About })

// 添加嵌套路由 —— 第一个参数是父路由的 name
router.addRoute('admin', { path: 'users', component: AdminUsers })

// 删除路由
router.removeRoute('about') // 按 name 删除

// 典型场景：根据权限动态加载路由
async function loadUserRoutes() {
  const permissions = await fetchUserPermissions() // ['admin', 'editor']
  routes.forEach((route) => {
    if (route.meta?.permission && permissions.includes(route.meta.permission)) {
      router.addRoute(route)
    }
  })
}
```

#### 路由元信息（meta）

```javascript
const routes = [
  {
    path: '/dashboard',
    component: Dashboard,
    meta: {
      requiresAuth: true, // 需要登录
      roles: ['admin'], // 需要的角色
      title: '仪表盘', // 页面标题
      keepAlive: true, // 是否缓存
      transition: 'fade' // 过渡动画
    }
  }
]

// 在全局守卫中使用
router.beforeEach((to, from) => {
  if (to.meta.requiresAuth && !isLoggedIn()) {
    return { name: 'login' }
  }
})
```

#### 路由懒加载与分包

```javascript
const routes = [
  // 基础懒加载：单独 chunk
  { path: '/home', component: () => import('@/views/Home.vue') },

  // 命名 chunk：相同 webpackChunkName 合并到一个 chunk
  { path: '/user', component: () => import(/* webpackChunkName: "user" */ '@/views/User.vue') },
  {
    path: '/profile',
    component: () => import(/* webpackChunkName: "user" */ '@/views/Profile.vue')
  }
]
```

#### Vue Router 4.x vs Vue Router 3.x 差异

| 变化             | Vue Router 3 (Vue 2)                      | Vue Router 4 (Vue 3)                               |
| ---------------- | ----------------------------------------- | -------------------------------------------------- |
| 创建方式         | `new Router({ routes })`                  | `createRouter({ history, routes })`                |
| History 模式     | `mode: 'history'` 字符串                  | `history: createWebHistory()` 函数                 |
| `*` 通配路由     | `path: '*'`                               | `path: '/:pathMatch(.*)*'`（支持命名）             |
| `next`           | 必须调用                                  | **可选**，推荐 `return`                            |
| 组合式 API       | 无                                        | `useRouter` / `useRoute` / `onBeforeRouteLeave` 等 |
| Transition       | 需配 `<transition>`                       | RouterView 内置插槽，推荐 `v-slot` 写法            |
| keep-alive       | `<keep-alive><router-view/></keep-alive>` | 同上，但需在 `<router-view>` 中用 `v-slot`         |
| `router.match` → | `router.match`                            | `router.resolve`                                   |
| scrollBehavior   | 返回位置坐标对象                          | 支持返回 `el` / 延迟 Promise                       |

### 2.16 Vuex vs Pinia 深度对比

::: details 参考

#### 核心设计差异

| 维度           | Vuex 3/4                                       | Pinia                                              |
| -------------- | ---------------------------------------------- | -------------------------------------------------- |
| **设计理念**   | Flux 模式，严格的单向数据流                    | 响应式 + 组合式，更灵活直观                        |
| **mutations**  | **有**（同步修改 state 的唯一方式）            | **无**（直接 `store.xxx = val` 修改）              |
| **模块化**     | 嵌套模块（`modules`），需用 `namespaced: true` | 扁平 Store，每个 store 独立，通过 import 组合      |
| **TypeScript** | 需要额外类型声明                               | 开箱即用，完整类型推导                             |
| **体积**       | ~10KB                                          | ~5KB                                               |
| **DevTools**   | 支持（时间旅行、状态快照）                     | 支持（Pinia 独立标签页）                           |
| **SSR**        | 需手动处理状态泄漏                             | 内置 SSR 支持，`$pinia` 注入                       |
| **代码分割**   | 需动态注册 module                              | 天然按 store 文件分割                              |
| **`this`**     | 不支持                                         | 在 `setup` store 中不可用（但 options store 支持） |

#### API 对比

```javascript
// ━━━━━ Vuex 4 ━━━━━
// store/index.js
import { createStore } from 'vuex'

const store = createStore({
  state: () => ({ count: 0, user: null }),
  getters: {
    doubleCount: (state) => state.count * 2
  },
  mutations: {
    INCREMENT(state, payload = 1) {
      // 必须同步！
      state.count += payload
    },
    SET_USER(state, user) {
      state.user = user
    }
  },
  actions: {
    async fetchUser({ commit }, userId) {
      // 异步在 action
      const user = await api.getUser(userId)
      commit('SET_USER', user)
    },
    incrementAsync({ commit }) {
      setTimeout(() => commit('INCREMENT'), 1000)
    }
  },
  modules: {
    products: {
      namespaced: true, // 必须加，否则 getter/action 全局污染
      state: () => ({ list: [] })
      // ...
    }
  }
})

// 组件中使用
import { useStore } from 'vuex'
const store = useStore()
console.log(store.state.count) // state 访问
console.log(store.getters.doubleCount) // getter 访问
store.commit('INCREMENT', 5) // mutation（同步）
store.dispatch('fetchUser', 1) // action（异步）
store.dispatch('products/fetchList') // 带命名空间的模块

// ━━━━━ Pinia ━━━━━
// stores/counter.js
import { defineStore } from 'pinia'

// Options store（类似 Vuex 风格）
export const useCounterStore = defineStore('counter', {
  state: () => ({ count: 0, user: null }),
  getters: {
    doubleCount: (state) => state.count * 2
  },
  actions: {
    async fetchUser(userId) {
      // action 可以直接是 async
      this.user = await api.getUser(userId) // 直接修改 this，无需 commit
    },
    increment(amount = 1) {
      this.count += amount // 没有 mutation，直接改
    }
  }
})

// Setup store（Composition API 风格 —— 更推荐）
export const useCounterStore = defineStore('counter', () => {
  const count = ref(0)
  const user = ref(null)
  const doubleCount = computed(() => count.value * 2)

  async function fetchUser(userId) {
    user.value = await api.getUser(userId)
  }
  function increment(amount = 1) {
    count.value += amount
  }

  return { count, user, doubleCount, fetchUser, increment }
})

// 组件中使用
import { useCounterStore } from '@/stores/counter'
const counter = useCounterStore()
console.log(counter.count) // 直接访问
console.log(counter.doubleCount) // 直接访问
counter.increment(5) // 直接调用 action
counter.fetchUser(1) // 直接调用 action

// 响应式解构（关键！）
import { storeToRefs } from 'pinia'
const { count, doubleCount } = storeToRefs(counter) // 保持响应性
// 注意：action 方法不要用 storeToRefs 解构
const { fetchUser } = counter // 方法直接解构即可
```

#### 为什么 Pinia 不需要 mutations？

Vuex 的 mutation 机制是为了配合 DevTools 追踪"谁在何时修改了什么"。Pinia 利用了 Vue 3 的响应式系统 + DevTools API，**直接修改也能被追踪到**。每个修改操作都会被记录，开发者可以清晰地看到调用栈。

#### 从 Vuex 迁移到 Pinia 的关键变化

1. **删除 mutations**：所有 `commit()` 改为直接赋值
2. **actions 不再有 `context` 参数**：直接用 `this` 访问 state/getter/其他 action
3. **模块扁平化**：不再需要 `namespaced: true`，每个文件 export 一个 `defineStore`
4. **`dispatch` → 直接调用**：`store.dispatch('xxx')` → `store.xxx()`
5. **无 `rootState` / `rootGetters`**：直接在另一个 store 的 action 中 import 其他 store
6. **`mapState` / `mapGetters` 等辅助函数**：不再需要，直接用 `storeToRefs` 或直接访问

#### 选型建议

| 场景                             | 推荐                                          |
| -------------------------------- | --------------------------------------------- |
| Vue 3 新项目                     | **Pinia**（官方推荐）                         |
| Vue 2 新项目                     | Pinia（支持 `@pinia/vue2-plugin`）            |
| Vue 2 已有大量 Vuex 代码的老项目 | 维持 Vuex，逐步迁移                           |
| 需要严格限制修改入口的大型团队   | Vuex（mutation 强约束）或 Pinia + ESLint 规则 |
| 需要时间旅行调试                 | 两者都支持 DevTools                           |

### 2.17 Composition API 设计哲学与核心 API 深入

::: details 参考

#### 为什么需要 Composition API？

Options API 的问题不是"不能用"，而是"不擅长规模化"。当组件逻辑复杂时：

```vue
<!-- Options API：逻辑按选项类型分散 -->
<script>
export default {
  data() {
    return {
```

```vue
<!-- Composition API：逻辑按功能聚合 -->
<script setup>
// ━━ 搜索逻辑（完整的独立功能块）━━
const keyword = ref('');

const loading = ref(false);

// ━━ 分页逻辑（完整的独立功能块）━━

```

更进一步，**每个功能块可以抽成 composable 函数**：

```javascript
// composables/useSearch.js
export function useSearch() {
  const keyword = ref('');
  const results = ref([]);
  const loading = ref(false);
  async function search() { /* ... */ }
  return { keyword, results, loading, search };
}

// composables/usePagination.js

  const currentPage = ref(1);
  const pageSize = ref(20);
  const hasMore = computed(() => /* */);
  async function loadMore() { /* ... */ }
  return { currentPage, pageSize, hasMore, loadMore };
}

// 组件中使用
const { keyword, results, search } = useSearch();
const { currentPage, hasMore, loadMore } = usePagination();
```

> 核心优势：**一段逻辑的代码写在同一个地方**，而不用在 `data`、`computed`、`methods`、`mounted` 之间横跳。

|            | Mixins（Vue 2）              | Composables（Vue 3）     |

| 类型推导   | 困难                         | 完整 TypeScript 类型推导 |

| 作用域隔离 | 不隔离                       | 每次调用创建独立作用域   |
| 调试       | 难追溯                       | 清晰的调用栈             |

#### 关键 API 深入

**1. `toRef` / `toRefs` —— 解构后保持响应性**

```javascript
const state = reactive({ name: 'Vue', version: 3 })

// 直接解构 → 丢失响应性！
const { name } = state // name 现在是普通字符串 'Vue'

// toRef：单个属性保持响应性连接
const nameRef = toRef(state, 'name')
nameRef.value = 'Vue 3' // 同时更新 state.name

// toRefs：批量转换（常用于 setup() 返回）
const { name, version } = toRefs(state) // 两者都是 ref
```

**2. `unref` —— 统一的"取值"操作**

```javascript
// 等价于 isRef(val) ? val.value : val
function unref(val) {
  return isRef(val) ? val.value : val
}
// 在 composable 中非常实用：参数可能是 ref 也可能是普通值
```

**3. `shallowRef` / `shallowReactive` —— 浅层响应式**

```javascript
// shallowRef: 只有 .value 本身是响应式的，内部属性不是
const state = shallowRef({ count: 0 })
state.value = { count: 1 } // ✅ 触发更新
state.value.count = 1 // ❌ 不触发更新（浅层）

// 使用场景：大型数据对象只做整体替换（如接口返回的大 JSON）
```

**4. `customRef` —— 自定义 ref 行为**

```javascript
// 实现防抖 ref
function useDebouncedRef(value, delay = 200) {
  let timeout
  return customRef((track, trigger) => ({
    get() {
      track() // 收集依赖
      return value
    },
    set(newVal) {
      clearTimeout(timeout)
      timeout = setTimeout(() => {
        value = newVal
        trigger() // 触发更新
      }, delay)
    }
  }))
}

const keyword = useDebouncedRef('', 500)
// 输入框中高频输入时，keyword 只以 500ms 间隔更新
```

**5. `effectScope` —— 管理副作用生命周期**

```javascript
// 场景：composable 中的多个 watch/watchEffect 需要一起清理
const scope = effectScope()

scope.run(() => {
  const doubled = computed(() => count.value * 2)
  watch(doubled, (v) => console.log(v))
  watchEffect(() => {
    /* ... */
  })
})

// 一键清理 composable 中的所有副作用
scope.stop() // 停止所有内部 effect、computed、watch
```

#### Composition API 常见陷阱

| 陷阱                           | 说明                                                              | 解决                           |
| ------------------------------ | ----------------------------------------------------------------- | ------------------------------ |
| `reactive` 解构丢失响应性      | `const { x } = reactive({ x: 1 })` 后 `x` 不再是响应式的          | 使用 `toRefs`                  |
| `reactive` 对象整体替换        | `state = reactive({ a: 1 }); state = reactive({ a: 2 })` 丢失引用 | 用 `ref` 包裹对象              |
| watch 的 `deep: true` 默认行为 | Vue 3 `watch` 的 `deep` 默认 `false`，与 Vue 2 不同               | 显式指定 `deep: true`          |
| `<script setup>` 中的 `await`  | 顶层 `await` 会让组件自动包裹 `<Suspense>`                        | 确保父组件有 `<Suspense>` 支撑 |
| 模板 ref 在 v-for 中           | `ref` 拿到的是数组，但顺序不保证和 v-for 一致                     | 用函数 ref 绑定                |

### 2.18 Vue SSR 服务端渲染原理与 Nuxt

::: details 参考

#### SSR 解决了什么问题？

SPA 的两大痛点：

1. **首屏白屏时间长**：浏览器下载 JS → 执行 JS → 渲染页面，用户看到内容前要等好几秒
2. **SEO 不友好**：搜索引擎爬虫不执行 JS，看到的只是空 `<div id="app"></div>`

SSR 的核心思路：**在服务端把 Vue 组件渲染成 HTML 字符串**，直接返回给浏览器。

```
SPA 流程:
  浏览器请求 → 返回空 HTML + JS → 浏览器执行 JS → 渲染页面

SSR 流程:
  浏览器请求 → 服务端执行 Vue 组件 → 返回完整 HTML → 浏览器直接渲染
                                     → 同时下载 JS → Hydration（激活交互）
```

#### Vue SSR 核心实现

```javascript
// server.js —— 最小化 Vue SSR 实现
import { createSSRApp } from 'vue'
import { renderToString } from 'vue/server-renderer'
import express from 'express'

const app = express()

app.get('*', async (req, res) => {
  // 1. 每个请求创建独立的 Vue 应用实例（避免状态污染！）
  const vueApp = createSSRApp({
    template: `<div id="app"><h1>{{ title }}</h1></div>`,
    data: () => ({ title: 'Hello SSR' })
  })

  // 2. 渲染为 HTML 字符串
  const html = await renderToString(vueApp)

  // 3. 注入到完整 HTML 模板中
  res.send(`
    <!DOCTYPE html>
    <html>
      <head><title>SSR Demo</title></head>
      <body>
        <div id="app">${html}</div>
        <script src="/client-entry.js"></script>
      </body>
    </html>
  `)
})

app.listen(3000)
```

**为什么每个请求要创建新实例？**
Node.js 服务是单进程长跑的。如果所有请求共享同一个 Vue 实例，A 用户的状态会污染 B 用户的页面。**每个请求 `createSSRApp()` 一次，保证了状态隔离。**

#### 同构（Isomorphic）与 Hydration

SSR 并不是"HTML 完全替代 JS"，而是"HTML 先到，JS 再激活"：

```
1. 服务端：renderToString() → 生成完整 HTML → 发送给浏览器
2. 浏览器：展示 HTML（此时页面可见，但按钮点击等交互不生效）
3. 浏览器：下载并执行 client-entry.js
4. Hydration（水合）：Vue 接管静态 HTML，将 DOM 与响应式系统绑定
   - 不是重新渲染！而是给已有的 DOM 节点"注入灵魂"
   - 对比服务端渲染的 VNode 和客户端渲染的 VNode，确保一致
```

**Hydration 失败的常见原因：**

- 服务端和客户端的渲染结果不一致（如用 `Math.random()` 或 `new Date()` 未做处理）
- 浏览器扩展修改了 DOM
- 此时 Vue 会丢弃现有 DOM 强制重渲染，控制台会有 `Hydration mismatch` 警告

#### Async Data（服务端数据预取）

SSR 中页面数据需要在**服务端渲染前**获取好：

```javascript
// 组件中定义 asyncData 或 serverPrefetch
// 服务端执行时机：renderToString 之前
// 客户端执行时机：路由跳转时

// Vue Router + 自定义钩子
const UserPage = {
  async beforeRouteEnter(to) {
    /* ... */
  }
}

// 或在 setup 中使用 onServerPrefetch（Vue 3-only）
import { onServerPrefetch } from 'vue'

onServerPrefetch(async () => {
  // 仅在服务端执行
  const data = await fetchUser()
  user.value = data
})
```

#### SSR 的代价（面试高分点：知道 SSR 不仅是"好"）

| 代价              | 说明                                                             |
| ----------------- | ---------------------------------------------------------------- |
| **服务器压力**    | 每次请求都需要渲染一次 Vue 应用，CPU 密集                        |
| **开发复杂度**    | 需要区分服务端/客户端代码（`window`、`document` 只在客户端存在） |
| **构建复杂**      | 需要两套构建：Server Bundle + Client Bundle                      |
| **TTFB 可能变长** | 如果服务端渲染慢（复杂计算/依赖多），首字节时间反而不如 SPA      |
| **第三方库兼容**  | 依赖浏览器 API 的库在服务端不能用，需特殊处理                    |
| **缓存策略**      | 需要考虑分级缓存（页面级/组件级/数据级），否则性能很差           |
| **流式渲染**      | Vue 3 支持 `renderToStream`，但需要 Node.js Stream + HTTP/2 支持 |

#### SSR vs SSG vs SPA 选型

|          | SSR（Nuxt 服务端模式） | SSG（Nuxt generate） | SPA                      |
| -------- | ---------------------- | -------------------- | ------------------------ |
| 渲染时机 | 请求时服务端渲染       | **构建时**生成 HTML  | 客户端渲染               |
| 内容更新 | 实时（每次请求渲染）   | 需重新构建           | 实时（API 数据）         |
| SEO      | 优秀                   | 优秀                 | 差                       |
| 首屏速度 | 快（需等服务器处理）   | 最快（纯 HTML）      | 慢                       |
| 服务器   | 需要 Node.js 服务器    | 不需要               | 不需要（静态服务器即可） |
| 适用场景 | 内容动态变化、强 SEO   | 博客/文档/营销站     | 后台管理/SaaS            |

#### Nuxt 3 核心能力

```javascript
// nuxt.config.ts —— 一行配置切换 SSR/SSG/SPA
export default defineNuxtConfig({
  ssr: true // 默认 true（SSR 模式）
  // ssr: false,  // SPA 模式
  // 执行 nuxi generate 即为 SSG 模式
})
```

Nuxt 3 关键特性：

- **自动导入**：`ref`/`computed`/`useFetch` 等无需手动 import
- **文件路由**：`pages/` 目录下文件自动生成路由
- **`useFetch` / `useAsyncData`**：内置 SSR 数据获取，自动处理双端数据同步和水合
- **Nitro Server**：跨平台服务端引擎，可部署到 Node.js/Serverless/Cloudflare Workers 等
- **混合渲染**：不同路由可选择不同渲染模式（SSR/SSG/SPA/ISR）
- **`<ClientOnly>`**：包裹仅在客户端渲染的组件

```vue
<template>
  <!-- 浏览器 API 相关组件（如视频播放器）包裹在 ClientOnly 中 -->
  <ClientOnly>
    <VideoPlayer :src="videoUrl" />
    <template #fallback>
      <VideoSkeleton />
      <!-- SSR 阶段展示的占位 -->
    </template>
  </ClientOnly>
</template>

<script setup>
// Nuxt 内置 SSR 数据获取 —— 服务端执行后状态会序列化给客户端
const { data: posts } = await useFetch('/api/posts')
</script>
```

```vue
<div :[attrName]="value"></div>
<!-- attrName = 'title' → :title="value" -->

<!-- 3. class 绑定 -->
<div :class="{ active: isActive, 'has-error': error }"></div>
<!-- 对象 -->

<!-- 数组 -->
```

#### v-if vs v-show 区别

|                   | v-if                                       | v-show                       |
| ----------------- | ------------------------------------------ | ---------------------------- |
| 机制              | 条件假时**删除 DOM 节点**                  | 条件假时添加 `display: none` |
| 切换开销          | **高**（销毁/重建 DOM + 重新执行生命周期） | **低**（只改 CSS）           |
| 初始渲染          | 条件假时**不渲染**                         | 无论条件，**始终渲染**       |
| 适用场景          | 条件很少改变（Tab 切换）                   | 频繁切换（展开/折叠）        |
| 生命周期          | 每次切换触发 created/mounted/unmounted     | 不触发                       |
| 配合 `<template>` | ✅（多元素条件包裹）                       | ❌（template 不渲染成 DOM）  |

#### v-for 深入

```vue

</li>

<!-- 遍历对象 -->

  {{ key }}: {{ value }}
</li>

<!-- 遍历数字 -->
<span v-for="n in 10" :key="n">{{ n }}</span>

<!-- 与 v-if 一起用（Vue 3）→ v-if 优先级高于 v-for -->
<!-- ❌ 同时使用时 v-if 拿不到 v-for 的变量 -->
<!-- ✅ 正确：把 v-if 放到 template 上 -->
<template v-for="item in items" :key="item.id">
  <li v-if="item.active">{{ item.name }}</li>
</template>
<!-- 或：用 computed 提前过滤 -->
```

### 2.20 插槽详解：默认插槽、具名插槽、作用域插槽

::: details 参考

#### 插槽是什么？

插槽是组件内容的分发机制——父组件向子组件的"占位区域"传递模板内容。类比：组件是一个"相框"，插槽就是可以替换的"照片"。

#### 默认插槽

```vue
<!-- 子组件 Layout.vue -->
<template>
  <div class="layout">
    <header>Header</header>
    <main>
      <slot />
      <!-- 默认插槽，父组件传入的内容渲染在这里 -->
    </main>
    <footer>Footer</footer>
  </div>
</template>

<!-- 父组件 -->
<Layout>
  <p>这是页面主要内容</p>  <!-- 渲染到 <slot /> 位置 -->
</Layout>
```

**插槽默认内容**：

```vue
<!-- 子组件 -->
<slot>这是默认内容，父组件没传时显示</slot>
```

#### 具名插槽

一个组件可以有多个插槽，通过 `name` 区分：

```vue
<!-- 子组件 Card.vue -->
<template>
  <div class="card">
    <div class="card-header">
      <slot name="header">默认标题</slot>
    </div>
    <div class="card-body">
      <slot />
      <!-- name="default"，默认插槽 -->
    </div>
    <div class="card-footer">
      <slot name="footer" />
    </div>
  </div>
</template>

<!-- 父组件 -->
<Card>
  <template #header>
    <h2>自定义标题</h2>
  </template>

  <!-- 没有指定名称 → 默认插槽 -->
  <p>卡片正文内容</p>

  <template #footer>
    <button>确定</button>
    <button>取消</button>
  </template>
</Card>
```

> `v-slot:header` 简写为 `#header`。`v-slot` 只能用在 `<template>` 或组件上。

#### 作用域插槽（Scoped Slots）

子组件把数据传给父组件的插槽内容：

```vue
<!-- 子组件 TodoList.vue -->
<template>
  <ul>
    <li v-for="todo in todos" :key="todo.id">
      <!-- 将 todo 和 index 暴露给父组件 -->
      <slot name="item" :todo="todo" :index="index">
        {{ todo.text }}
        <!-- 默认渲染 -->
      </slot>
    </li>
  </ul>
</template>

<script setup>
defineProps({ todos: Array })
</script>

<!-- 父组件 —— 自定义每一项如何渲染 -->
<TodoList :todos="todos">
  <template #item="{ todo, index }">
    <!-- { todo, index } 是解构 slot props -->
    <span :class="{ done: todo.done }">
      <input type="checkbox" :checked="todo.done" />
      {{ index + 1 }}. {{ todo.text }}
    </span>
  </template>
</TodoList>
```

作用域插槽的典型场景：

- **列表渲染自定义**：渲染表格行、Todo 列表项（让父决定 UI）
- **组件逻辑复用**：封装数据获取/处理逻辑，渲染交给使用者
- **高级组件库**：el-table 的 `#default="{ row }"`、v-data-table 的 slot

#### Vue 2 vs Vue 3 插槽区别

|                     | Vue 2                             | Vue 3                                                |
| ------------------- | --------------------------------- | ---------------------------------------------------- |
| 具名插槽            | `slot="name"`（已废弃）           | `v-slot:name` 或 `#name`                             |
| 作用域插槽          | `slot-scope="{ item }"`（已废弃） | `v-slot:default="{ item }"` 或 `#default="{ item }"` |
| `this.$slots`       | 内容已解析为 VNode 数组           | 内容已解析为 VNode 数组（一致性）                    |
| `this.$scopedSlots` | 存在                              | **合并到 `this.$slots`**，所有 slot 都是函数         |
| 动态插槽名          | 不支持                            | 支持：`#[dynamicSlotName]`                           |

```vue
<!-- Vue 3 动态插槽名 -->
<template #[slotName]="{ item }">
  {{ item.name }}
</template>
```

### 2.21 keep-alive 与动态组件

::: details 参考

#### 动态组件 `<component :is>`

同一个挂载点，根据条件切换不同的组件：

```vue
<template>
  <button @click="currentTab = 'Home'" :class="{ active: currentTab === 'Home' }">首页</button>
  <button @click="currentTab = 'Profile'" :class="{ active: currentTab === 'Profile' }">
    个人
  </button>

  <!-- 切换组件时，离开的组件会被销毁 -->
  <component :is="currentTab" />
</template>

<script setup>
import Home from './Home.vue'
import Profile from './Profile.vue'
const currentTab = ref('Home')
</script>
```

#### keep-alive —— 缓存组件实例

默认情况下，`<component :is>` 切换离开的组件会被**销毁**（数据/状态/滚动位置全部丢失）。`<keep-alive>` 解决这个问题：

```vue
<keep-alive>
  <component :is="currentTab" />
</keep-alive>
```

**核心属性：**

| 属性      | 说明                            | 示例                             |
| --------- | ------------------------------- | -------------------------------- |
| `include` | 只缓存匹配的组件（按组件 name） | `:include="['Home', 'Profile']"` |
| `exclude` | 排除不缓存的组件                | `:exclude="['Settings']"`        |
| `max`     | 最大缓存实例数（LRU 策略）      | `:max="10"`                      |

```vue
<keep-alive :include="cachedViews" :max="10">
  <router-view />
</keep-alive>
```

#### keep-alive 生命周期

被 `<keep-alive>` 包裹的组件会多两个生命周期：

```vue
<script setup>
import { onActivated, onDeactivated } from 'vue'

onActivated(() => {
  // 组件被激活（从缓存中取出显示）
  // 适用：刷新数据、恢复滚动位置
})

onDeactivated(() => {
  // 组件被停用（被缓存起来）
  // 适用：清理临时状态（如定时器）
})
</script>
```

完整流程：

```
首次进入 → setup() → onBeforeMount → onMounted → onActivated
离开     → onDeactivated（组件被缓存）
再进入   → onActivated（从缓存恢复，不会重新创建）
缓存被淘汰 → onBeforeUnmount → onUnmounted
```

#### keep-alive 原理

`<keep-alive>` 内部是一个抽象组件（不渲染 DOM），维护一个 `cache` 对象和一个 `keys` 数组：

- 组件第一次挂载：缓存 VNode 实例到 `cache`
- 组件切换离开：调用 `$deactivate`，保留 DOM 但移除显示
- 组件再次进入：从 `cache` 中取出实例重新激活，不重新创建
- 超过 `max`：按 LRU 策略淘汰最久未使用的缓存

#### 实际应用场景

| 场景                   | 为什么需要 keep-alive           |
| ---------------------- | ------------------------------- |
| Tab 切换               | 保留各 Tab 的填写内容、滚动位置 |
| 列表 → 详情 → 返回列表 | 保留列表的筛选条件、滚动位置    |
| 多步骤表单             | 上一步数据不丢失                |
| 后台多页签             | 模拟浏览器多页签体验            |

#### 注意事项

1. **组件必须有 `name` 选项**，`include`/`exclude` 通过 name 匹配
2. **Vue 3 中 `<script setup>` 组件的 name 默认是文件名**，或通过 `defineOptions({ name: 'xxx' })` 显式指定
3. **被缓存的组件 `onUnmounted` 不会调用**（组件没有被销毁），清理工作要在 `onDeactivated` 中做
4. **缓存组件的 `onMounted` 只执行一次**，后续激活走 `onActivated`

### 2.22 自定义指令

::: details 参考

#### 什么时候用自定义指令？

当需要对**普通 DOM 元素进行底层操作**时。如果一个功能可以通过组件实现，优先用组件。

**适合场景**：focus 管理、权限控制、滚动行为、粘性定位、点击外部关闭、防抖输入、图片懒加载、拖拽。

**不适合场景**：可以通过组件 + props + events 实现的功能（因为有模板/样式/组合能力）。

#### 自定义指令基础

```javascript
// 全局注册
app.directive('focus', {
  mounted(el) {
    el.focus()
  }
})

// 局部注册
export default {
  directives: {
    focus: {
      mounted(el) {
        el.focus()
      }
    }
  }
}

// 使用
;<input v-focus />
```

#### 指令钩子（Vue 3）

| 钩子            | 调用时机                       | 对应 Vue 2（旧）              |
| --------------- | ------------------------------ | ----------------------------- | ----------------- |
| `created`       | 元素属性/事件监听器被应用前    | —（新增）                     |
| `mounted`       | 元素插入父节点后               | `bind` →                      | `inserted` 的部分 |
| `beforeUpdate`  | 组件 VNode 更新前              | —（新增）                     |
| `updated`       | 组件 VNode 及其子 VNode 更新后 | `update` + `componentUpdated` |
| `beforeUnmount` | 元素被卸载前                   | —（新增）                     |
| `unmounted`     | 元素被卸载后（指令与元素解绑） | `unbind`                      |

每个钩子都接收相同的 4 个参数：

- `el`：指令绑定的 DOM 元素
- `binding`：`{ value, oldValue, arg, modifiers, instance, dir }`
- `vnode`：绑定元素的 VNode
- `prevVnode`：上一个 VNode（仅 update 相关钩子）

#### 实战示例

**1. 点击外部关闭（Click Outside）**

```javascript
app.directive('click-outside', {
  mounted(el, binding) {
    el.__clickOutsideHandler = (event) => {
      if (!(el === event.target || el.contains(event.target))) {
        binding.value(event) // 调用传入的函数
      }
    }
    document.addEventListener('click', el.__clickOutsideHandler)
  },
  unmounted(el) {
    document.removeEventListener('click', el.__clickOutsideHandler)
  }
})

// 使用
;<div v-click-outside="closeDropdown">下拉内容</div>
```

**2. 权限控制（v-permission）**

```javascript
app.directive('permission', {
  mounted(el, binding) {
    const { value } = binding // 需要的权限，如 'admin'
    const permissions = store.state.user.permissions // 用户权限列表
    if (!permissions.includes(value)) {
      el.parentNode?.removeChild(el) // 没有权限则移除元素
    }
  }
})

// 使用
;<button v-permission="'delete'">删除</button>
```

**3. 图片懒加载（Intersection Observer）**

```javascript
app.directive('lazy', {
  mounted(el, binding) {
    const observer = new IntersectionObserver(([entry]) => {
      if (entry.isIntersecting) {
        el.src = binding.value // 进入视口才加载
        observer.unobserve(el)
      }
    })
    observer.observe(el)
    el.__lazyObserver = observer
  },
  unmounted(el) {
    el.__lazyObserver?.unobserve(el)
  }
})

// 使用
;<img v-lazy="imageUrl" />
```

**4. 防抖（Debounce）**

```javascript
app.directive('debounce', {
  mounted(el, binding) {
    let timer;
    el.addEventListener('input', (e) => {
      clearTimeout(timer);
      timer = setTimeout(() => {
        binding.value(e.target.value);
      }, binding.arg || 300); // v-debounce:500="handler"
    });
  },
});

// 使用
<input v-debounce:500="handleSearch" />
```

#### Vue 2 vs Vue 3 指令钩子对照

| Vue 2              | Vue 3       | 说明             |
| ------------------ | ----------- | ---------------- |
| `bind`             | `created`   | 元素初始化时     |
| `inserted`         | `mounted`   | 元素插入父节点后 |
| `update`           | —           | **已移除**       |
| `componentUpdated` | `updated`   | VNode 全部更新后 |
| `unbind`           | `unmounted` | 指令与元素解绑   |

> Vue 3 指令钩子命名对齐组件生命周期，更直观好记。

### 2.23 Transition 过渡与动画

::: details 参考

#### `<Transition>` 基础

Vue 会在元素插入/移除时**自动**添加和移除 CSS class：

```vue
<template>
  <button @click="show = !show">Toggle</button>
  <Transition name="fade">
    <p v-if="show">hello</p>
  </Transition>
</template>

<style>
/* 6 个过渡 class */
.fade-enter-from {
  opacity: 0;
} /* 进入前 */
.fade-enter-active {
  transition: opacity 0.5s;
} /* 进入过程中 */
.fade-enter-to {
  opacity: 1;
} /* 进入后 */

.fade-leave-from {
  opacity: 1;
} /* 离开前 */
.fade-leave-active {
  transition: opacity 0.5s;
} /* 离开过程中 */
.fade-leave-to {
  opacity: 0;
} /* 离开后 */
</style>
```

**过渡 class 时间轴：**

```
进入阶段：
  enter-from(立即) → enter-active(过渡中) → enter-to(过渡结束移除)

离开阶段：
  leave-from(立即) → leave-active(过渡中) → leave-to(过渡结束移除)
```

#### Vue 3 class 命名变化

| Vue 2            | Vue 3                    |
| ---------------- | ------------------------ |
| `v-enter`        | **`v-enter-from`**       |
| `v-leave`        | **`v-leave-from`**       |
| `v-enter-active` | `v-enter-active`（不变） |
| `v-leave-active` | `v-leave-active`（不变） |
| `v-enter-to`     | `v-enter-to`（不变）     |
| `v-leave-to`     | `v-leave-to`（不变）     |

#### 配合 Animate.css 等第三方动画库

```vue
<Transition
  name="custom"
  enter-active-class="animate__animated animate__bounceIn"
  leave-active-class="animate__animated animate__bounceOut"
>
  <p v-if="show">动画！</p>
</Transition>
```

#### JS 钩子

```vue
<Transition
  @before-enter="onBeforeEnter"
  @enter="onEnter"
  @after-enter="onAfterEnter"
  @enter-cancelled="onEnterCancelled"
  @before-leave="onBeforeLeave"
  @leave="onLeave"
  @after-leave="onAfterLeave"
  @leave-cancelled="onLeaveCancelled"
>
  <p v-if="show">内容</p>
</Transition>

<script setup>
function onEnter(el, done) {
  // 用 GSAP / Velocity 等 JS 动画库
  gsap.from(el, { opacity: 0, duration: 0.5, onComplete: done })
  // 必须调用 done() 告诉 Vue 动画结束
}
</script>
```

> `:css="false"` 告诉 Vue 跳过 CSS 检测，完全走 JS 钩子。

#### `<TransitionGroup>` —— 列表动画

用于 `v-for` 列表的添加/移除/移动动画：

```vue
<TransitionGroup name="list" tag="ul">
  <li v-for="item in items" :key="item.id">
    {{ item.text }}
    <button @click="remove(item.id)">×</button>
  </li>
</TransitionGroup>

<style>
.list-enter-active {
  transition: all 0.5s ease;
}
.list-leave-active {
  transition: all 0.5s ease;
}
.list-enter-from {
  opacity: 0;
  transform: translateX(30px);
}
.list-leave-to {
  opacity: 0;
  transform: translateX(-30px);
}
.list-leave-active {
  position: absolute;
} /* 离开元素脱离文档流，其他元素平滑上移 */

/* 移动动画（FLIP 技术）—— 非常关键！ */
.list-move {
  transition: transform 0.5s ease;
}
</style>
```

`<TransitionGroup>` vs `<Transition>`：

- 渲染一个**真实的 DOM 元素**（默认 `<span>`，通过 `tag` 指定）
- 每个子元素**必须有唯一的 key**
- 支持 `.v-move` class（元素位置变化时的 FLIP 动画）
- 离开动画期间，元素仍会保留在 DOM 中

#### 过渡模式（mode）

```vue
<!-- 先离开再进入（推荐，避免布局跳动） -->
<Transition mode="out-in">
  <component :is="currentView" />
</Transition>

<!-- 先进入再离开 -->
<Transition mode="in-out">
  <component :is="currentView" />
</Transition>
```

#### 出现在初始渲染（appear）

```vue
<Transition appear>
  <p>页面加载时就有动画！</p>
</Transition>
<!-- 或自定义 appear class -->
<Transition appear appear-active-class="animate__animated animate__fadeIn">
  <p>初始动画</p>
</Transition>
```

#### 常见过渡场景总结

| 场景       | 方案                                                                                                      |
| ---------- | --------------------------------------------------------------------------------------------------------- |
| 单元素显隐 | `<Transition>` + `v-if` / `v-show`                                                                        |
| 组件切换   | `<Transition mode="out-in">` + `<component :is>`                                                          |
| 路由切换   | `<router-view v-slot="{ Component }"><Transition><component :is="Component"/></Transition></router-view>` |
| 列表增删移 | `<TransitionGroup>`                                                                                       |
| 复杂动画   | JS 钩子 + GSAP / Anime.js                                                                                 |
| 第三方动画 | `enter-active-class` + Animate.css                                                                        |

## 3 React

### 3.1 React和vue 选型和优缺点、核心架构的区别

::: details 参考

| 维度       | React                                            | Vue                                         |
| ---------- | ------------------------------------------------ | ------------------------------------------- |
| 架构理念   | UI = f(state)，函数式编程思想，视图是状态的映射  | MVVM，响应式 + 模板，声明式渲染             |
| 响应式机制 | 手动 `setState` 触发更新，依赖主动通知           | 自动追踪依赖，数据变化自动更新              |
| 模板       | JSX（JavaScript 表达式能力）                     | `<template>`（HTML-based），也支持 JSX      |
| 组件       | 函数组件 + Hooks（主流）                         | Options API / Composition API               |
| 数据流     | 单向数据流，props 向下，子组件通过回调通知父组件 | 单向数据流，但 `v-model` 语法糖实现双向绑定 |
| 状态管理   | 官方无内置方案，社区 Redux/Zustand/Jotai         | Vuex / Pinia（官方维护）                    |
| 跨组件通信 | Context / 状态管理库                             | provide/inject / 状态管理库 / 事件总线      |
| 更新粒度   | 组件级（需手动优化）                             | 组件级（自动依赖追踪，更精确）              |
| TypeScript | 天然友好（JSX 易于类型化）                       | Vue 3 大幅改进                              |
| 学习曲线   | 陡峭（需要理解 Hooks 规则、闭包陷阱等）          | 平缓（模板语法直观）                        |
| 生态       | 巨大，社区驱动，选择多但有碎片化                 | 中等，官方维护核心库，统一性好              |

#### 选型建议

**React 更适合**：

- 大型复杂项目，需要精细控制渲染逻辑
- 团队有较强的 JS 功底，能驾驭 Hooks 和函数式范式
- React Native 统一移动端
- 需要大量第三方库和社区方案（如复杂富文本编辑器）

**Vue 更适合**：

- 中小型项目，追求快速开发
- 渐进式迁移老项目（直接引入 `<script>` 就能用）
- 团队前端技术水平不一，模板语法更容易上手
- 需要官方统一方案减少决策成本

#### 核心架构区别：运行时 vs 编译时

- Vue 在**编译时**做了大量优化（静态标记、PatchFlag、静态提升），运行时 diff 跳过静态内容。
- React 主要在**运行时**做优化（Fiber 中断恢复、并发特性），编译端相对简单，通过 `React.memo`、`useMemo` 等 API 手动优化渲染。

> 两者没有绝对优劣，区别在于编程范式的选择——函数式（React）vs 响应式（Vue）。

### 3.2 React中setState的执行机制，如何有效的管理状态

::: details 参考

#### setState 执行机制

**异步 / 批量更新**：React 将多次 `setState` 合并为一次更新，在事件处理函数中表现为"异步"。

```javascript
// 事件处理中：批量更新
handleClick = () => {
  this.setState({ count: this.state.count + 1 })
  this.setState({ count: this.state.count + 1 })
  console.log(this.state.count) // 仍然是旧值
  // 两次 setState 合并，最终 count 只 +1
}

// 函数式更新：解决依赖旧值问题
handleClick = () => {
  this.setState((prev) => ({ count: prev.count + 1 }))
  this.setState((prev) => ({ count: prev.count + 1 }))
  // 最终 count +2，每次基于最新值
}
```

**合成事件 vs 原生事件 vs 异步代码**：

| 场景                          | 行为                                 |
| ----------------------------- | ------------------------------------ |
| React 事件处理 (`onClick`)    | 批量更新（异步）                     |
| `setTimeout` / `Promise`      | React 17 同步更新，React 18 批量更新 |
| 原生事件 (`addEventListener`) | React 17 同步更新，React 18 不批量   |
| `useEffect` / 生命周期        | 批量更新                             |

React 18 引入**自动批处理（Automatic Batching）**，所有上下文中的 setState 都自动批处理。

#### Hooks 状态管理

```javascript
// useState：简单状态
const [count, setCount] = useState(0);
setCount(prev => prev + 1); // 函数式更新

// useReducer：复杂状态逻辑
const [state, dispatch] = useReducer(reducer, initialState);

// useRef：不需要触发渲染的值
const timerRef = useRef(null);
timerRef.current = setInterval(...);

// useMemo / useCallback：缓存值和函数，避免不必要的子组件渲染
const sorted = useMemo(() => arr.sort(), [arr]);
const handleClick = useCallback(() => { ... }, [deps]);
```

#### 有效管理状态的原则

1. **状态提升**：多组件共享的状态放到最近的公共父组件
2. **状态下沉**：只属于某个组件的状态不要放到全局
3. **区分 UI 状态和服务端状态**：服务端数据（缓存、loading、error）用 React Query / SWR 管理，不要手动用 useState
4. **不可变更新**：永远创建新对象/数组而不是修改原值
5. **Context 粒度**：频繁变化和稳定的 Context 分开，避免大范围重新渲染

:::

### 3.3 React的事件底层实现机制

::: details 参考

#### 合成事件（SyntheticEvent）

React 不直接把事件绑定在 DOM 上，而是使用**事件委托**策略，将所有事件绑定到根容器上（React 17 是 `document`，React 18 是 `root` 节点），通过事件冒泡统一处理。

```javascript
// SyntheticEvent 是对原生事件的包装
function handleClick(e) {
  console.log(e.nativeEvent) // 原生事件对象
  console.log(e.type) // 'click'
  e.stopPropagation() // 阻止合成事件冒泡
  e.nativeEvent.stopImmediatePropagation() // 阻止原生事件冒泡
  e.persist() // React 17 前保留事件引用
}
```

#### 为什么需要合成事件？

1. **跨浏览器兼容**：统一不同浏览器的事件行为，抹平差异
2. **事件池（Event Pooling，React 16）**：复用事件对象减少 GC，React 17 已移除
3. **批量更新**：在事件处理完成后，统一执行一次批量更新
4. **优先级调度**（React 18）：结合 Fiber 架构，对不同事件分配优先级

#### 事件绑定流程

```
jsx: <button onClick={handleClick}>

→ 编译为: createElement('button', { onClick: handleClick })

→ React 在 render 阶段将 onClick 注册到 root 节点的 __reactEvents 中
  (存储为: 'click' → { capture: [listeners], bubble: [listeners] })

→ 用户点击 → 原生事件冒泡到 root
  → React 找到对应的合成事件监听器
  → 模拟事件捕获/冒泡阶段
  → 批量调用监听器
  → 执行 setState 合并批量更新
```

#### 事件优先级（React 18）

| 事件类型                            | 优先级             |
| ----------------------------------- | ------------------ |
| 离散事件（click、keydown、focus）   | 同步车道，立即处理 |
| 连续事件（scroll、mousemove、drag） | 默认车道           |
| 异步事件（setTimeout、fetch）       | 普通车道           |

#### 注意事项

- React 事件命名用驼峰：`onClick`、`onChange`
- `e.stopPropagation()` 阻止的是 React 合成事件的冒泡，不是原生事件
- 在 React 事件中调用 `e.preventDefault()` 就可以阻止默认行为，不需要 `return false`
- React 17+ 的 `onChange` 对 `<input>` 和原生 `onInput` 行为一致（实时触发）

### 3.4 React的虚拟DOM和Diff算法的内部实现

::: details 参考

#### 虚拟 DOM

虚拟 DOM 就是用 JS 对象描述真实 DOM 结构的轻量表示。每个 React 元素都对应一个 Fiber 节点（React 16+），包含 `type`、`props`、`key`、`ref` 等信息。

```javascript
// JSX
<div id="container">
  <span>hello</span>
</div>

// 对应的虚拟 DOM（简化）
{
  type: 'div',
  props: { id: 'container', children: [
    { type: 'span', props: { children: 'hello' } }
  ]}
}
```

#### Diff 算法三条核心策略

1. **同层比较**：只比较同一层级的节点，不跨层级。不同层级认为是新增/删除。
2. **类型不同则直接替换**：`<div>` → `<span>`，直接销毁旧节点（含子节点），创建新节点。
3. **key 标识可复用节点**：同一层级子节点通过 `key` 判断是否可复用。

#### 单节点 Diff（reconcileSingleElement）

```
新节点 type 和 key 与旧节点都相同 → 复用 DOM，只更新 props
type 不同 → 删除旧节点，创建新节点（同级旧节点标记删除）
```

#### 多节点 Diff（reconcileChildrenArray）

React 对同层子节点（数组）进行两轮遍历：

**第一轮：逐个比较**

- 依次比较 `newChildren[i]` 和 `oldFiber[i]`（同级同位置）
- `key` 相同且 `type` 相同 → 复用，继续下一对
- `key` 相同但 `type` 不同 → 删除旧节点，跳出第一轮
- `key` 不同 → 跳出第一轮

**第二轮：根据剩余节点处理**

- 新节点遍历完了，旧节点还有 → 删除剩余旧节点
- 旧节点遍历完了，新节点还有 → 新增剩余新节点
- 两者都有剩余 → 将剩余旧节点按 `key` 放入 Map → 遍历剩余新节点到 Map 中查找：
  - 找到且 type 相同 → 复用，移动位置
  - 找到但 type 不同 → 删除旧的，创建新的
  - 找不到 → 创建新的
    → 最后删除 Map 中未被复用的旧节点

#### 为什么 key 不能用 index？

当列表重新排序或插入/删除时，用 index 做 key 会导致：原本复用的节点被错误复用、节点意外重建、不必要的 DOM 操作和状态丢失。

:::

### 3.5 React的Fiber工作原理，解决了什么问题

::: details 参考

#### 解决了什么问题？

React 15 的 Stack Reconciler 是同步递归——一旦开始渲染，会一直执行直到完成，无法中断。当组件树很深时，JS 长时间占用主线程，导致浏览器无法响应用户输入，出现**掉帧/卡顿**。

#### Fiber 是什么？

Fiber 是一个**工作单元**的数据结构，也是一棵可中断的链表树。每个 React 元素都对应一个 Fiber 节点：

```javascript
// Fiber 节点核心字段
{
  type: 'div',         // 组件类型
  key: null,
  stateNode: domNode,  // 对应的真实 DOM

  // 链表结构（核心！）
  child: fiberA,       // 第一个子节点
  sibling: fiberB,     // 下一个兄弟节点
  return: parentFiber, // 父节点

  // 副作用
  effectTag: 'Update', // Placement | Update | Deletion
  nextEffect: fiber,   // 副作用链表

  // 调度
  lanes: 0,            // 优先级
  alternate: fiber,    // 双缓存：指向另一棵树（current ↔ workInProgress）
}
```

链表结构使遍历可以**暂停**和**恢复**——从任何节点中断，记录下来，之后继续。

#### 双缓存机制

```
current Tree (当前屏幕上显示的)  ←→  workInProgress Tree (正在内存中构建的)

每次更新：
1. 基于 current 克隆一棵 workInProgress 树
2. 在 workInProgress 上做 diff 和副作用标记
3. 完成后一键切换：workInProgress → current
```

#### 工作循环（Work Loop）

```
function workLoopSync / workLoopConcurrent() {
  while (workInProgress !== null) {
    performUnitOfWork(workInProgress);
  }
}
```

每个单元工作的执行过程（深度优先）：

```
beginWork(fiber):       进入节点，diff 子节点
  → 返回第一个 child
  → 没有 child 则 completeWork(fiber)
  → completeWork 创建/更新 DOM，收集副作用到 effectList
  → 有 sibling → beginWork(sibling)
  → 没有 sibling → 回到 parent completeWork

每个 unit 执行完后，检查是否还有剩余时间（shouldYield）
  → 有剩余时间 → 继续下一个 unit
  → 时间用尽 → 暂停，让浏览器渲染
  → 下次空闲时继续
```

#### React 18 并发特性

- **useTransition / useDeferredValue**：标记非紧急更新，可以被更高优先级的更新打断
- **Suspense**：配合并发渲染优雅处理异步数据加载
- **自动批处理**：所有 setState 自动合并

#### 总结

Fiber 的核心思想：**将渲染工作拆分成细粒度的工作单元，利用空闲时间分段执行**，让 React 在渲染大型应用时仍然保持页面响应。

:::

### 3.6 React Router和Vue Router的底层实现原理、动态加载实现原理

::: details 参考

#### 共通核心原理

两个 Router 底层都依赖两大机制：

**1. Hash 模式（`#/path`）**

```javascript
window.addEventListener('hashchange', () => {
  const path = window.location.hash.slice(1)
  renderRoute(path)
})
```

- `#` 后面的变化不触发页面刷新（页面不会重新请求）
- 兼容性好，不需要服务端配置
- URL 不美观，不利于 SEO

**2. History 模式（`/path`）**

```javascript
// pushState / replaceState 改变 URL 但不刷新页面
history.pushState({}, '', '/new-path')

// popstate 监听前进/后退
window.addEventListener('popstate', () => {
  renderRoute(window.location.pathname)
})
```

- URL 干净，像正常页面
- 需要服务端配合：所有路径返回同一个 HTML（否则刷新 404）

#### React Router 核心实现

```javascript
// Provider 模式：提供路由上下文
<BrowserRouter>
  ↓ 内部监听 popstate + pushState
  ↓ 维护 location state
  ↓ 通过 Context 下发
<Routes>
  <Route path="/" element={<Home />} />
  <Route path="/user/:id" element={<User />} />
</Routes>
```

匹配原理：`matchPath(pattern, pathname)` → 用 `path-to-regexp` 将 `/user/:id` 转为正则 → 匹配当前路径 → 提取 params。

#### Vue Router 核心实现

```javascript
const router = createRouter({
  history: createWebHistory(), // 或 createWebHashHistory()
  routes: [
    { path: '/', component: Home },
    { path: '/user/:id', component: User }
  ]
})
```

Vue Router 利用 Vue 的响应式系统：

- `route` 是响应式对象（`reactive` 包裹），路径变化自动触发组件更新
- `<router-view>` 本质是 `computed(() => matchedComponent)`，匹配变化自动渲染对应组件

#### 动态加载（路由懒加载）

```javascript
// React（React.lazy + Suspense）
const Home = React.lazy(() => import('./Home'))

// Vue（动态 import）
const Home = () => import('./Home.vue')
```

原理：

1. Webpack/Vite 将 `import('./Home')` 编译为单独 chunk
2. 路由匹配到该路径时，异步加载对应 chunk
3. 加载完成后，组件挂载到 `<router-view>` 或 `<Routes>`

#### React Router vs Vue Router 差异

|           | React Router v6                 | Vue Router 4                            |
| --------- | ------------------------------- | --------------------------------------- |
| 路由定义  | `<Routes><Route/></Routes>` JSX | `routes` 配置数组                       |
| 导航      | `useNavigate()`                 | `useRouter().push()`                    |
| 参数      | `useParams()`                   | `useRoute().params`                     |
| 守卫      | 组件内自行处理                  | 全局守卫 `beforeEach` / `beforeResolve` |
| KeepAlive | 自行实现或第三方                | `<KeepAlive>` 内置                      |

:::

### 3.7 可熟练应用React API、生命周期等，可应用HOC、render props、Hooks等高阶用法解决问题

::: details 参考

#### React 生命周期（类组件，了解即可）

```
挂载阶段：  constructor → static getDerivedStateFromProps → render → componentDidMount
更新阶段：  getDerivedStateFromProps → shouldComponentUpdate → render → getSnapshotBeforeUpdate → componentDidUpdate
卸载阶段：  componentWillUnmount
错误处理：  static getDerivedStateFromError / componentDidCatch
```

#### Hooks 核心 API

| Hook                  | 用途                             | 注意事项                                     |
| --------------------- | -------------------------------- | -------------------------------------------- |
| `useState`            | 状态管理                         | 函数式更新获取最新值                         |
| `useEffect`           | 副作用（请求、DOM、订阅）        | 返回清理函数；依赖数组 vs 空数组 vs 不传     |
| `useRef`              | 引用不变的值/DOM                 | 修改 `.current` 不触发重新渲染               |
| `useMemo`             | 缓存计算结果                     | 依赖不变返回缓存值                           |
| `useCallback`         | 缓存函数引用                     | `useMemo(fn, deps)` 的语法糖                 |
| `useReducer`          | 复杂状态逻辑                     | Redux 风格的 action→state 模式               |
| `useContext`          | 消费 Context                     | Context value 变化导致所有 consumer 重新渲染 |
| `useLayoutEffect`     | DOM 操作后、浏览器绘制前同步执行 | 会阻塞渲染，谨慎使用                         |
| `useImperativeHandle` | 自定义 ref 暴露的实例值          | 配合 `forwardRef`                            |
| `useTransition`       | 标记非紧急更新                   | React 18，低优先级更新可被中断               |

#### HOC（高阶组件）

函数接收一个组件，返回一个新组件。用于逻辑复用（React Router 的 `withRouter`、Redux 的 `connect`）。

```javascript
function withAuth(Component) {
  return function AuthenticatedComponent(props) {
    const { user } = useAuth()
    if (!user) return <Login />
    return <Component {...props} user={user} />
  }
}
```

缺点：嵌套过深导致"wrapper hell"、props 命名冲突、类型推断困难。

#### Render Props

通过函数 prop 共享代码：

```javascript
<Mouse render={({ x, y }) => <Cat x={x} y={y} />} />
```

缺点：嵌套导致"回调地狱"；每个 render 函数在每次渲染时都会重新创建。

#### Hooks vs HOC vs Render Props

|            | Hooks            | HOC           | Render Props          |
| ---------- | ---------------- | ------------- | --------------------- |
| 嵌套问题   | 无（平铺）       | 多层嵌套      | 多层嵌套              |
| Props 冲突 | 无               | 容易冲突      | 参数明确              |
| 代码组织   | 逻辑内聚         | 分散          | 分散                  |
| 学习成本   | 需理解闭包和依赖 | 理解 HOC 模式 | 理解函数作为 children |

> 现代 React 开发中 Hooks 已基本取代 HOC 和 Render Props。后者主要出现在遗留代码中。

### 3.8 基于React的特性和原理，可以手动实现一个简单的React

::: details 参考

```javascript
// ━━━━━━━ VDOM 创建 ━━━━━━━
function createElement(type, props, ...children) {
  return {
    type,
    props: { ...props, children: children.flat() }
  }
}

// ━━━━━━━ 渲染 ━━━━━━━
function render(vnode, container) {
  // 文本节点
  if (typeof vnode === 'string' || typeof vnode === 'number') {
    container.appendChild(document.createTextNode(vnode))
    return
  }
  // 创建 DOM
  const dom = document.createElement(vnode.type)

  // 设置属性
  if (vnode.props) {
    Object.keys(vnode.props).forEach((key) => {
      if (key === 'children') return
      if (key.startsWith('on')) {
        dom.addEventListener(key.slice(2).toLowerCase(), vnode.props[key])
      } else {
        dom[key] = vnode.props[key]
      }
    })
  }

  // 递归渲染子节点
  vnode.props?.children?.forEach((child) => render(child, dom))

  container.appendChild(dom)
}

// ━━━━━━━ Fiber 调度核心 ━━━━━━━
let nextUnitOfWork = null
let currentRoot = null
let wipRoot = null
let deletions = []

function workLoop(deadline) {
  let shouldYield = false
  while (nextUnitOfWork && !shouldYield) {
    nextUnitOfWork = performUnitOfWork(nextUnitOfWork)
    shouldYield = deadline.timeRemaining() < 1
  }
  if (!nextUnitOfWork && wipRoot) commitRoot()
  requestIdleCallback(workLoop)
}
requestIdleCallback(workLoop)

// ━━━━━━━ reconciliation ━━━━━━━
function reconcileChildren(wipFiber, elements) {
  let index = 0
  let oldFiber = wipFiber.alternate?.child
  let prevSibling = null

  while (index < elements.length || oldFiber) {
    const element = elements[index]
    let newFiber = null
    const sameType = oldFiber && element && element.type === oldFiber.type

    if (sameType) {
      newFiber = {
        type: oldFiber.type,
        props: element.props,
        dom: oldFiber.dom,
        parent: wipFiber,
        alternate: oldFiber,
        effectTag: 'UPDATE'
      }
    }
    if (element && !sameType) {
      newFiber = {
        type: element.type,
        props: element.props,
        dom: null,
        parent: wipFiber,
        alternate: null,
        effectTag: 'PLACEMENT'
      }
    }
    if (oldFiber && !sameType) {
      oldFiber.effectTag = 'DELETION'
      deletions.push(oldFiber)
    }

    if (oldFiber) oldFiber = oldFiber.sibling
    if (index === 0) wipFiber.child = newFiber
    else prevSibling.sibling = newFiber
    prevSibling = newFiber
    index++
  }
}

// ━━━━━━━ Commit 阶段 ━━━━━━━
function commitRoot() {
  deletions.forEach(commitWork)
  commitWork(wipRoot.child)
  currentRoot = wipRoot
  wipRoot = null
  deletions = []
}

function commitWork(fiber) {
  if (!fiber) return
  const domParent = fiber.parent.dom
  if (fiber.effectTag === 'PLACEMENT' && fiber.dom) domParent.appendChild(fiber.dom)
  else if (fiber.effectTag === 'UPDATE' && fiber.dom)
    updateDom(fiber.dom, fiber.alternate.props, fiber.props)
  else if (fiber.effectTag === 'DELETION') domParent.removeChild(fiber.dom)
  commitWork(fiber.child)
  commitWork(fiber.sibling)
}

// ━━━━━━━ Hook 系统 ━━━━━━━
let wipFiber = null
let hookIndex = 0

function useState(initial) {
  const oldHook = wipFiber.alternate?.hooks?.[hookIndex]
  const hook = { state: oldHook ? oldHook.state : initial, queue: [] }

  oldHook?.queue.forEach((action) => {
    hook.state = action(hook.state)
  })

  const setState = (action) => {
    hook.queue.push(typeof action === 'function' ? action : () => action)
    wipRoot = { dom: currentRoot.dom, props: currentRoot.props, alternate: currentRoot }
    nextUnitOfWork = wipRoot
    deletions = []
  }

  wipFiber.hooks = wipFiber.hooks || []
  wipFiber.hooks.push(hook)
  hookIndex++
  return [hook.state, setState]
}
```

核心要点回顾：

1. **Virtual DOM** → JS 对象描述 UI
2. **Fiber** → 链表结构，可中断
3. **Reconciliation** → type + key 决定复用/新增/删除
4. **Commit** → 一次性把副作用应用到真实 DOM
5. **Hooks** → Fiber 节点上挂载链表，调用顺序决定 Hook 对应关系

### 3.9 useEffect 深入：闭包陷阱、竞态条件、清理函数、与 useLayoutEffect 对比

::: details 参考

#### 闭包陷阱（Stale Closure）

`useEffect` 中引用的变量是**捕获创建时的值**，不是最新值：

```javascript
function Counter() {
  const [count, setCount] = useState(0)

  useEffect(() => {
    const timer = setInterval(() => {
      console.log(count) // 永远打印 0！
      setCount(count + 1) // count 永远是 0，所以始终 setCount(1)
    }, 1000)
    return () => clearInterval(timer)
  }, []) // 空依赖，只在挂载时执行一次

  return <div>{count}</div>
}
```

**解决方案**：

```javascript
// 方案 1：函数式更新（推荐，不依赖外部 count）
useEffect(() => {
  const timer = setInterval(() => {
    setCount((c) => c + 1) // 不需要 count 在依赖里
  }, 1000)
  return () => clearInterval(timer)
}, [])

// 方案 2：useRef 存最新值
const countRef = useRef(count)
countRef.current = count
useEffect(() => {
  const timer = setInterval(() => {
    console.log(countRef.current) // 始终最新
  }, 1000)
  return () => clearInterval(timer)
}, [])

// 方案 3：count 加入依赖数组（简单但要理解后果——每次 count 变都会重建定时器）
useEffect(() => {
  const timer = setInterval(() => {
    console.log(count)
  }, 1000)
  return () => clearInterval(timer)
}, [count]) // 每次 count 变化清理旧定时器，建新定时器
```

#### 竞态条件（Race Condition）

多次请求返回顺序不一致时，旧请求可能覆盖新请求的结果：

```javascript
function SearchResults({ query }) {
  const [results, setResults] = useState([])

  useEffect(() => {
    let ignore = false // 标记是否应该忽略本次结果

    fetch(`/api/search?q=${query}`)
      .then((res) => res.json())
      .then((data) => {
        if (!ignore) setResults(data) // 只有没被忽略的才更新
      })

    return () => {
      ignore = true
    } // 下次 effect 执行前，标记本次为"忽略"
  }, [query])

  return (
    <ul>
      {results.map((r) => (
        <li key={r.id}>{r.name}</li>
      ))}
    </ul>
  )
}
```

当 `query` 快速变化（如快速输入 "re" → "rea" → "reac" → "react"），每次都会触发新请求。清理函数将旧请求的 `ignore` 置为 `true`，旧请求即使返回也不会更新 UI。

#### 清理函数（Cleanup）到底是干什么的？

清理函数在两个时机执行：

1. 组件卸载前
2. **下一次 effect 执行前**（清除上一次 effect 的副作用）

```javascript
useEffect(() => {
  // 订阅
  const subscription = api.subscribe(channelId)

  // 清理函数
  return () => {
    subscription.unsubscribe() // channelId 变了 → 取消旧订阅 → 重新执行 effect 订阅新 channel
  }
}, [channelId])
```

**面试要点**：清理函数中的变量也是闭包，捕获的是**创建 effect 时的值**。

#### useEffect vs useLayoutEffect

|            | useEffect                  | useLayoutEffect                        |
| ---------- | -------------------------- | -------------------------------------- |
| 执行时机   | 浏览器**绘制之后**异步执行 | DOM 变更后、浏览器**绘制之前**同步执行 |
| 阻塞渲染   | 不会                       | **会阻塞**（同步执行完才绘制）         |
| 使用场景   | 数据请求、订阅、日志       | 读取 DOM 布局、同步修改 DOM 防止闪烁   |
| 服务端渲染 | 不执行                     | 会有警告（SSR 时服务端没有 DOM）       |

```javascript
// 典型 useLayoutEffect 场景：避免闪烁
function Tooltip({ position }) {
  const ref = useRef(null)
  const [adjustedPos, setAdjustedPos] = useState(position)

  useLayoutEffect(() => {
    // 先计算实际位置（如是否会溢出屏幕），再绘制
    const rect = ref.current.getBoundingClientRect()
    if (rect.right > window.innerWidth) {
      setAdjustedPos({ ...position, x: window.innerWidth - rect.width })
    }
  }, [position])

  return (
    <div ref={ref} style={{ left: adjustedPos.x }}>
      提示
    </div>
  )
}
```

> 经验法则：**99% 用 useEffect**，只有遇到视觉闪烁或需要同步读取 DOM 布局时才换成 useLayoutEffect。如果 SSR 报 useLayoutEffect 警告，在客户端 `useEffect` 中做。

:::

### 3.10 React.memo、useMemo、useCallback 正确使用姿势与性能优化

::: details 参考

#### React 默认的渲染行为（关键认知）

父组件重新渲染 → **所有子组件默认全部重新渲染**，即使子组件的 props 没有变化。

```javascript
function Parent() {
  const [count, setCount] = useState(0)
  return (
    <div>
      <button onClick={() => setCount((c) => c + 1)}>Count: {count}</button>
      <ExpensiveChild /> {/* Parent 每次渲染，ExpensiveChild 也渲染 */}
    </div>
  )
}
```

#### React.memo —— 阻止不必要的子组件渲染

```javascript
const ExpensiveChild = React.memo(function ExpensiveChild() {
  console.log('ExpensiveChild rendered')
  return <div>大量计算...</div>
})
// 父组件 count 变化时，ExpensiveChild 不会重新渲染（props 没变）

// 自定义比较函数
React.memo(Component, (prevProps, nextProps) => {
  return prevProps.user.id === nextProps.user.id // 只比较 id
})
```

> `React.memo` 做的是**浅比较**（`Object.is`）。对象/数组/函数类型的 props 每次都是新引用，所以 `React.memo` 需要配合 `useMemo` / `useCallback` 才有效。

#### 常见失效场景

```javascript
// ❌ 错误：每次渲染都传入新对象/函数
<ExpensiveChild user={{ name: 'John' }} />          // 新对象，浅比较不相等
<ExpensiveChild onClick={() => handleClick()} />    // 新函数，浅比较不相等

// ✅ 正确：用 useMemo 和 useCallback 稳定引用
const user = useMemo(() => ({ name: 'John' }), []); // 引用稳定
const handleClick = useCallback(() => { ... }, []);  // 引用稳定
<ExpensiveChild user={user} onClick={handleClick} />
```

#### 何时使用 / 何时不用

**应该用 `useMemo`**：

- 计算开销大（如大数组排序、过滤、复杂递归）
- 作为 `React.memo` 子组件的 prop（保证引用稳定）
- 作为其他 Hook（useEffect、useCallback）的依赖

**不应该用 `useMemo`**：

- 简单计算（对象字面量、字符串拼接等——创建新对象比 useMemo 本身的开销还小）
- 值从不会改变
- 依赖经常变（缓存永远不会命中，反而多了开销）

**应该用 `useCallback`**：

- 传给 `React.memo` 子组件的回调函数
- 作为 `useEffect` 的依赖（避免 effect 不必要的重复执行）

**不应该用 `useCallback`**：

- 传给原生 DOM 元素（`<button onClick={fn}>`——DOM 事件不会触发组件重渲染）
- 函数体很简单的内联函数

#### 性能优化的正确顺序

```
1. 先写没有优化的代码
2. 遇到性能问题 → Profiler 测量
3. 确认哪个组件渲染太多 → React.memo
4. 确认哪些 props 引用不稳定 → useMemo / useCallback
5. 确认哪些计算太慢 → useMemo 包裹
```

> "过早优化是万恶之源。" React 渲染很快，请先用 Profiler 确认瓶颈再动手优化。

#### useMemo 的常见误用

```javascript
// ❌ 滥用
const name = useMemo(() => props.name, [props.name]) // 直接引用就行
const style = useMemo(() => ({ color: 'red' }), []) // 静态值，放组件外即可

// ✅ 合理的用法
const sortedList = useMemo(() => expensiveSort(largeList, sortConfig), [largeList, sortConfig]) // 大数据量排序，值得缓存

const themeContext = useMemo(() => ({ theme, toggle }), [theme])
// 作为 Context value，theme 不变时引用不变，下游 consumer 不重渲染
```

#### 一个完整的性能优化例子

```javascript
const Parent = () => {
  const [count, setCount] = useState(0)
  const [keyword, setKeyword] = useState('')

  // useMemo: 缓存计算结果
  const filtered = useMemo(() => items.filter((i) => i.name.includes(keyword)), [keyword, items])

  // useCallback: 稳定函数引用，避免子组件不必要的渲染
  const handleDelete = useCallback((id) => {
    setItems((prev) => prev.filter((i) => i.id !== id))
  }, [])

  return (
    <>
      <input value={keyword} onChange={(e) => setKeyword(e.target.value)} />
      <button onClick={() => setCount((c) => c + 1)}>{count}</button>
      {/* count 变化时，ItemList 不会重渲染 */}
      <ItemList items={filtered} onDelete={handleDelete} />
    </>
  )
}

const ItemList = React.memo(({ items, onDelete }) => {
  return items.map((item) => <Item key={item.id} item={item} onDelete={onDelete} />)
})
```

### 3.11 React 18 并发特性详解：useTransition、useDeferredValue、Automatic Batching

::: details 参考

#### 并发模式（Concurrent Mode）要解决什么？

React 的传统渲染是**不可中断的**——一旦开始渲染一棵组件树，必须全部渲染完。这导致：

- 用户输入了一个搜索词，但 React 正在渲染一个复杂列表，输入框"卡住"了
- 页面大型列表排序，页面要"白"几百毫秒直到排序完成

并发模式的核心：**渲染可以被中断和恢复**，React 可以在多个任务间"交替"工作。

#### useTransition —— 标记低优先级更新

```javascript
import { useState, useTransition } from 'react'

function SearchPage() {
  const [query, setQuery] = useState('')
  const [isPending, startTransition] = useTransition()

  function handleChange(e) {
    // 高优先级：立即更新输入框
    setQuery(e.target.value)

    // 低优先级：可以被中断的列表过滤
    startTransition(() => {
      setFilteredList(filterItems(e.target.value))
    })
  }

  return (
    <>
      <input value={query} onChange={handleChange} />
      {isPending && <Spinner />} {/* 低优先级更新未完成时展示 */}
      <ExpensiveList items={filteredList} /> {/* 渲染可能被中断 */}
    </>
  )
}
```

效果：用户输入时，输入框始终跟手，列表更新可以"慢一点"。

#### useDeferredValue —— 延迟值的"旧版本"

```javascript
import { useDeferredValue } from 'react'

function SearchPage() {
  const [query, setQuery] = useState('')
  const deferredQuery = useDeferredValue(query)
  // query 立即变，deferredQuery 延迟变

  return (
    <>
      <input value={query} onChange={(e) => setQuery(e.target.value)} />
      {/* 当 query 快速变化时，memo 只拿 deferredQuery 的最终值渲染，省略中间状态 */}
      <MemoList query={deferredQuery} />
    </>
  )
}
```

#### useTransition vs useDeferredValue 何时使用

|                        | useTransition                         | useDeferredValue                                        |
| ---------------------- | ------------------------------------- | ------------------------------------------------------- |
| 能控制 `setState` 吗？ | 是——`startTransition(() => setXxx())` | 否——只能拿到延迟后的值                                  |
| 知道 pending 状态吗？  | 是——`isPending`                       | 否——需自行判断值是否"过期"                              |
| 使用场景               | 可以在事件处理中降低优先级            | **不能控制**数据来源（如 props 传入的频繁变化的 query） |

#### Automatic Batching（自动批处理）

React 18 之前，只有 React 事件处理中的 `setState` 会被批处理。`setTimeout`、`Promise` 回调中的 `setState` 每次都会触发独立的重新渲染。

React 18 **所有上下文**中的 setState 都会自动批处理：

```javascript
// React 17
setTimeout(() => {
  setCount((c) => c + 1) // 触发一次重新渲染
  setFlag((f) => !f) // 触发又一次重新渲染！
}, 0)

// React 18（自动批处理）
setTimeout(() => {
  setCount((c) => c + 1)
  setFlag((f) => !f)
  // 只触发一次重新渲染！
}, 0)

// 如果确实需要立即拿到更新后的 DOM（类似 React 17 的同步行为）
import { flushSync } from 'react-dom'
flushSync(() => {
  setCount((c) => c + 1) // 立即 flush，同步更新
})
```

#### Suspense for Data Fetching

```javascript
// React 18: Suspense 不仅用于代码分割，还能用于数据加载
function ProfilePage() {
  return (
    <Suspense fallback={<ProfileSkeleton />}>
      <ProfileDetails /> {/* 内部可以直接 throw Promise！ */}
      <Suspense fallback={<PostsSkeleton />}>
        <ProfilePosts /> {/* 嵌套 Suspense：独立加载中状态 */}
      </Suspense>
    </Suspense>
  )
}
```

第三方库（React Query、SWR、Next.js App Router）封装了 Suspense 集成，日常开发不需要手动 throw Promise。

#### 并发特性总结

| 特性               | 作用                                 | 典型场景               |
| ------------------ | ------------------------------------ | ---------------------- |
| `useTransition`    | 标记更新为低优先级，拿到 `isPending` | Tab 切换、搜索过滤     |
| `useDeferredValue` | 延迟值变化，渲染最终状态             | 搜索输入、实时图表数据 |
| Automatic Batching | 所有 setState 自动合并               | 全局（无感知，纯改进） |
| `Suspense`         | 声明式加载中状态                     | 代码分割、数据加载     |
| `startTransition`  | 降低包装内 setState 的优先级         | 路由跳转、列表切换     |

### 3.12 React Context 性能问题与优化方案

::: details 参考

#### Context 的核心问题

Context value 变化 → **所有使用该 Context 的组件（useContext/Consumer）全部重新渲染**，即使该组件只用了 value 中的一小部分。

```javascript
const AppContext = createContext()

function App() {
  const [user, setUser] = useState(null) // 频繁变化
  const [theme, setTheme] = useState('light') // 很少变化

  // ❌ 每次 user 变化，theme 的消费者也重新渲染
  const value = { user, setUser, theme, setTheme }

  return (
    <AppContext.Provider value={value}>
      <Header /> {/* 只用 theme */} ← user 变了 Header 也渲染
      <Main /> {/* 只用 user */}
    </AppContext.Provider>
  )
}
```

**根本原因**：每次渲染 `value = { user, theme }` 都是新对象引用，Context 用 `Object.is` 判断是否变化。

#### 解决策略

**策略 1：拆分 Context（最推荐）**

将变化频率不同的数据分到不同的 Context：

```javascript
const UserContext = createContext()
const ThemeContext = createContext()

function App() {
  const [user, setUser] = useState(null)
  const [theme, setTheme] = useState('light')

  return (
    <ThemeContext.Provider value={useMemo(() => ({ theme, setTheme }), [theme])}>
      <UserContext.Provider value={useMemo(() => ({ user, setUser }), [user])}>
        <Header /> {/* 只消费 ThemeContext，user 变化不影响它 */}
        <Main /> {/* 只消费 UserContext，theme 变化不影响它 */}
      </UserContext.Provider>
    </ThemeContext.Provider>
  )
}
```

**策略 2：拆分读写**

把读和写分到两个 Context，因为 setter 函数通常不会变：

```javascript
const UserStateContext = createContext() // 读（经常变）
const UserDispatchContext = createContext() // 写（几乎不变）

function UserProvider({ children }) {
  const [user, setUser] = useState(null)
  return (
    <UserStateContext.Provider value={user}>
      <UserDispatchContext.Provider value={setUser}>{children}</UserDispatchContext.Provider>
    </UserStateContext.Provider>
  )
}
// 只调用 setter 的组件不再因为 user 变化而重渲染
```

**策略 3：Selector 模式（用第三方库或自建）**

```javascript
// 手动实现简单的 selector（或用 use-context-selector 库）
import { useContextSelector } from 'use-context-selector'

function Header() {
  const theme = useContextSelector(AppContext, (v) => v.theme)
  // 只有 theme 变化才重渲染，user 变化不影响
  return <div className={theme}>Header</div>
}
```

**策略 4：children prop（组件组合）**

```javascript
// 如果某些子组件不依赖 Context，让它通过 children 传入
function App() {
  return (
    <ThemeProvider>
      <Layout>
        <StaticSidebar /> {/* 不消费 Context → 不重渲染 */}
        <DynamicContent />
      </Layout>
    </ThemeProvider>
  )
}

function ThemeProvider({ children }) {
  const [theme, setTheme] = useState('light')
  return <ThemeContext.Provider value={{ theme, setTheme }}>{children}</ThemeContext.Provider>
}
// StaticSidebar 是 children prop 传入的，theme 变化不会导致它重新渲染
// ——因为 children 是 ThemeProvider render 之前就已经创建好的 JSX
```

#### Context vs 状态管理库

|      | Context                          | Zustand / Redux              |
| ---- | -------------------------------- | ---------------------------- |
| 定位 | 依赖注入（主题、语言、用户信息） | 状态管理（复杂业务状态）     |
| 性能 | 所有 consumer 重渲染             | 细粒度订阅（只订阅部分状态） |
| 适用 | 低频变化的全局配置               | 频繁变化且多处引用的业务状态 |

> 核心原则：**Context 不是状态管理工具**。如果你用 Context 存高频率变化的数据（如表单值、列表数据），而且很多组件都消费它——这就是该换状态管理库的信号。

### 3.13 Error Boundaries 错误边界

::: details 参考

#### 什么是 Error Boundary？

React 组件树中任何组件的 render 报错，如果不捕获，整个组件树会**白屏**。Error Boundary 捕获子组件的渲染错误，展示降级 UI，保持其他部分正常工作。

```javascript
class ErrorBoundary extends React.Component {
  constructor(props) {
    super(props)
    this.state = { hasError: false, error: null }
  }

  static getDerivedStateFromError(error) {
    // 更新 state 使下一次渲染展示降级 UI
    return { hasError: true, error }
  }

  componentDidCatch(error, errorInfo) {
    // 上报错误到监控平台
    console.error('ErrorBoundary caught:', error, errorInfo.componentStack)
  }

  render() {
    if (this.state.hasError) {
      return this.props.fallback || <h1>出错了</h1>
    }
    return this.props.children
  }
}

// 使用
;<ErrorBoundary fallback={<ErrorUI />}>
  <RiskyComponent />
</ErrorBoundary>
```

#### 能捕获 vs 不能捕获

**可以捕获**：

- 渲染期间（render）的错误（包括函数组件的整个函数体）
- 生命周期函数中的错误
- 子组件树中构造函数中的错误

**不能捕获**（需要 try/catch / .catch()）：

- **事件处理函数**中的错误（如 onClick、onChange）
- **异步代码**错误（setTimeout、Promise）
- **服务端渲染**中的错误（SSR 错误）
- **Error Boundary 自身**抛出的错误

#### 为什么 Error Boundary 必须用 class 组件？

React 还没有对应的 Hook（`useErrorBoundary` 不存在）。因为 Error Boundary 需要用到 `getDerivedStateFromError` 和 `componentDidCatch` 这两个生命周期方法，目前只在 class 组件上可用。

**替代方案**：使用 `react-error-boundary` 库，提供 Hook 友好的 API。

#### 实践建议

1. **分层放置**：在应用根节点、每个路由页面、风险高的组件各放一层 Error Boundary
2. **提供重置按钮**：`key` 变化会导致组件卸载重建

```javascript
function App() {
  const [resetKey, setResetKey] = useState(0)
  return (
    <ErrorBoundary key={resetKey} fallback={<ErrorUI onRetry={() => setResetKey((k) => k + 1)} />}>
      <RiskyComponent />
    </ErrorBoundary>
  )
}
```

> 面试金句："Error Boundary 实现的是优雅降级，让局部错误不影响整体应用。"

### 3.14 Hooks 规则与底层实现原理

::: details 参考

#### 两条铁律

1. **只在函数组件顶层调用 Hooks**（不能在条件、循环、return 之后调用）
2. **只在 React 函数组件或自定义 Hook 中调用 Hooks**

#### 为什么不能条件调用？

React 用**链表**存储 Hook 状态，按**调用顺序**匹配：

```javascript
// 第一次渲染
function Component() {
  const [a, setA] = useState(1) // Hook 0 ← 挂到 fiber 的 hook 链表
  const [b, setB] = useState(2) // Hook 1
  useEffect(() => {}, [a]) // Hook 2
}

// 第二次渲染（update）
function Component() {
  const [a, setA] = useState(1) // 读 Hook 0 的状态 → a
  const [b, setB] = useState(2) // 读 Hook 1 的状态 → b
  useEffect(() => {}, [a]) // 读 Hook 2 的状态
}
// 渲染间的 Hook 按"顺序"对应，不按"名字"
```

如果允许条件调用：

```javascript
// 第一次渲染
if (condition) {
  const [a, setA] = useState(1) // Hook 0
}
const [b, setB] = useState(2) // Hook 1

// 第二次渲染：condition = false
const [b, setB] = useState(2) // 读到 Hook 0 → 拿到 a 的值！Bug！
```

**顺序乱了，所有状态就全乱了。** React 完全靠调用顺序来匹配前后两次渲染的 Hook。

#### Fiber 上的 Hook 链表

```javascript
// Fiber 节点上的 hooks 字段（简化）
fiber.memoizedState = {
  // Hook 0
  memoizedState: 1, // state 值
  queue: {
    /* update queue */
  }, // setState 的更新队列（环状链表）
  next: {
    // Hook 1
    memoizedState: 2,
    queue: {
      /* ... */
    },
    next: {
      // Hook 2 (effect)
      memoizedState: {
        // effect 信息
        create: () => {
          /* ... */
        },
        destroy: undefined,
        deps: [a]
      },
      next: null
    }
  }
}
```

#### useState 简易实现

```javascript
let workInProgressHook = null // 当前正在处理的 hook
let isMount = true

function useState(initialState) {
  let hook

  if (isMount) {
    // 首次渲染：创建 hook 节点
    hook = { memoizedState: initialState, queue: [], next: null }
    if (!workInProgressHook) {
      currentlyRenderingFiber.memoizedState = hook
    } else {
      workInProgressHook.next = hook
    }
    workInProgressHook = hook
  } else {
    // 更新时：取下一个 hook
    hook = workInProgressHook
    workInProgressHook = workInProgressHook.next
  }

  // 执行 update queue 得到最新 state
  let state = hook.memoizedState
  hook.queue.forEach((update) => {
    state = typeof update === 'function' ? update(state) : update
  })
  hook.memoizedState = state

  const setState = (update) => {
    hook.queue.push(update)
    scheduleUpdate() // 触发重新渲染
  }

  return [state, setState]
}
```

#### 自定义 Hook vs 普通函数

自定义 Hook 就是以 `use` 开头的函数，内部调用了其他 Hook。本质区别在于：

- 自定义 Hook **有自己的 Hook 链表节点**，能持有状态和副作用
- 普通函数每次渲染都重新执行，不持有任何 React 内部状态

```javascript
// 自定义 Hook → 每个调用它的组件实例有独立的 Hook 状态
function useWindowSize() {
  const [size, setSize] = useState({ width: 0, height: 0 })
  useEffect(() => {
    /* 监听 resize */
  }, [])
  return size
}

// 两个组件各自调用 useWindowSize() → 各自有自己的 size state
// A 组件的 size 变化不会影响 B 组件
```

### 3.15 React 19 核心新特性与 React Server Components

::: details 参考

> React 19 于 2024 年底发布稳定版。

#### 新 Hook：`use()`

在 render 中读取 Promise 或 Context，**不是 Hook 但可以在条件语句中使用**：

```javascript
function Post({ postId }) {
  // use() 可以出现在 if/return 之后！
  if (shouldShow) {
    const post = use(fetchPost(postId)) // 读取 Promise
    return <div>{post.title}</div>
  }
  return <Fallback />
}
```

`use()` 的独特之处：

- 可以在条件语句、循环中使用（因为它不依赖调用顺序）
- 与 Suspense 深度集成：Promise pending 时触发最近的 `<Suspense>`
- 也可以读取 Context：`const theme = use(ThemeContext)`

#### Actions（Server Actions 的基础）

React 19 的 Actions 统一了"异步操作 + 状态管理"的模式：

```javascript
function ChangeName() {
  const [error, setError] = useState(null)
  const [isPending, setIsPending] = useState(false)

  // 传统写法 → React 19 Actions
  async function handleSubmit(formData) {
    setIsPending(true)
    setError(null)
    try {
      await updateName(formData.get('name'))
    } catch (e) {
      setError(e.message)
    }
    setIsPending(false)
  }
}
```

React 19 提供了自动处理 pending、error、optimistic update 的 API：

```javascript
import { useActionState, useFormStatus, useOptimistic } from 'react'

// useOptimistic：乐观更新
const [optimisticMessages, addOptimisticMessage] = useOptimistic(messages, (state, newMessage) => [
  ...state,
  { ...newMessage, sending: true }
])

// useFormStatus：读取表单提交状态
function SubmitButton() {
  const { pending } = useFormStatus()
  return <button disabled={pending}>{pending ? '提交中...' : '提交'}</button>
}

// useActionState：表单 Action 的完整状态管理
const [state, formAction, isPending] = useActionState(updateProfile, initialState)
```

#### `ref` 作为 prop

React 19 中 `ref` 可以直接作为 prop 传递，不再需要 `forwardRef`：

```javascript
// React 18
const MyInput = React.forwardRef((props, ref) => <input ref={ref} {...props} />)

// React 19 — forwardRef 不再需要！
function MyInput({ ref, ...props }) {
  return <input ref={ref} {...props} />
}
```

#### React Server Components（RSC）

React 19 的核心范式转变——**组件可以在服务端运行，永远不会发送到客户端**。

```
传统 React（CSR）:
  浏览器下载 JS → 执行 → 渲染 → 展示

RSC:
  服务端执行组件 → 渲染为序列化的 JSX 流 → 传给浏览器 → 浏览器渲染
  （组件的 JS 代码不会发送到浏览器！）
```

**三类组件**：

| 类型                     | 文件名                          | 运行位置               | 能做什么                                         |
| ------------------------ | ------------------------------- | ---------------------- | ------------------------------------------------ |
| Server Component（默认） | 无后缀                          | 只在服务端             | 直接查数据库、读文件系统、访问后端 API           |
| Client Component         | `.client.jsx` 或 `'use client'` | 客户端 + 服务端（SSR） | 交互（onClick、useState、useEffect）、浏览器 API |
| Shared Component         | 无后缀                          | 两边都可能             | 不含 server-only 或 client-only 的特性           |

```javascript
// Server Component —— 可以直接 await 数据库查询！
// 这段代码永远不会送到浏览器
async function PostList() {
  const posts = await db.query('SELECT * FROM posts') // 直接访问数据库！
  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>
          <PostTitle title={post.title} />
          <LikeButton postId={post.id} /> {/* Client Component */}
        </li>
      ))}
    </ul>
  )
}
```

**RSC 的好处**：

1. 零 JS 体积：Server Component 的代码不发送到客户端
2. 直接访问后端资源（数据库、文件系统、微服务）
3. 自动代码分割：只有 Client Component 边界产生 JS bundle
4. 避免客户端-服务端瀑布请求

**Next.js App Router** 是目前 RSC 最主要的落地框架。

#### 其他 React 19 变化

- **Document Metadata**：`<title>`、`<meta>`、`<link>` 写在组件里，自动提升到 `<head>` 中
- **`<Context>` 作为 Provider**：`<ThemeContext value="dark">` 替代 `<ThemeContext.Provider value="dark">`
- **资源预加载 API**：`prefetchDNS`、`preconnect`、`preload`、`preinit` 等
- **清理函数支持异步**：`useEffect` 清理函数现在可以返回 Promise

### 3.16 React 性能优化全景清单

::: details 参考

#### 渲染层面的优化

| 优化项            | 怎么用                          | 什么时候用                                                  |
| ----------------- | ------------------------------- | ----------------------------------------------------------- |
| `React.memo`      | 包裹组件                        | Props 浅比较不变时跳过渲染；子组件渲染开销大                |
| `useMemo`         | 缓存计算结果                    | 计算开销大（排序/过滤大数组）；作为子组件 prop 保持引用稳定 |
| `useCallback`     | 缓存函数引用                    | 传给 memo 子组件的回调；作为 useEffect 依赖                 |
| 状态下沉          | 将状态放到使用它的最小子树      | 避免父组件频繁重渲染导致大片子树更新                        |
| 列表 `key`        | 用唯一稳定 ID                   | 避免 index 做 key 导致的错误复用和不必要的 DOM 操作         |
| 避免内联对象/函数 | `useMemo`/`useCallback`稳定引用 | 配合 `React.memo` 时                                        |

#### 代码层面的优化

| 优化项                         | 说明                                                                     |
| ------------------------------ | ------------------------------------------------------------------------ |
| **代码分割（Code Splitting）** | `React.lazy(() => import('./Page'))` + `<Suspense>`，按路由/功能拆包     |
| **虚拟列表**                   | `react-window` / `react-virtualized`，只渲染可视区域的 DOM（长列表必备） |
| **防抖/节流**                  | 高频事件（scroll/resize/input）用 debounce/throttle 减少渲染次数         |
| **Web Worker**                 | 将 CPU 密集型计算（大 JSON 处理、加密）搬到 Worker 线程                  |

#### 状态管理层面的优化

| 注意事项                       | 说明                                              |
| ------------------------------ | ------------------------------------------------- |
| Context 拆分                   | 频繁变化和稳定的值分到不同 Context（见 3.12）     |
| 服务端数据用 React Query / SWR | 不要用手动 useState + useEffect 管理请求状态      |
| 区分全局状态和局部状态         | 不需要共享的状态留在组件内，不要放到全局 Store    |
| 状态的原子化                   | 用 Zustand / Jotai 等细粒度订阅库，避免过度重渲染 |

#### 资源加载优化

| 优化项     | 说明                                                   |
| ---------- | ------------------------------------------------------ |
| 图片懒加载 | `<img loading="lazy">` 原生支持                        |
| 字体优化   | `font-display: swap` 避免 FOIT（字体加载时白屏）       |
| 预加载     | `<link rel="preload">` 关键资源、`prefetch` 非首屏资源 |
| CDN        | 静态资源走 CDN                                         |

#### 调试工具

| 工具                        | 用途                                           |
| --------------------------- | ---------------------------------------------- |
| **React DevTools Profiler** | 录制渲染 → 火焰图定位慢组件 → 确认优化是否生效 |
| **Chrome Performance**      | 找到 Long Task → 确认是否由 React 渲染引起     |
| **`why-did-you-render`**    | 开发模式下打印不必要的重渲染及原因             |
| **Lighthouse**              | 综合打分 + 优化建议                            |

#### 性能优化决策框架

```
遇到性能问题？
  ├─ 先上 Profiler 定位瓶颈（别猜！）
  ├─ 确认是 JS 渲染慢？
  │    ├─ 是 → React.memo + useMemo/useCallback
  │    ├─ 是（大列表）→ 虚拟列表
  │    └─ 是（大量计算）→ useMemo / Web Worker
  ├─ 确认是首屏慢？
  │    ├─ 代码分割 + 懒加载路由
  │    ├─ 图片/字体优化
  │    └─ SSR / SSG
  ├─ 确认是交互卡顿？
  │    ├─ useTransition / useDeferredValue（React 18）
  │    └─ debounce/throttle 高频事件
  └─ 没确认 → 别动！大概率一切正常
```

### 3.17 JSX 语法规则与编译原理

::: details 参考

#### JSX 本质

JSX 是 `React.createElement()` 的语法糖：

```javascript
// JSX
const el = (
  <h1 className="title" id="main">
    Hello {name}
  </h1>
)

// Babel 编译后
const el = React.createElement(
  'h1',
  {
    className: 'title',
    id: 'main'
  },
  'Hello ',
  name
)

// createElement 返回的 VNode
// { type: 'h1', props: { className: 'title', id: 'main', children: ['Hello ', 'React'] } }
```

#### 核心规则

| 规则                         | 示例                                                                    | 说明                                        |
| ---------------------------- | ----------------------------------------------------------------------- | ------------------------------------------- |
| **单根节点**                 | `<><A/><B/></>` （Fragment）                                            | 必须返回单个元素，空标签 `<></>` 也是语法糖 |
| **`className` 不是 `class`** | `<div className="box">`                                                 | `class` 是 JS 保留字，用 `className`        |
| **`htmlFor` 不是 `for`**     | `<label htmlFor="inputId">`                                             | `for` 是 JS 保留字                          |
| **驼峰命名属性**             | `onClick`、`tabIndex`、`strokeWidth`                                    | 所有 DOM 属性用驼峰                         |
| **大括号 `{}`**              | `{name}`、`{items.map(...)}`                                            | 嵌入 JS 表达式，不能放语句（如 `if`）       |
| **`style` 是对象**           | <code>style=&#123;&#123; color: 'red', fontSize: 14 &#125;&#125;</code> | CSS 属性驼峰，值加单位或数字(px 可省略)     |
| **布尔属性**                 | `<input disabled={true} />`                                             | 不写值等价于 `true`                         |
| **注释**                     | `{/* 这是注释 */}`                                                      | 必须在大括号里                              |
| **`key`**                    | `<li key={item.id}>`                                                    | 列表元素的稳定唯一标识                      |

#### 表达式 vs 语句

```javascript
// ✅ 表达式（有返回值）：可以放在 {} 里
<h1>{name}</h1>                           // 变量
<h1>{items.length}</h1>                   // 属性访问
<h1>{getName()}</h1>                      // 函数调用
<h1>{condition ? <A/> : <B/>}</h1>       // 三元表达式
<h1>{items.map(i => <li key={i.id}>{i.name}</li>)}</h1>  // map

// ❌ 语句（没有返回值）：不能放在 {} 里
<h1>{if (condition) { return <A/> }}</h1> // 报错！
<h1>{for (let i = 0; ...) { ... }}</h1>   // 报错！
```

> JSX 本质上是对 `React.createElement` 的调用，它接收表达式作为参数，而 `if`/`for` 是语句，不能作为函数参数。

#### JSX 如何防止 XSS

```javascript
const userInput = '<img src=x onerror=alert(1)>'
const el = <div>{userInput}</div> // 自动转义为纯文本，显示字符串本身
// 渲染结果: <div>&lt;img src=x onerror=alert(1)&gt;</div>
```

`React.createElement` 内部对 children 做了转义处理。如果需要渲染 HTML 字符串，必须显式使用 `dangerouslySetInnerHTML`：

```javascript
<div dangerouslySetInnerHTML={{ __html: '<b>bold</b>' }} />
// 注意：除非完全信任内容源，否则有 XSS 风险
```

### 3.18 条件渲染与列表渲染

::: details 参考

#### 条件渲染

```javascript
// 1. if 语句（不能在 JSX 里，但在组件函数里）
function Greeting({ isLoggedIn }) {
  if (isLoggedIn) {
    return <UserDashboard />
  }
  return <Login />
}

// 2. 三元表达式（最常用）
{
  isLoggedIn ? <LogoutButton /> : <LoginButton />
}

// 3. && 短路（仅显示/隐藏，没有 "else" 分支）
{
  unreadCount > 0 && <Badge count={unreadCount} />
}
// ⚠️ 陷阱：左边是 0 时会渲染 "0" 到页面上！
// count && <div/>  →  count=0 时 0 是 falsy，渲染 0
// 正确写法：count > 0 && <div/>

// 4. 复杂条件用变量 + if
let content
if (loading) {
  content = <Spinner />
} else if (error) {
  content = <Error message={error} />
} else if (items.length === 0) {
  content = <Empty />
} else {
  content = <List items={items} />
}
return <div>{content}</div>
```

#### 列表渲染

```javascript
const todos = [
  { id: 1, text: 'Learn React', done: false },
  { id: 2, text: 'Build App', done: false }
]

// map 渲染，key 必须加
;<ul>
  {todos.map((todo) => (
    <li key={todo.id}>
      <span style={{ textDecoration: todo.done ? 'line-through' : 'none' }}>{todo.text}</span>
    </li>
  ))}
</ul>
```

#### key 详解（高频面试题）

**key 的作用**：React 通过 key 判断新旧两次渲染中哪些元素是"同一个"，从而决定复用 DOM 还是销毁重建。

**为什么不能用 index？**

```javascript
// 初始列表（用 index 做 key）
;[
  { id: 'a', text: 'A' }, // key=0
  { id: 'b', text: 'B' }, // key=1
  { id: 'c', text: 'C' } // key=2
][
  // 头部插入 D 后，index 全变了
  ({ id: 'd', text: 'D' }, // key=0 (原来是 A!)
  { id: 'a', text: 'A' }, // key=1 (原来是 B!)
  { id: 'b', text: 'B' }, // key=2 (原来是 C!)
  { id: 'c', text: 'C' }) // key=3 (新 key!)
]

// React 认为：
// key=0: A → D（type 相同，更新 text，不行！应该是新节点）
// key=1: B → A（更新 text）
// key=2: C → B（更新 text）
// key=3: 新节点 → C（应该是旧节点复用！）
```

结果：所有 DOM 都被"更新"而不是"移动"，而且 C 被当成新节点重建。对于有内部 state 的组件（如输入框内容），**state 会错乱**。

```javascript
// ✅ 用稳定唯一 ID 做 key
{
  todos.map((todo) => <li key={todo.id}>{todo.text}</li>)
}

// ❌ 用 index
{
  todos.map((todo, i) => <li key={i}>{todo.text}</li>)
}
```

**什么时候 index 勉强可用？**

- 列表永远不会重排序、不会在头部插入/删除
- 列表项没有内部 state 和受控 input
- 静态列表（从不会变的纯展示）

#### 常见陷阱

```javascript
// ❌ key 放在子元素上（非 map 的 return 元素）
{
  todos.map((todo) => (
    <div>
      {' '}
      {/* ← key 放这里！map 返回的第一个元素 */}
      <span key={todo.id}>{todo.text}</span> {/* ← 错了 */}
    </div>
  ))
}

// ✅ 正确
{
  todos.map((todo) => (
    <div key={todo.id}>
      <span>{todo.text}</span>
    </div>
  ))
}

// ✅ React 19: <template> 也支持 key
{
  todos.map((todo) => (
    <React.Fragment key={todo.id}>
      <span>{todo.text}</span>
      <button>Delete</button>
    </React.Fragment>
  ))
}
```

### 3.19 表单处理：受控组件 vs 非受控组件

::: details 参考

#### 受控组件（Controlled Component）

**表单的值由 React state 控制**。每次输入 → `onChange` → `setState` → 重新渲染。React 是"唯一数据源"（Single Source of Truth）。

```javascript
function ControlledForm() {
  const [email, setEmail] = useState('')
  const [password, setPassword] = useState('')

  function handleSubmit(e) {
    e.preventDefault()
    console.log({ email, password })
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        type="email"
        value={email} // 值来自 state
        onChange={(e) => setEmail(e.target.value)} // 更新 state
      />
      <input type="password" value={password} onChange={(e) => setPassword(e.target.value)} />
      <button type="submit">提交</button>
    </form>
  )
}
```

优势：

- 实时校验、实时格式化（如手机号自动加空格）
- 条件禁用提交按钮
- 动态表单字段

#### 非受控组件（Uncontrolled Component）

**表单的值由 DOM 自己管理**，React 只在需要时通过 `ref` 读取。

```javascript
function UncontrolledForm() {
  const emailRef = useRef(null)
  const passwordRef = useRef(null)

  function handleSubmit(e) {
    e.preventDefault()
    console.log({
      email: emailRef.current.value, // 需要时才读
      password: passwordRef.current.value
    })
  }

  return (
    <form onSubmit={handleSubmit}>
      <input type="email" ref={emailRef} defaultValue="user@example.com" />
      <input type="password" ref={passwordRef} />
      <button type="submit">提交</button>
    </form>
  )
}
```

#### 对比与选择

|            | 受控组件                               | 非受控组件                              |
| ---------- | -------------------------------------- | --------------------------------------- |
| 数据源     | React state                            | DOM                                     |
| 实时校验   | ✅ 容易（每次 onChange 都能校验）      | ❌ 需手动在 onChange 中处理             |
| 实时格式化 | ✅                                     | ❌                                      |
| 动态联动   | ✅                                     | ❌（需要 ref 读取）                     |
| 代码量     | 多（每个字段需要 state + onChange）    | 少                                      |
| 性能       | 每次输入触发重渲染                     | 不触发重渲染                            |
| 适用场景   | 需要即时反馈的表单（搜索框、实时校验） | 简单表单、提交时才读取、集成非 React 库 |

> 大多数情况下用受控组件。React 19 的 `useActionState` 简化了受控表单的状态管理。

#### 常见表单元素处理

```javascript
// textarea（React 中用 value，不是 innerHTML）
<textarea value={text} onChange={e => setText(e.target.value)} />

// select（value 在 select 上，不用 option 的 selected）
<select value={fruit} onChange={e => setFruit(e.target.value)}>
  <option value="apple">苹果</option>
  <option value="banana">香蕉</option>
</select>

// 多选
<select multiple value={selectedFruits} onChange={e =>
  setSelectedFruits(Array.from(e.target.selectedOptions, o => o.value))
} />

// checkbox
<input type="checkbox" checked={agree} onChange={e => setAgree(e.target.checked)} />

// radio
<input type="radio" name="gender" value="male"
  checked={gender === 'male'} onChange={e => setGender(e.target.value)} />
```

### 3.20 React Refs 详解

::: details 参考

#### useRef vs useState

```javascript
function Timer() {
  const [count, setCount] = useState(0)
  const intervalRef = useRef(null) // 不会触发重渲染
  const countRef = useRef(count) // 存最新值的"盒子"

  // 同步最新 count 到 ref
  countRef.current = count

  useEffect(() => {
    intervalRef.current = setInterval(() => {
      // 用 ref.current 拿最新值，避免闭包陷阱
      setCount(countRef.current + 1)
    }, 1000)
    return () => clearInterval(intervalRef.current)
  }, [])

  return <div>{count}</div>
}
```

|          | useState           | useRef                                                |
| -------- | ------------------ | ----------------------------------------------------- |
| 值变化时 | 触发重新渲染       | **不触发**重新渲染                                    |
| 渲染期间 | 值不变             | 最新值立刻拿                                          |
| 典型用途 | 影响 UI 的数据     | DOM 引用、定时器 ID、缓存最新值、不需要驱动渲染的变量 |
| 可变性   | 不可变（必须 set） | 可变（直接 `.current =` 修改）                        |

#### forwardRef —— 把 ref 传给子组件

```javascript
// 父组件
const inputRef = useRef(null)
;<CustomInput ref={inputRef} />

function focusInput() {
  inputRef.current?.focus()
}

// 子组件（React 18 及以前需要 forwardRef）
const CustomInput = React.forwardRef((props, ref) => {
  return <input ref={ref} {...props} />
})

// React 19：ref 作为普通 prop，不需要 forwardRef
function CustomInput({ ref, ...props }) {
  return <input ref={ref} {...props} />
}
```

#### useImperativeHandle —— 限制子组件暴露给父的 API

子组件可能有很多内部 ref，但只想暴露特定方法给父组件调用：

```javascript
const FancyInput = React.forwardRef((props, ref) => {
  const inputRef = useRef(null)
  const [focused, setFocused] = useState(false)

  // 只暴露这两个方法
  useImperativeHandle(ref, () => ({
    focus: () => inputRef.current?.focus(),
    select: () => inputRef.current?.select()
    // 不暴露 inputRef、focused 等内部实现
  }))

  return (
    <input
      ref={inputRef}
      onFocus={() => setFocused(true)}
      onBlur={() => setFocused(false)}
      className={focused ? 'focused' : ''}
    />
  )
})

// 父组件
const ref = useRef(null)
ref.current?.focus() // ✅ 只能调 focus，不能访问内部的 inputRef
```

#### Callback Ref —— ref 的另一种形式

```javascript
function MeasureExample() {
  const [height, setHeight] = useState(0)

  // callback ref：在 DOM 挂载/更新/卸载时被调用
  const measuredRef = useCallback((node) => {
    if (node !== null) {
      setHeight(node.getBoundingClientRect().height)
    }
  }, [])

  return (
    <>
      <div ref={measuredRef}>动态内容</div>
      <p>高度: {height}px</p>
    </>
  )
}
```

Callback ref vs 普通 ref：

|          | `useRef(null)` + `ref={ref}`   | Callback ref                                      |
| -------- | ------------------------------ | ------------------------------------------------- |
| 挂载时   | `ref.current` 被赋值           | `(node) => {...}` 被调用                          |
| 卸载时   | `ref.current` 被置为 null      | 传入 `null`                                       |
| 更新时   | 无回调（引用的还是同一个 DOM） | **再次被调用**（先传 null 清旧引用，再传新 node） |
| 使用场景 | 访问 DOM、保存可变值           | **测量布局**、需要感知 ref 变化的场景             |

#### ref 在列表中的使用

```javascript
const itemsRef = useRef({}) // { [id]: DOMNode }

{
  items.map((item) => (
    <div
      key={item.id}
      ref={(el) => {
        itemsRef.current[item.id] = el
      }}
    >
      {item.name}
    </div>
  ))
}

// 滚动到某个 item
function scrollToItem(id) {
  itemsRef.current[id]?.scrollIntoView({ behavior: 'smooth' })
}
```

### 3.21 Portals（createPortal）

::: details 参考

#### 是什么？

Portal 将子组件渲染到**父组件 DOM 树之外**的 DOM 节点中。但 React 组件树层级不变——事件冒泡、Context 照样正常工作。

```javascript
import { createPortal } from 'react-dom'

function Modal({ children, onClose }) {
  return createPortal(
    <div className="overlay" onClick={onClose}>
      <div className="modal" onClick={(e) => e.stopPropagation()}>
        {children}
      </div>
    </div>,
    document.body // ← 渲染到 body 下，而不是调用方所在的 DOM 层级
  )
}

// 使用
function App() {
  const [show, setShow] = useState(false)
  return (
    <div>
      <button onClick={() => setShow(true)}>打开弹窗</button>
      {show && (
        <Modal onClose={() => setShow(false)}>
          <p>我是弹窗内容</p>
        </Modal>
      )}
    </div>
  )
}
// Modal 的 DOM 在 body 下，但事件冒泡和 Context 仍在 App 的组件树中生效
```

#### 使用场景

| 场景                        | 为什么需要 Portal                                  |
| --------------------------- | -------------------------------------------------- |
| **Modal / Dialog / Drawer** | 避免被父元素的 `overflow: hidden` / `z-index` 裁剪 |
| **Tooltip / Popover**       | 需要定位到视口任意位置，不受父容器限制             |
| **Dropdown**                | 下拉菜单经常被父元素的 `overflow` 截断             |
| **Toast / Notification**    | 需要固定在视口边缘，在 DOM 最顶层                  |
| **全局加载遮罩**            | 覆盖整个页面                                       |

#### 与 Vue Teleport 的对比

React 的 `createPortal` 和 Vue 3 的 `<Teleport>` 本质相同——都是"逻辑在组件树内，DOM 渲染到别处"。区别在于：

- React 是 **JS 函数调用**：`createPortal(jsx, domNode)`
- Vue 是 **声明式组件**：`<Teleport to="body"><Modal/></Teleport>`

### 3.22 React 组件通信方式全景

::: details 参考

| 场景                   | 方案                                       | 适用关系            |
| ---------------------- | ------------------------------------------ | ------------------- |
| 父 → 子                | **props**                                  | 父子                |
| 父 → 子（嵌套）        | **children prop / 组件组合**               | 避免 props drilling |
| 子 → 父                | **回调函数 prop**（`onXxx`）               | 父子                |
| 父获取子数据和调用方法 | **ref + forwardRef + useImperativeHandle** | 父子                |
| 祖先 → 后代            | **Context**                                | 祖先-任意后代       |
| 兄弟（同父）           | **状态提升**到公共父组件                   | 兄弟                |
| 任意组件               | **Zustand / Redux / Jotai** 状态管理库     | 任意                |
| 任意组件               | **URL 参数**（路由 query / params）        | 跨页面              |
| 任意组件               | **Event Emitter**（不推荐——难以追踪）      | 任意                |
| 任意组件               | **localStorage / sessionStorage**          | 跨页面 / 跨标签页   |

#### 各方案具体使用

**1. Props + 回调（父子）**

```javascript
function Parent() {
  const [value, setValue] = useState('')
  return <Child value={value} onChange={setValue} />
}
function Child({ value, onChange }) {
  return <input value={value} onChange={(e) => onChange(e.target.value)} />
}
```

**2. Context（跨层级）**

```javascript
const ThemeContext = createContext('light')

function App() {
  const [theme, setTheme] = useState('light')
  return (
    <ThemeContext.Provider value={{ theme, setTheme }}>
      <DeepChild /> {/* 任意层级 */}
    </ThemeContext.Provider>
  )
}

function DeepChild() {
  const { theme, setTheme } = useContext(ThemeContext)
  return <button onClick={() => setTheme(theme === 'light' ? 'dark' : 'light')}>{theme}</button>
}
```

**3. 状态提升（兄弟通信）**

```javascript
// 两个兄弟组件共享搜索词
function Parent() {
  const [keyword, setKeyword] = useState('')

  return (
    <>
      <SearchBar keyword={keyword} onChange={setKeyword} />
      <SearchResults keyword={keyword} />
    </>
  )
}
```

**4. 组合（composition）——避免 props drilling**

```javascript
// ❌ props drilling：A → B → C
function A() {
  return <B user={user} />
}
function B({ user }) {
  return <C user={user} />
} // B 自己不用 user
function C({ user }) {
  return <div>{user.name}</div>
}

// ✅ 组合：A 直接包含 C
function A() {
  return (
    <Layout right={<UserInfo user={user} />}>
      <MainContent />
    </Layout>
  )
}
function Layout({ children, right }) {
  return (
    <div className="layout">
      <main>{children}</main>
      <aside>{right}</aside>
    </div>
  )
}
```

#### 通信方案选择决策树

```
需要通信的组件关系？
  ├─ 父子 → props + 回调函数
  ├─ 父子（需要调用子组件方法） → ref + useImperativeHandle
  ├─ 祖先后代（跨很多层） → Context 或 组件组合
  ├─ 兄弟 → 状态提升到公共父组件
  ├─ 跨页面 → URL 参数 / 状态管理库
  └─ 全局共享状态 → Zustand（首选）/ Redux（大型团队）
       ├─ 服务端数据 → React Query / SWR
       ├─ UI 状态（主题/语言） → Context
       └─ 表单状态 → 留在组件本地
```

#### React Testing Library 核心理念

> "测试你的组件应该像用户使用它们一样，而不是测试实现细节。"

- 不测 state / props / 内部方法调用
- 测渲染结果、用户交互后的变化
- 通过文本/role/label 查找元素（模拟用户）

```javascript
import { render, screen, fireEvent, waitFor } from '@testing-library/react'
import userEvent from '@testing-library/user-event'
import Counter from './Counter'

describe('Counter', () => {
  // 基础渲染
  it('renders initial count', () => {
    render(<Counter />)

  })

  // 用户交互
  it('increments on button click', async () => {
    const user = userEvent.setup()
    render(<Counter />)
    await user.click(screen.getByRole('button', { name: '+' }))
    expect(screen.getByText('Count: 1')).toBeInTheDocument()

})
```

按照 RTL 推荐的使用顺序：

| ------ | ---------------------- | ----------------------------------- |
| 1      | `getByRole`            | 最推荐——模拟辅助技术查找方式        |
| 2      | `getByLabelText`       | 表单字段首选                        |
| 3      | `getByPlaceholderText` | 仅在没有 label 时用                 |
| 4      | `getByText`            | 非交互文本                          |
| 5      | `getByDisplayValue`    | 表单当前值                          |
| 6      | `getByAltText`         | 图片                                |
| 7      | `getByTitle`           | 不推荐                              |
| 8      | `getByTestId`          | **最后手段**（加 data-testid 属性） |

```javascript
// 按 Role 查找

screen.getByRole('heading', { level: 1 })
```

### 3.24 React SSR 与 Next.js 深入

::: details 参考

#### React SSR 实现原理

```javascript
// server.js
import { renderToString, renderToPipeableStream } from 'react-dom/server'
import express from 'express'

const app = express()

app.get('*', async (req, res) => {
  // React 18 推荐流式渲染
  const { pipe } = renderToPipeableStream(<App />, {
    bootstrapScripts: ['/client-bundle.js'],
    onShellReady() {
      res.setHeader('Content-Type', 'text/html')
      pipe(res)
    }
  })
})
```

#### CSR → SSR → SSG → ISR 演进

| 渲染模式 | 渲染时机              | 首屏 | SEO  | 实时性 | 服务器    |
| -------- | --------------------- | ---- | ---- | ------ | --------- |
| **CSR**  | 客户端                | 慢   | 差   | 实时   | 不需要    |
| **SSR**  | 每次请求              | 快   | 好   | 实时   | 需要 Node |
| **SSG**  | 构建时                | 最快 | 最好 | 不实时 | 不需要    |
| **ISR**  | 构建时 + 按需重新生成 | 快   | 好   | 准实时 | 需要      |

#### Next.js App Router（React 全栈框架）

**核心概念：**

```
app/
├── layout.js      ← 布局（嵌套，持久化，不重新渲染）
├── page.js        ← 页面
├── loading.js     ← Suspense fallback（页面加载中）
├── error.js       ← Error Boundary（错误时展示）
├── not-found.js   ← 404 页面
└── api/           ← API Routes（服务端接口）
```

**三种组件类型：**

```javascript
// 1. Server Component（默认）—— 代码不发送到浏览器
async function PostPage({ params }) {
  const post = await db.post.findUnique({ where: { id: params.id } });
  // 此处直接查数据库，无需 fetch API！
  return (
    <div>
      <h1>{post.title}</h1>
      <p>{post.content}</p>
      <LikeButton postId={post.id} /> {/* Client Component */}
    </div>
  );
}

// 2. Client Component（'use client'）—— 与 React SPA 写法和能力一致
'use client';
function LikeButton({ postId }) {
  const [liked, setLiked] = useState(false);
  async function handleLike() {
    setLiked(true);
    await fetch(`/api/posts/${postId}/like`, { method: 'POST' });
  }
  return <button onClick={handleLike}>{liked ? '❤️' : '🤍'}</button>;
}

// 3. Server Action —— 直接从组件调用服务端函数，无需 API 路由
async function updateProfile(formData: FormData) {
  'use server';
  const name = formData.get('name');
  await db.user.update({ where: { id: userId }, data: { name } });
  revalidatePath('/profile');
}

function EditForm() {
  return (
    <form action={updateProfile}>
      <input name="name" />
      <button type="submit">保存</button>
    </form>
  );
}
```

#### Hydration 过程中的常见问题

```
1. 服务端生成 HTML → 发送给浏览器
2. 浏览器展示 HTML（可见，不可交互）
3. 下载并执行 JS Bundle
4. Hydrate：React 将事件监听器等"激活"到已有 DOM 上
5. 页面可交互
```

**Hydration 失败原因**：

- 服务端/客户端渲染结果不一致（`typeof window !== 'undefined'` 判断不当）
- 使用了 `Math.random()`、`Date.now()` 等不确定值
- 第三方库在服务端不可用

**解决**：`useEffect` 中的代码只在客户端执行；`next/dynamic` 关闭 SSR：

```javascript
import dynamic from 'next/dynamic'
const Chart = dynamic(() => import('./Chart'), { ssr: false })
```

#### Next.js 总结

| 特性              | 说明                                           |
| ----------------- | ---------------------------------------------- |
| 文件路由          | `app/` 目录结构即路由                          |
| Server Components | 默认，零 JS 体积，直接访问数据库               |
| 流式渲染          | `loading.js` → Suspense fallback，渐进式传输   |
| Server Actions    | 无需 API 路由，直接从组件调用服务端函数        |
| 增量静态再生(ISR) | 构建后可按需重新生成页面                       |
| 中间件            | 请求到达前执行（鉴权、重定向、A/B 测试）       |
| 缓存策略          | 全链路可配置（fetch 级别、页面级别、路由级别） |

## 4 多端开发

### 4.1 单页面应用（SPA）的原理和优缺点，掌握一种快速开发SPA的方案

::: details 参考

#### 原理

SPA 只有一个 HTML 页面，通过 JS 动态切换内容，依靠**前端路由**模拟页面跳转。

核心机制：

- **Hash 模式**：监听 `hashchange` 事件，切换组件而不刷新页面
- **History 模式**：`history.pushState()` 改变 URL + `popstate` 事件监听，需服务端重定向支持

#### 优缺点

| 优点                              | 缺点                                           |
| --------------------------------- | ---------------------------------------------- |
| 页面切换快，用户体验流畅          | 首屏加载时间长（需加载整个 JS Bundle）         |
| 前后端分离，并行开发              | SEO 困难（SPA 内容由 JS 渲染，爬虫可能抓不到） |
| 局部刷新，减少服务端压力          | 浏览器后退/前进需自行管理滚动位置等状态        |
| 可离线使用（配合 Service Worker） | 内存管理：长期不卸载的页面容易内存泄漏         |

#### 快速开发方案

- **Vite + Vue 3 + Vue Router**：脚手架 `npm create vue@latest`，开箱即用
- **Create React App / Vite + React Router**：快速启动
- **非框架方案**：ajax + `history.pushState` + `popstate` 实现简易 SPA

#### MPA vs SPA 选型

- ToC 营销页面、内容型网站、强 SEO 需求 → MPA 或 SSR/SSG
- 后台管理系统、SaaS 工具、交互密集型 → SPA
- 折中方案：Nuxt/Next 的 SSR/SSG + 客户端 Hydration

### 4.2 理解Viewport、em、rem的原理和用法，分辨率、px、ppi、dpi、dp的区别和实际应用

::: details 参考

#### Viewport（视口）

移动浏览器会将页面渲染在一个虚拟的"窗口"（layout viewport）中，然后缩放显示。

```html
<!-- 核心 meta 标签 -->
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
```

| Viewport 类型   | 说明                                   |
| --------------- | -------------------------------------- |
| Layout Viewport | 页面布局的虚拟宽度（默认 980px）       |
| Visual Viewport | 屏幕当前可见区域                       |
| Ideal Viewport  | 设备独立像素宽度（iPhone 14 为 390px） |

#### px / em / rem

| 单位  | 说明                                                                                                  |
| ----- | ----------------------------------------------------------------------------------------------------- |
| `px`  | 设备上的一个物理像素点（CSS 像素≠物理像素，见下文）                                                   |
| `em`  | 相对于**父元素**的 `font-size`，如父元素 `font-size: 16px`，则 `2em = 32px`，会层层继承，嵌套时难控制 |
| `rem` | 相对于**根元素 `<html>`** 的 `font-size`，整个页面统一基准                                            |

```css
html {
  font-size: 16px;
}
.box {
  width: 10rem;
} /* 160px */
.box {
  font-size: 1.5em;
} /* 24px，相对父元素 */
```

#### 分辨率 / ppi / dpi / dp

| 概念                | 全称                     | 解释                                                                      |
| ------------------- | ------------------------ | ------------------------------------------------------------------------- |
| 分辨率 (Resolution) | —                        | 屏幕的物理像素点数，如 2532×1170（iPhone 14）                             |
| ppi                 | Pixels Per Inch          | 每英寸物理像素数，反映屏幕细腻度，越高越清晰                              |
| dpi                 | Dots Per Inch            | 打印领域术语，每英寸点数，在 Android 开发中也用于表示屏幕密度             |
| dp (dip)            | Device-independent Pixel | Android 抽象单位，1dp = 1/160 英寸，与物理像素解耦                        |
| CSS 像素 (逻辑像素) | —                        | 浏览器使用的抽象像素，1 CSS px 对应多少物理像素由 `devicePixelRatio` 决定 |

#### 设备像素比（devicePixelRatio, dpr）

`dpr = 物理像素 / CSS 像素`

- iPhone 14：dpr = 3，1 CSS px = 3×3 = 9 个物理像素
- 普通显示器：dpr = 1

这意味着 100×100 CSS px 的图片在 Retina 屏幕上需要 300×300 物理像素才能清晰：

```css
/* 解决高清屏图片模糊 */
.logo {
  background: url('logo@2x.png'); /* 200px 图显示为 100px */
  background-size: 100px 100px;
}
```

#### 实际应用

- `rem` + 动态设置根字体大小 → 移动端适配（lib-flexible 方案）
- `vw` / `vh` → 更直接的比例布局
- `em` → 组件内部的相对间距，如按钮 padding 相对文字大小
- `dpr` → 高清屏适配（1px 边框问题 → `transform: scale(0.5)`）

:::

### 4.3 移动端页面适配解决方案、不同机型适配方案

::: details 参考

#### 适配核心问题

不同手机的屏幕宽度、dpr 各不相同，需要一套方案让页面在不同设备上**等比缩放**，视觉效果一致。

#### 主流方案对比

| 方案                     | 原理                                                       | 代表                           | 优点                   | 缺点                                |
| ------------------------ | ---------------------------------------------------------- | ------------------------------ | ---------------------- | ----------------------------------- |
| **rem + 动态 font-size** | 设置 `html{font-size}` = 屏幕宽度 / 10，页面所有尺寸用 rem | lib-flexible + postcss-pxtorem | 等比缩放简单           | 需要转换工具，对第三方组件不友好    |
| **vw/vh**                | 直接使用视口单位                                           | postcss-px-to-viewport         | 原生 CSS 单位，无需 JS | 超大屏幕元素过大，需 min-width 限宽 |
| **媒体查询**             | 不同断点写不同 CSS                                         | Bootstrap 方案                 | 灵活控制               | 代码量大，难以覆盖所有设备          |
| **scale 缩放**           | 固定设计稿宽度，等比缩放整个页面                           | 简单 H5 活动页                 | 极简，所有内容自动缩放 | 交互（点击、字体）可能异常          |

#### rem 方案实现

```javascript
// flexible.js 核心逻辑
;(function () {
  const docEl = document.documentElement
  function setRemUnit() {
    const width = docEl.clientWidth
    // 设计稿宽度 375，1rem = 37.5px（375/10）
    docEl.style.fontSize = width / 10 + 'px'
  }
  setRemUnit()
  window.addEventListener('resize', setRemUnit)
})()

// 使用时配合 PostCSS px → rem
// 设计稿 375px 宽，div 宽 100px → 编译后 2.667rem
```

```javascript
  plugins: {
    'postcss-px-to-viewport': {
      viewportWidth: 375, // 设计稿宽度
      unitPrecision: 5,
      viewportUnit: 'vw'
    }
  }
```

1. **1px 边框**：dpr=2 的屏幕上 1px CSS = 2px 物理像素，用伪元素 + `transform: scale(0.5)` 实现真正的 1 物理像素边框

### 4.4 掌握一种JavaScript移动客户端开发技术，如React Native：可以搭建React Native开发环境，熟练进行开发，可理解React Native的运作原理，不同端适配

::: details 参考

#### React Native 运作原理

RN 的三层架构：

```
┌──────────────────┐
│   JS 代码（业务逻辑）  │  ← React 组件、状态管理、路由
├──────────────────┤
│   Bridge（通信桥）    │  ← 序列化的 JSON 消息：{"module":"RCTView","method":"setProps",...}
├──────────────────┤
│   Native 层         │  ← iOS (ObjC/Swift) / Android (Java/Kotlin) 原生组件渲染
└──────────────────┘
```

JS 线程 → Bridge（异步、批处理）→ Native 线程。所有 JS ↔ Native 通信都经过 Bridge 序列化，这是性能瓶颈的来源。

**新架构（React Native 0.68+）**：

- **JSI（JavaScript Interface）**：替代 Bridge，允许 JS 直接调用 Native 方法（类似 WebAssembly），无需 JSON 序列化
- **Fabric**：新的渲染引擎，替代 UI Manager
- **Turbo Modules**：按需加载原生模块
- **Codegen**：静态类型生成，确保 JS 和 Native 类型一致

#### 环境搭建

```
npx @react-native-community/cli init MyApp  // 完整环境（需 Xcode/Android Studio）
npx create-expo-app MyApp                   // Expo 托管（无需原生开发环境，推荐新手）
```

#### 与 Web 开发的对比

|          | React (Web)            | React Native                              |
| -------- | ---------------------- | ----------------------------------------- |
| 基础组件 | `<div>` `<span>` `<p>` | `<View>` `<Text>` `<Image>`               |
| 样式     | CSS                    | `StyleSheet.create({})`，Flexbox 默认布局 |
| 路由     | React Router           | `@react-navigation/native`                |
| 存储     | localStorage           | AsyncStorage                              |
| 网络     | fetch/axios            | fetch/axios                               |

#### 不同端适配

- **Platform 模块**：`import { Platform } from 'react-native'; Platform.OS === 'ios'`
- **Platform.select()**：`Platform.select({ ios: ..., android: ..., default: ... })`
- **平台文件扩展**：`Button.ios.js` / `Button.android.js`
- **SafeAreaView**：处理刘海屏安全区
- **Dimensions / useWindowDimensions**：获取屏幕尺寸，响应式布局

#### 性能注意事项

- 减少 Bridge 通信频率（如 `onScroll` 用 `Animated` 在 Native 线程处理）
- 长列表使用 `FlatList` 而非 `ScrollView`（虚拟列表）
- 避免在渲染中创建匿名函数

### 4.5 掌握一种JavaScript PC客户端开发技术，如Electron：可搭建Electron开发环境，熟练进行开发，可理解Electron的运作原理

::: details 参考

#### Electron 架构

```
┌────────────────────────────┐
│ Main Process (Node.js)     │ ← 唯一的，管理窗口、系统交互、文件系统
│ - BrowserWindow 管理       │
│ - Tray、Menu、dialog       │
│ - ipcMain 通信             │
├────────────────────────────┤
│ Renderer Process (Chromium)│ ← 每个窗口一个，运行 Web 页面
│ - HTML/CSS/JS              │
│ - 默认无法访问 Node.js API  │
│ - ipcRenderer 通信         │
├────────────────────────────┤
│ Preload Script             │ ← 桥梁，通过 contextBridge 暴露安全 API
└────────────────────────────┘
```

#### 进程通信（IPC）

```javascript
// 主进程（main.js）
import { app, BrowserWindow, ipcMain } from 'electron'

ipcMain.handle('read-file', async (event, path) => {
  return fs.readFileSync(path, 'utf-8')
})

// Preload（preload.js）
import { contextBridge, ipcRenderer } from 'electron'
contextBridge.exposeInMainWorld('electronAPI', {
  readFile: (path) => ipcRenderer.invoke('read-file', path)

// 渲染进程（renderer.js）

```

3. **禁用 `remote` 模块**：`@electron/remote` 已废弃
4. **Preload 使用 `contextBridge`**：不暴露整个 `ipcRenderer`
5. **沙箱模式**：`sandbox: true`（macOS App Store 要求）

- **更新**：使用 `electron-updater` 实现自动更新
- **打包**：使用 `electron-builder` 打包为 Windows/macOS/Linux 安装包
- **性能**：渲染进程占用高用 `BrowserView` 替代 `webview`；减少主进程同步操作

### 4.6 掌握一种小程序开发框架或原生小程序开发

::: details 参考

#### 小程序架构

小程序运行在**双线程模型**上：

```
┌──────────────┐     ┌──────────────┐
│  渲染层 (WebView) │     │  逻辑层 (JSCore)  │
│  - WXML/WXSS     │ ←→ │  - JS 业务逻辑    │
│  - 多个页面各一个   │     │  - 全局唯一       │
```

- 渲染层和逻辑层分离，操作 DOM 受限（没有 `window`、`document`）

| **Taro**    | JD 开源        | React/Vue 语法可转 H5/RN/各小程序 | 编译产物复杂，部分 API 有坑   |
| **uni-app** | DCloud         | Vue 语法，生态完善(HBuilderX)     | QQ/头条小程序适配不如微信完善 |
| WePY        | 腾讯           | 类 Vue 2 语法                     | 更新缓慢，社区不活跃          |
| mpvue       | 美团           | Vue 2 语法                        | 已停止维护                    |

### 4.7 理解多端框架的内部实现原理，至少了解一个多端框架的使用

::: details 参考

#### 多端框架的通用原理

多端框架（Taro、uni-app）的核心目标是：**一套代码编译为多端可运行产物**。实现方式主要有两种：

**1. 编译时转换（Taro 1/2、uni-app 的 vue-loader ）**

```
源码（React/Vue）
  → 解析为 AST
  → 转换为小程序模板语法（WXML/WXSS/JS）
  → 输出小程序代码包
```

**2. 运行时适配（Taro 3、Rax）**

```
源码（React/Vue）
  → 保持原始语法
  → 运行时通过自定义 DOM/BOM API 适配层
  → 在各端模拟浏览器环境运行
```

#### Taro 3 架构详解

Taro 3 采用**运行时方案**，核心是一套跨平台的适配器：

```
React/Vue 代码
    ↓
Taro Runtime（模拟浏览器 API）
    ├── DOM 层：document.createElement → 创建 TaroElement
    ├── BOM 层：window/navigator 模拟
    ├── Events 层：合成事件系统
    └── 渲染适配器：
        ├── H5 适配器 → 直接操作真实 DOM
        ├── 小程序适配器 → setData 驱动模板
        └── RN 适配器 → 映射到 RN 组件
```

核心原理：在编译时将 `View`、`Text` 等跨平台组件编译为对应平台的组件标签，运行时通过 `TaroElement` 模拟 DOM 树，最终由各端适配器渲染。

#### 关键特性

| 特性               | 说明                                                          |
| ------------------ | ------------------------------------------------------------- |
| Taro.createElement | 替代 `React.createElement`，创建可跨端的虚拟 DOM              |
| Taro.nextTick      | 替代 `Promise.resolve()`，适配小程序 setData 异步更新         |
| 条件编译           | `if (process.env.TARO_ENV === 'weapp')` 或注释 `/* #ifdef */` |
| 多端组件库         | `@tarojs/components` 中的 View/Text/Image 自动映射到各端      |

#### 使用建议

- 业务偏重微信小程序 + H5 → **uni-app**（Vue 生态，HBuilderX IDE 加持）
- 偏重多端统一 + React 技术栈 → **Taro 3**（跨端一致性更好）
- 只做微信小程序且追求极致性能 → **原生开发**
- 已有 React Web 项目想转小程序 → Taro 迁移成本最低

#### 常见坑

- 小程序的双线程模型和历史限制导致部分 Web API 不可用（如 `getBoundingClientRect` 异步）
- CSS 支持度不如 Web（部分选择器、伪类不支持）
- 长列表性能：小程序端不能使用 DOM 回收，需用虚拟列表

### 5.1 掌握React和Vue传统的跨组件通信方案，对比采用数据流管理框架的异同

::: details 参考

#### Vue 跨组件通信

```javascript
// 1. Props down, Events up（父子）
<Child :data="data" @update="handleUpdate" />

// 2. provide / inject（祖先→后代，长距离注入）
provide('key', value);          // 祖先
const value = inject('key');    // 后代（任意深度）

// 3. Event Bus（任意组件，Vue 3 推荐用 mitt）
const bus = mitt();
bus.emit('event', data);
bus.on('event', handler);

// 4. $parent / $refs（访问父子组件实例）
this.$refs.child.focus();

// 5. $attrs / $listeners（透传）
<Child v-bind="$attrs" />
```

#### React 跨组件通信

```javascript
// 1. Props drilling（逐层传递，层级深了麻烦）
;<Child data={data} onUpdate={handleUpdate} />

// 2. Context（跨层级共享）
const ThemeContext = React.createContext('light')
;<ThemeContext.Provider value="dark">
  <DeepChild /> {/* 任意深度都能消费 */}
</ThemeContext.Provider>

// 3. Ref + useImperativeHandle（暴露子组件方法）
const ref = useRef()
ref.current.focus()

// 4. 回调 / Event Emitter
window.addEventListener('custom-event', handler)
```

#### 传统通信 vs 数据流管理框架

| 维度       | 传统通信               | 状态管理库（Redux/Vuex/Pinia）                     |
| ---------- | ---------------------- | -------------------------------------------------- |
| 数据流向   | 隐式，难追踪           | 显式，单向数据流，DevTools 可追踪                  |
| 状态存储   | 分散在各组件中         | 集中存储，单一数据源                               |
| 变更控制   | 任何组件都能直接改     | 通过 action/mutation 统一修改                      |
| 调试       | console.log            | 时间旅行、状态快照                                 |
| 跨模块通信 | 需要组件间建立连接     | 任何组件都能访问和修改全局状态                     |
| 适用场景   | 简单父子通信、小型项目 | 中大型项目、多模块共享状态                         |
| 学习成本   | 低                     | 中高（概念多：action/mutation/reducer/middleware） |

#### 选型原则

- 3 层以内传参 → props + events / Context
- 跨页面、跨模块共享状态 → 状态管理库
- 服务端状态（请求数据） → React Query / SWR / Pinia + 自定义 composable
- 表单、路由状态 → 留在组件本地或 URL 参数中

### 5.2 熟练使用Redux管理数据流，并理解其实现原理，中间件实现原理

::: details 参考

#### Redux 三大原则

1. **单一数据源**：整个应用的 state 存储在一棵 object tree 中，即唯一 store
2. **State 只读**：唯一改变 state 的方式是 dispatch action
3. **使用纯函数修改**：reducer 必须是纯函数：`(prevState, action) => newState`

#### 数据流

```
dispatch(action) → reducer(state, action) → new state → subscribe 的回调 → UI 更新
```

```javascript
// Action
const addTodo = (text) => ({ type: 'ADD_TODO', payload: text })

// Reducer（纯函数）
const todoReducer = (state = [], action) => {
  switch (action.type) {
    case 'ADD_TODO':
      return [...state, { text: action.payload, done: false }]
    default:
      return state
  }
}

// Store
import { createStore } from 'redux'
const store = createStore(todoReducer)
store.dispatch(addTodo('Learn Redux'))
store.subscribe(() => console.log(store.getState()))
```

#### createStore 简化实现

```javascript
function createStore(reducer, enhancer) {
  if (enhancer) return enhancer(createStore)(reducer)

  let state
  const listeners = []

  function getState() {
    return state
  }
  function dispatch(action) {
    state = reducer(state, action)
    listeners.forEach((l) => l())
    return action
  }
  function subscribe(listener) {
    listeners.push(listener)
    return () => listeners.splice(listeners.indexOf(listener), 1)
  }

  dispatch({ type: '@@INIT' }) // 初始化 state
  return { getState, dispatch, subscribe }
}
```

#### 中间件原理

中间件本质是**对 dispatch 的增强**，在 action 到达 reducer 之前做额外处理。洋葱模型：

```javascript
// 简化 applyMiddleware
function applyMiddleware(...middlewares) {
  return (createStore) => (reducer) => {
    const store = createStore(reducer)
    let dispatch = store.dispatch

    const middlewareAPI = {
      getState: store.getState,
      dispatch: (action) => dispatch(action)
    }
    // 每层中间件拿到 middlewareAPI
    const chain = middlewares.map((m) => m(middlewareAPI))
    // compose 串联：mid1(mid2(mid3(store.dispatch)))
    dispatch = compose(...chain)(store.dispatch)
    return { ...store, dispatch }
  }
}

function compose(...funcs) {
  return funcs.reduce(
    (a, b) =>
      (...args) =>
        a(b(...args))
  )
}
```

一个中间件的结构（三层柯里化）：

```javascript
const logger = (store) => (next) => (action) => {
  console.log('before', store.getState())
  const result = next(action) // 传给下一个中间件 / reducer
  console.log('after', store.getState())
  return result
}
```

#### Redux Toolkit（现代 Redux 推荐写法）

Redux Toolkit 封装了繁琐的样板代码，内置 `immer`（不可变更新）、`redux-thunk`（异步处理）：

```javascript
import { createSlice, configureStore } from '@reduxjs/toolkit'

const todoSlice = createSlice({
  name: 'todos',
  initialState: [],
  reducers: {
    addTodo(state, action) {
      state.push({ text: action.payload, done: false }) // immer 允许"可变"写法
    }
  }
})

const store = configureStore({ reducer: { todos: todoSlice.reducer } })
store.dispatch(todoSlice.actions.addTodo('Learn RTK'))
```

### 5.3 熟练使用Mobx管理数据流，并理解其实现原理，相比Redux有什么优势

::: details 参考

#### 核心概念

| 概念             | 说明                               | 装饰器 / 函数                       |
| ---------------- | ---------------------------------- | ----------------------------------- |
| Observable State | 被观察的响应式状态                 | `observable` / `makeAutoObservable` |
| Computed Values  | 派生计算值，自动缓存               | `computed`                          |
| Actions          | 修改状态的方法（建议开启严格模式） | `action`                            |
| Reactions        | 自动响应状态变化的副作用           | `autorun` / `reaction` / `when`     |

#### 使用示例

```javascript
import { makeAutoObservable, autorun } from 'mobx'

class TodoStore {
  todos = []
  filter = 'all'

  constructor() {
    makeAutoObservable(this) // 自动将属性和方法标记为 observable 和 action
  }

  get filteredTodos() {
    // computed: todos 或 filter 变化时自动重新计算
    switch (this.filter) {
      case 'done':
        return this.todos.filter((t) => t.done)
      case 'undone':
        return this.todos.filter((t) => !t.done)
      default:
        return this.todos
    }
  }

  addTodo(text) {
    this.todos.push({ text, done: false }) // 直接修改，底层 Proxy 追踪变化
  }

  setFilter(filter) {
    this.filter = filter
  }
}

const store = new TodoStore()

// 自动追踪依赖并执行
autorun(() => {
  console.log(`当前有 ${store.filteredTodos.length} 个待办`)
})

store.addTodo('Learn MobX') // 自动触发 autorun
```

#### 实现原理

MobX 用 **ES6 Proxy（或 Object.defineProperty）** 实现：

1. **拦截 get** → 收集依赖：记录"哪个 derivation（computed/reaction）依赖了哪个 observable"
2. **拦截 set** → 通知更新：找出所有依赖该 observable 的 derivation —— 交给调度器执行
3. **事务批处理**：同一事务中的多次 set 只触发一次更新（类似 Vue 的 nextTick）
4. **computed 惰性求值**：依赖不变时不会重新计算，缓存旧值

本质上是**细粒度的发布-订阅 + 依赖自动收集**，做到了"数据变了，只更新用了它的组件"。

#### MobX vs Redux

|            | Redux                                | MobX                                 |
| ---------- | ------------------------------------ | ------------------------------------ |
| 编程风格   | 函数式（纯 reducer）                 | 面向对象 / 响应式                    |
| 不可变性   | **强制**（永远返回新对象）           | 不强制（直接修改，但也可 immutable） |
| 样板代码   | 多（action + reducer + connect）     | 少（makeAutoObservable 一行）        |
| 状态更新   | 显式 dispatch → reducer → new state  | 直接赋值，自动追踪                   |
| 性能优化   | 手动（useMemo / useSelector 等）     | 自动细粒度更新                       |
| 学习曲线   | 中等                                 | 低（直觉更自然）                     |
| TypeScript | 需要额外声明                         | OOP 风格天然友好                     |
| 适用场景   | 大型团队、需要严格流程控制的复杂项目 | 追求开发效率、快速迭代、中小型项目   |

:::

### 5.4 熟练使用Vuex管理数据流，并理解其实现原理

::: details 参考

#### 实现原理（简化版 Vuex）

```javascript
class Store {
  constructor(options = {}) {
    // 用 Vue.reactive 包装 state，使其变成响应式
    this._state = reactive(options.state || {})

    // getter 用计算属性实现
    this.getters = {}
    const computedCache = {}
    Object.entries(options.getters || {}).forEach(([key, fn]) => {
      computedCache[key] = computed(() => fn(this.state, this.getters))
      Object.defineProperty(this.getters, key, {
        get: () => computedCache[key].value
      })
    })

    // mutations
    this._mutations = options.mutations || {}

    // actions（可以异步）
    const { dispatch, commit } = this
    this.dispatch = dispatch.bind(this)
    this.commit = commit.bind(this)

    this._actions = options.actions || {}
    Object.entries(this._actions).forEach(([key, fn]) => {
      this._actions[key] = fn.bind(null, this)
    })
  }

  get state() {
    return this._state
  }

  commit = (type, payload) => {
    const mutation = this._mutations[type]
    if (!mutation) throw new Error(`[vuex] unknown mutation type: ${type}`)
    mutation(this.state, payload)
  }

  dispatch = (type, payload) => {
    const action = this._actions[type]
    if (!action) throw new Error(`[vuex] unknown action type: ${type}`)
    return Promise.resolve(action(payload))
  }
}
```

核心要点：

- State → `reactive` 包裹（Vue 2 用 `new Vue({ data })`），实现响应式
- Getters → `computed` 包裹，带缓存
- Mutations → 直接修改 state（必须是同步的，保证 DevTools 快照可追踪）
- Actions → 可以异步，调用 commit 修改 state

#### 手写一个简易 Canvas 图表

```javascript
class SimpleChart {
  constructor(canvas) {
    this.ctx = canvas.getContext('2d')
    this.width = canvas.width
    this.height = canvas.height
  }

  drawBarChart(data, options = {}) {
    const { padding = 40, barColor = '#5470c6' } = options
    const ctx = this.ctx
    const maxVal = Math.max(...data.map((d) => d.value))
    const barWidth = ((this.width - padding * 2) / data.length) * 0.6
    const gap = ((this.width - padding * 2) / data.length) * 0.4

    ctx.clearRect(0, 0, this.width, this.height)

    data.forEach((item, i) => {
      const barH = (item.value / maxVal) * (this.height - padding * 2)
      const x = padding + i * (barWidth + gap)
      const y = this.height - padding - barH

      ctx.fillStyle = barColor
      ctx.fillRect(x, y, barWidth, barH)
      // 标签
      ctx.fillStyle = '#333'
      ctx.font = '12px sans-serif'
      ctx.textAlign = 'center'
      ctx.fillText(item.label, x + barWidth / 2, this.height - 10)
    })
  }
}
```

### 6.5 工具函数库，如lodash、underscore、moment等，理解使用的工具类或工具函数的具体实现原理

::: details 参考

#### Lodash 常用方法及实现原理

```javascript
// 1. debounce（防抖）：高频触发，只执行最后一次
function debounce(fn, delay) {
  let timer = null
  return function (...args) {
    clearTimeout(timer)
    timer = setTimeout(() => fn.apply(this, args), delay)
  }
}

// 2. throttle（节流）：固定间隔执行
function throttle(fn, interval) {
  let lastTime = 0
  return function (...args) {
    const now = Date.now()
    if (now - lastTime >= interval) {
      lastTime = now
      fn.apply(this, args)
    }
  }
}

// 3. cloneDeep（深拷贝）
function cloneDeep(obj, cache = new WeakMap()) {
  if (typeof obj !== 'object' || obj === null) return obj
  if (cache.has(obj)) return cache.get(obj) // 循环引用处理

  const clone = Array.isArray(obj) ? [] : {}
  cache.set(obj, clone)

  // 递归拷贝（不拷贝原型链上的属性）
  for (const key of Object.keys(obj)) {
    clone[key] = cloneDeep(obj[key], cache)
  }
  return clone
}

// 4. get / set （安全访问嵌套属性）
function get(obj, path, defaultValue) {
  const keys = Array.isArray(path) ? path : path.split('.')
  let result = obj
  for (const key of keys) {
    if (result == null) return defaultValue
    result = result[key]
  }
  return result ?? defaultValue
}
get({ a: { b: { c: 42 } } }, 'a.b.c') // 42
get({ a: {} }, 'a.b.c', 'N/A') // 'N/A' 不会报错
```

Moment.js 已经进入维护状态（不再新增功能），推荐使用更轻量的替代方案：

| 库                      | 说明                                       |
| ----------------------- | ------------------------------------------ |
| **Day.js**              | 2KB，API 与 Moment 几乎一致，不可变+插件化 |
| **date-fns**            | 函数式，按需引入，Tree Shaking 友好        |

#### 前端工具库选型趋势

1. **能用原生 API 就原生**：ES6+ 提供了 `Array.prototype.flat`/`flatMap`/`includes`、`Object.entries`/`fromEntries`、`??`/`?.` 等
2. **lodash → lodash-es**：ES Module 版本，Tree Shaking 友好
3. **Moment → Day.js / date-fns**：体积从 70KB+ 降到 2KB
4. **工具函数原则**：不引入整个库只为一个函数；如果只用 1-2 个，自己写或复制源码

- **XHR/fetch Breakpoint**：按 URL 片段断点，拦截特定 API 请求

#### Network 面板时序分析

```
Queueing        排队等待（HTTP/1.1 连接数限制或域名并发限制）
Stalled         等待可用连接
DNS Lookup      DNS 解析
Initial Connection  TCP 握手 + SSL 协商
Request sent    发送请求
Waiting (TTFB)  等待服务器首字节
Content Download 下载响应体
```

#### Performance 面板的火焰图读法

- **宽度** = 执行时长，越宽越慢
- **Y 轴** = 调用栈深度，从下到上是父→子的调用关系
- **红色三角** = 长任务（Long Task），可能导致掉帧
- 重点关注 Self Time（函数自身耗时）高的函数进行优化

:::

### 7.2 熟练使用一种代理工具实现请求代理、抓包，如charls

::: details 参考

> 注意：题目中 "charls" 应为 **Charles**，是一款常用的 HTTP 调试代理工具。

#### Charles 核心功能

| 功能                | 说明                                                 |
| ------------------- | ---------------------------------------------------- |
| **HTTP/HTTPS 抓包** | 查看所有请求和响应的详细信息（Header、Body、Cookie） |
| **Map Local**       | 将线上请求映射到本地文件，调试代码不改服务器         |
| **Map Remote**      | 将请求重定向到另一个 URL                             |
| **Breakpoints**     | 在请求/响应时中断，可手动修改数据                    |
| **Rewrite**         | 自动替换请求/响应中的内容                            |
| **Throttle**        | 模拟慢网络（3G/4G/自定义带宽）                       |
| **SSL 代理**        | 解密 HTTPS 流量（需安装 Charles 根证书）             |
| **Repeat**          | 重放请求，不需刷新页面                               |

#### HTTPS 抓包原理（中间人代理）

```
客户端 ←→ [Charles Proxy] ←→ 服务器

1. Charles 作为中间人代理
2. 客户端请求 → Charles 收到，用 Charles 的证书加密 → 发给服务器
3. 服务器响应 → Charles 收到，用 Charles 的证书加密 → 发给客户端
4. 客户端需要信任 Charles 的根证书，否则会提示"不受信任"
```

#### Map Local（代理本地文件）

```
线上: https://cdn.example.com/app.js → 本地: /Users/me/dev/app.js

场景: 调试线上 Bug，不部署代码就能验证修复
```

#### 常用替代方案

| 工具                | 平台                           | 特点                                |
| ------------------- | ------------------------------ | ----------------------------------- |
| **Charles**         | macOS/Windows/Linux            | 老牌，付费，功能全面                |
| **Fiddler**         | Windows（Everywhere 版跨平台） | Windows 首选                        |
| **Proxyman**        | macOS                          | UI 现代、原生 macOS 设计            |
| **mitmproxy**       | 全平台                         | 命令行、可编程、开源                |
| **Whistle**         | 全平台（Node.js）              | 国人开发，插件丰富，推荐            |
| **Chrome DevTools** | 浏览器内置                     | Overrides 可替代部分 Map Local 功能 |

#### 移动端抓包

1. 电脑（Charles/Fiddler）与手机在同一 Wi-Fi
2. 手机设置代理 → 指向电脑 IP + 代理端口（Charles 默认 8888）
3. 手机安装并信任代理工具的 SSL 证书
4. HTTPS 请求即可在电脑上看到明文

:::

### 7.4 了解Vue、React等框架调试工具的使用

::: details 参考

#### Vue DevTools

**安装**：Chrome / Firefox 扩展商店搜索 "Vue.js devtools"

**核心面板：**

| 面板           | 功能                                                    |
| -------------- | ------------------------------------------------------- |
| **Components** | 组件树、每个组件的 data/props/computed、可实时修改值    |
| **Timeline**   | 性能：组件渲染时间线、事件调用时间线（Vue DevTools 6+） |
| **Pinia**      | Pinia Store 的状态查看与修改（需 Pinia DevTools 插件）  |
| **Router**     | 路由信息查看（需集成）                                  |
| **Settings**   | 配置：是否在 Console 中显示组件名等                     |

**使用技巧：**

- 在 Components 面板中选中组件 → 右侧可编辑 `data`/`props` 实时看到 UI 变化
- Timeline → 可录制用户操作，回放组件渲染过程，定位不必要的渲染
- Console 中 `$vm0` 引用 Components 面板当前选中的组件实例

**Vite 项目启动 DevTools：**

```javascript
// vite.config.js (Vite 插件方式，无需浏览器扩展)
import vueDevTools from 'vite-plugin-vue-devtools'

export default {
  plugins: [vue(), vueDevTools()]
}
```

#### React DevTools

**安装**：Chrome / Firefox 扩展商店搜索 "React Developer Tools"

**核心面板：**

| 面板           | 功能                                                                    |
| -------------- | ----------------------------------------------------------------------- |
| **Components** | 组件树、props/state/hooks、可实时修改 state 值、Suspense 边界、渲染来源 |
| **Profiler**   | 渲染性能：录制交互、火焰图、组件渲染次数和耗时、Commit 信息             |

**Profiler 面板解读：**

1. 点击录制 → 操作页面 → 停止录制
2. 火焰图模式：每个条 = 一个组件的一次渲染，宽度 = 渲染耗时
3. Ranked 模式：按渲染耗时排序，一眼看出瓶颈组件
4. Commit 选择器：筛选到特定的渲染提交
5. 灰色条 → 组件未重新渲染（被 `React.memo` 跳过）
6. 彩色条 → 重新渲染

**使用技巧：**

- Components 中选中组件 → 右侧 **`rendered by`** 字段告诉你哪个父组件触发了渲染
- `Highlight updates` 开关 → 重新渲染的组件在页面上有高亮边框闪烁
- Profiler 配合 `React.memo` / `useMemo` / `useCallback` 验证优化是否生效

#### 框架 DevTools 对比

|          | Vue DevTools                   | React DevTools           |
| -------- | ------------------------------ | ------------------------ |
| 数据编辑 | 可直接修改 props/data/computed | 可修改 state/props/hooks |
| 渲染追踪 | Timeline 时间线                | Profiler 火焰图          |
| 触发来源 | 一般需额外判断                 | 明确标注 "rendered by"   |
| 生态插件 | Vite 插件版无需扩展            | 独立扩展                 |

:::
